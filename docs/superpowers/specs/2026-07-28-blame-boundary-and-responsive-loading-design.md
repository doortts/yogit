# Blame 카드 경계와 즉시 탐색 설계

## 목적

Blame 화면에서 선택한 줄의 커밋 정보 카드가 메타데이터 열 안에만
표시되게 한다. Blame 계산이 끝나지 않았더라도 이미 읽은 소스 코드는 바로
보여 주고 키보드로 탐색할 수 있게 한다.

## 확인한 원인

### 커밋 카드가 코드를 덮는 이유

`FullBlameView`는 커밋 카드를 아바타 열 오른쪽에 배치한다. 카드가 쓸 수
있는 폭은 현재 Blame 메타데이터 열이 아니라 콘텐츠 화면 전체 폭에서
아바타 폭을 뺀 값이다. `FullDiffCommitInfoCard`의 최대 폭은 420px라서
화면이 넓으면 메타데이터 열의 360px 경계를 넘어 소스 코드 위까지
표시된다.

기존 위젯 테스트는 카드가 Blame 목록의 전체 화면 안에 있는지만 확인한다.
메타데이터 열의 오른쪽 색상선은 검사하지 않으므로 현재 문제를 잡지
못한다.

### 파일 목록에서 Blame으로 늦게 이동하는 이유

파일 목록의 오른쪽 이동키 처리는 `state.blame.data`가 준비된 경우에만
Blame 목록으로 포커스를 넘긴다. 첫 Blame 요청은 다음 순서로 진행된다.

1. 선택한 파일의 전체 내용을 읽고 `FileDocument`를 만든다.
2. `git blame --line-porcelain`으로 모든 줄의 커밋 정보를 계산한다.
3. 파일의 줄과 Blame 결과의 줄 수를 맞춰 `BlameDocument`를 만든다.
4. `FullBlameView`를 화면에 붙인 뒤 포커스를 옮긴다.

현재 저장소에서 9,545줄인 `test/app_test.dart`를 확인했을 때 파일 내용은
0.00초 안에 읽었지만 `git blame --line-porcelain`은 약 0.18초가 걸렸다.
파일이 크거나 이력이 길면 Git이 이력을 따라가는 시간이 더 늘어난다.
작업 트리 파일은 임시 내용을 만들고 파일이 계산 중에 바뀌지 않았는지도
확인하므로 더 오래 걸릴 수 있다.

## 선택한 방향

파일을 읽은 뒤에는 Blame 계산을 기다리지 않고 소스 화면을 먼저 붙인다.
줄 번호와 코드는 즉시 표시하며 작성자, 커밋 요약, 날짜, 색상선은 계산
중임을 나타내는 낮은 강조도의 상태로 둔다. Blame 결과가 도착하면 같은
화면 상태에서 실제 메타데이터로 바꾼다.

이 방식은 새 Git 요청을 만들지 않는다. 사용자가 열지 않을 파일까지 미리
계산하지도 않는다. Git 계산 시간 자체는 그대로지만 포커스 이동과 코드
탐색을 막지 않으므로 기다리는 시간이 사용을 가로막지 않는다.

인접 파일을 미리 계산하거나 `git blame` 결과를 줄 단위로 흘려보내는
방식은 이번 범위에서 제외한다. 전자는 필요하지 않은 Git 작업을 늘리고,
후자는 프로세스 실행과 Blame 모델을 크게 바꿔야 한다.

## 화면 구성

### 메타데이터 열

메타데이터 열의 폭을 계산하는 공개 함수
`fullBlameMetadataWidth(double viewportWidth)`를 둔다. 현재 행 배치가 쓰는
값을 그대로 옮긴다.

- 화면 폭이 900px 이상이면 360px
- 그보다 좁으면 화면 폭의 38%를 250px에서 320px 사이로 제한한 값

`BlameSourceRow`와 커밋 카드가 이 함수를 함께 사용한다. 행과 카드가 서로
다른 계산식을 갖지 않게 해서 같은 문제가 다시 생기지 않도록 한다.

### 커밋 정보 카드

카드는 지금처럼 선택한 행의 아바타 오른쪽에서 시작한다. 카드 바깥쪽
제약 폭은 `메타데이터 열 폭 - 아바타 폭 - 색상선 폭`으로 정한다.
따라서 카드의 오른쪽 끝은 메타데이터 열의 색상선 앞에서 멈춘다.

`FullDiffCommitInfoCard`의 자체 최대 폭과 메시지 표시 방식은 유지한다.
파일 History에서 쓰는 카드도 바꾸지 않는다. 별도로 계획된 긴 메시지
스크롤 기능이 들어오더라도 Blame 화면의 바깥쪽 폭 제약이 먼저 적용되므로
두 변경은 함께 동작할 수 있다.

### 계산 중인 Blame

`FullBlameView`는 준비된 `BlameDocument`로 만드는 기본 생성자와
`FullBlameView.loading` 생성자를 제공한다. 두 생성자는 내부에서 같은
`FileDocument`, 같은 목록과 같은 포커스 상태를 쓴다.

계산 중에는 다음 내용을 표시한다.

- 이미 읽은 소스 코드와 줄 번호
- 비어 있는 아바타와 날짜
- 낮은 강조도의 `Blame 계산 중…` 문구
- 아직 선택한 줄에 커밋 정보 카드를 표시하지 않음

Blame 결과가 도착해도 위젯의 키를 바꾸지 않는다. 선택한 줄, 목록 포커스,
스크롤 위치를 그대로 둔 채 메타데이터만 실제 값으로 바꾼다.

## 키보드와 포커스

파일 목록에서 오른쪽 화살표 또는 `l`을 누르면 계산 중인 Blame 목록도
포커스를 받을 수 있다. 파일 내용까지 아직 준비되지 않았다면 사용자의
이동 의도를 기억한다. `FileDocument`가 도착해 Blame 목록이 화면에
붙는 첫 프레임에서 포커스를 넘긴다.

계산 중인 목록에서도 위쪽·아래쪽 화살표와 `k`·`j`로 줄을 선택할 수 있다.
왼쪽 화살표와 `h`는 현재처럼 파일 목록으로 돌아간다.

Blame 결과가 도착한 뒤에는 선택한 줄의 실제 커밋 정보를 사용한다. 선택한
줄이 그대로라면 새로 포커스를 요청하거나 스크롤하지 않는다.

## 데이터 흐름

1. `FullDiffSessionController`는 지금처럼 파일 내용과 Diff를 함께 읽는다.
2. Blame 화면이 선택되어 있으면 파일 내용이 준비되는 즉시
   `_ensureBlame()`이 기존 Git 요청을 시작한다.
3. `DiffScreen`은 UTF-8 `FileDocument`가 있고 Blame 결과가 아직 없으면
   `FullBlameView.loading`을 표시한다.
4. `FullBlameView.loading`은 소스 코드를 표시하고 키보드 탐색을 받는다.
5. `state.blame.data`가 준비되면 `DiffScreen`이 같은 키로 일반
   `FullBlameView`를 다시 만든다.
6. Flutter가 기존 `FullBlameViewState`를 유지하므로 선택, 포커스, 스크롤도
   유지된다.

기존 `_blameCache`는 그대로 사용한다. 같은 커밋과 파일을 다시 열었을 때는
캐시에 있는 `BlameDocument`를 즉시 표시한다.

## 오류 처리

- 파일 내용을 읽는 중에는 현재 로딩 안내를 유지한다.
- UTF-8 파일 내용이 준비되면 Blame 계산 중 화면으로 바꾼다.
- Blame 요청이 실패하면 현재 오류 문구를 표시한다. 파일 목록 포커스는
  사용할 수 있으며 다른 파일을 선택할 수 있다.
- 바이너리, 지원하지 않는 인코딩, 크기 제한 파일은 계산 중 화면을 만들지
  않고 현재 표시 규칙을 유지한다.
- 늦게 끝난 이전 파일의 Blame 결과는 컨트롤러의 요청 번호와 선택 세대
  검사로 계속 버린다.

## 변경 범위

### 수정할 코드

- `lib/full_blame_view.dart`
  - 메타데이터 폭 계산을 한곳으로 모은다.
  - 커밋 카드 폭을 메타데이터 열 안으로 제한한다.
  - 계산 중인 소스 행과 포커스 상태를 지원한다.
- `lib/diff_screen.dart`
  - 파일 내용이 준비된 시점부터 계산 중인 Blame 화면을 표시한다.
  - 오른쪽 화살표와 `l`의 포커스 이동 의도를 기억한다.
- `test/full_diff_content_views_test.dart`
  - 카드가 메타데이터 색상선을 넘지 않는지 확인한다.
  - 계산 중 줄 선택과 결과 반영 뒤 상태 유지를 확인한다.
- `test/full_diff_workspace_test.dart`
  - Blame 로딩 중 파일 목록에서 오른쪽으로 이동하는 동작을 확인한다.

### 바꾸지 않을 코드

- `GitRepository.loadBlame`의 명령과 파싱 방식
- `FullDiffSessionController`의 Blame 요청 캐시와 늦은 결과 차단
- 파일 History 커밋 카드
- Blame 메타데이터 열의 현재 폭
- 인접 파일 사전 계산
- 새 패키지 추가

## 검증 기준

1. 넓은 화면에서 커밋 카드의 오른쪽 끝이
   `blame-rail-<line>`의 왼쪽 경계를 넘지 않는다.
2. 좁은 화면에서도 카드가 메타데이터 열 안에 있고 레이아웃 오류가 없다.
3. Blame 결과를 지연시킨 상태에서 오른쪽 화살표 한 번으로 계산 중인 소스
   목록에 포커스가 간다.
4. 계산 중에도 위·아래 화살표와 `j`·`k`로 줄을 선택할 수 있다.
5. Blame 결과가 도착한 뒤 선택한 줄, 포커스, 스크롤 위치가 유지된다.
6. 실제 메타데이터가 표시된 뒤에만 커밋 정보 카드가 나타난다.
7. 이전 파일의 늦은 결과가 현재 화면을 바꾸지 않는다.
8. 같은 파일을 다시 열면 기존 Blame 캐시를 사용한다.
9. 관련 위젯 테스트와 전체 `flutter test`가 통과한다.
10. `flutter analyze`와 macOS 디버그 빌드가 성공한다.
