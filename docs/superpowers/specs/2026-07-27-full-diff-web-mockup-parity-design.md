# Full Diff 웹 시안 일치 설계

## 문서 상태

이 문서는 Yogit Full Diff 화면의 최종 구현 기준입니다. 2026-07-27에
사용자가 승인한 웹 시안과 기능별 검수 이미지를 그대로 따릅니다.

이전 문서인
[Full Diff 작업 화면 설계](2026-07-27-full-diff-workspace-design.md)는
1차 구현의 설계 기록으로 남깁니다. 두 문서가 다르면 이 문서가
우선합니다. 승인 없이 메뉴 이름, 배치, 색상, 크기, 기능 범위 또는
반응형 기준을 바꾸지 않습니다.

## 목표와 완료 조건

현재 Hunk 중심의 1차 Full Diff 화면을 승인된 웹 시안과 같은 작업
공간으로 확장합니다. 다음 조건을 모두 만족해야 완료입니다.

- 첫 번째 머리글의 메뉴 이름과 순서가
  `편집기로 열기`, `File`, `Diff`, `Blame`, `History`, `UTF-8`과
  일치합니다.
- 두 번째 머리글의 메뉴 이름과 순서가 `집중 모드`, `Hunk`, `Inline`,
  `Split`, 이전 변경, 변경 번호, 다음 변경, `diff 알고리즘`,
  `공백 무시`, `줄바꿈`과 일치합니다.
- 기본 선택은 `Diff`와 `Hunk`입니다.
- 웹 시안에 보이는 모든 조작 기능이 실제 저장소 데이터로 동작합니다.
- 대응하는 기능별 기준 이미지와 비교했을 때 허용 범위 밖의 차이가
  없습니다.
- 기존 커밋·파일 탐색, 머지 부모 선택, 키보드 이동, 텍스트 선택과
  작업 트리 비교 기능이 그대로 동작합니다.

## 화면 구조

`FullDiffWorkspace`는 순서가 고정된 머리글 두 구역과 반응형 본문으로
나눕니다. 각 머리글 구역은 세 본문 열 전체 너비를 사용하며 공간이
부족하면 높이를 늘려 내부 조작 요소를 다음 줄로 넘깁니다.

```text
FullDiffWorkspace
├─ GlobalFileBar
│  ├─ FileIdentityGroup
│  └─ FileActionGroup
├─ GlobalDiffToolbar
│  ├─ FocusAndPresentationGroup
│  └─ DiffToolGroup
└─ ResponsiveDiffBody
   ├─ NearbyCommitsPane
   ├─ CommitFilesPane
   └─ ContentPane
      ├─ FileView
      ├─ DiffView
      │  ├─ HunkPresentation
      │  ├─ InlinePresentation
      │  └─ SplitPresentation
      ├─ BlameView
      ├─ HistoryView
      └─ DiffMinimap
```

### 첫 번째 머리글

왼쪽부터 다음 순서를 지킵니다.

1. 코드 파일 아이콘
2. 선택한 파일 경로 칩
3. 파일 상태와 추가·삭제 수를 합친 배지
4. 남는 공간
5. 외부 링크 아이콘과 `편집기로 열기`
6. `File`, `Diff`, `Blame`, `History`
7. 파일 내용 상태 배지

파일 경로는 한 줄로 말줄임합니다. 상태 배지는 예를 들어
`M · +12 −4`로 표시합니다. 파일 내용 상태는 `UTF-8`, `Binary`,
`Unsupported encoding`, `Too large` 중 하나입니다.

### 두 번째 머리글

왼쪽 그룹은 `집중 모드`, `Hunk`, `Inline`, `Split` 순서입니다.
오른쪽 그룹은 이전 변경 화살표, `2 / 7` 형식의 변경 번호, 다음 변경
화살표, `diff 알고리즘`, `공백 무시`, `줄바꿈` 순서입니다.

알고리즘 메뉴 이름은 선택값과 관계없이 항상 `diff 알고리즘`입니다.
메뉴 항목은 `Git setting`, `Myers`, `Minimal`, `Patience`,
`Histogram`입니다. 선택값은 열린 메뉴 안에서 체크 상태로 구분하며
닫힌 메뉴에는 별도 문자열을 덧붙이지 않습니다.

### 세 본문 열

- `주변 커밋`: 커밋 제목과 짧은 SHA를 두 줄로 표시합니다.
- 커밋·파일 열: 선택한 커밋 제목, SHA·작성자, `변경 파일`, 전체 파일
  수와 추가·삭제 합계, 변경 파일 목록을 표시합니다.
- 콘텐츠: 선택한 `File`, `Diff`, `Blame`, `History` 화면을 표시합니다.

선택한 커밋과 파일 행은 모서리를 둥글게 만들지 않은 남색 배경을 열
너비 전체에 칠합니다. 파일 상태는 별도 배지가 아닌 한 글자로
표시합니다. 콘텐츠는 카드 목록이 아닌 이어진 평면으로 그립니다.

## 상태 모델과 화면 전환

주 화면과 Diff 표시 방식을 별도 상태로 관리합니다.

```dart
enum FullDiffView { file, diff, blame, history }
enum DiffPresentation { hunk, inline, split }
```

`FullDiffView`는 첫 번째 머리글의 네 메뉴에 대응합니다.
`DiffPresentation`은 `Diff`를 선택했을 때 내용을 그리는 방식입니다.
`Inline`은 별도 주 화면이 아닙니다.

- 주 화면을 바꿔도 선택한 변경 위치와 Diff 표시 방식을 유지합니다.
- `Hunk`, `Inline`, `Split`은 다른 주 화면에서도 같은 위치와 모양으로
  표시합니다. 이때 표시 방식을 바꾸면 선택 상태만 저장하고 Git을 다시
  읽지 않습니다. `Diff`로 돌아오면 저장한 방식을 적용합니다.
- 파일·커밋·머지 부모를 바꾸면 주 화면과 Diff 표시 방식은 유지하고 새
  patch를 읽은 뒤 첫 번째 변경 위치를 선택합니다.
- 알고리즘을 바꿔 Hunk 경계가 달라지면 이전 소스 행에서 가장 가까운
  새 Hunk를 선택합니다.
- `History`에서 다른 커밋을 확정해서 선택한 경우 그 커밋과 당시 경로를
  새 선택으로 사용합니다.
- 이름 변경 행은 해당 커밋의 결과 경로를 선택합니다. 삭제 행은 삭제
  상태를 선택하고 파일 원본과 Blame에 이전 경로를 사용합니다. 머지
  커밋은 History 행에 부모 선택 정보가 없다면 첫 번째 부모를
  사용합니다.
- History에서 고른 커밋이 현재 주변 커밋 목록에 없으면 목록 첫 행에
  같은 모양의 임시 선택 행을 넣습니다. 이후 주변 커밋을 다시 읽어
  해당 커밋이 목록에 들어오면 임시 행을 없앱니다.
- 키보드 포커스만 History 행으로 옮겼을 때는 현재 diff를 바꾸지
  않습니다.

### File

선택한 비교 결과의 파일 전체를 보여줍니다. 수정·추가·이름 변경·복사
파일은 결과 쪽을 사용합니다. 삭제된 파일은 부모 쪽 내용을 사용하고
삭제 상태를 알립니다. 현재 변경 위치를 소스 행 기준으로 찾아
강조합니다.

### Diff

선택한 부모와 결과를 비교합니다.

- `Hunk`: 현재 Hunk의 변경 행만 한 열에 표시합니다. 바뀌지 않은 문맥
  행은 숨깁니다. Hunk 머리글은
  `SetupBase · lines 312–316 · change 2 of 7` 형식을 사용합니다.
  줄 범위는 결과 쪽 Hunk 범위를 사용하고 결과 쪽 행이 없는 삭제 전용
  Hunk만 이전 쪽 범위를 사용합니다.
- `Inline`: 모든 Hunk를 한 열에 이어서 표시합니다. 삭제와 추가 행을
  섞어 배치하고 앞뒤 문맥 3줄을 함께 보여줍니다.
- `Split`: 모든 Hunk의 이전 파일과 새 파일을 같은 행의 좌우에
  배치합니다. 대응하는 행이 없으면 빗금 빈칸을 표시합니다.

세 표시 방식은 이미 읽은 `DiffDocument`를 다르게 그릴 뿐입니다.
표시 방식을 바꿀 때 Git 명령을 다시 실행하지 않으며 변경 번호와
선택한 Hunk도 유지합니다.

### Blame

`File`과 같은 전체 파일에 각 행의 커밋 SHA와 작성자 정보를 붙입니다.
파일 행 번호와 변경 위치는 `File`과 같습니다. 작업 트리의 커밋하지
않은 행은 `Uncommitted`로 표시합니다.

### History

파일 이름 변경을 따라가며 선택한 경로를 바꾼 커밋을 표시합니다. 각
행에는 SHA, 제목, 작성자, 상대 시간을 둡니다. History에서는 코드
미니맵을 숨깁니다. 이전·다음 변경 버튼과 번호는 시안의 자리를
유지하지만 `aria-disabled` 상태로 두고 눌러도 아무 동작을 하지
않습니다.

## 조작 기능

### 집중 모드

집중 모드를 켜면 두 탐색 열을 숨기고 콘텐츠 열을 본문 전체 너비로
넓힙니다. 버튼은 탐색 패널을 복원한다는 의미의 아이콘과 이름으로
바뀝니다. 켜진 상태의 정확한 이름은 `탐색 패널`이며
`panel-left-open` 아이콘을 사용합니다. 끄면 기존 열 너비와 커밋·파일
선택을 복원합니다.

### 이전·다음 변경

- 첫 Hunk에서 이전, 마지막 Hunk에서 다음을 누르면 현재 위치를
  유지합니다.
- `Hunk`에서는 표시할 Hunk를 교체합니다.
- `Inline`, `Split`, `File`, `Blame`에서는 같은 앵커가 보이도록
  스크롤합니다.
- 사용자가 스크롤하면 화면에 가장 가까운 앵커로 변경 번호만
  갱신합니다. 이때 화면을 다시 끌어당기지 않습니다.
- 화살표나 미니맵으로 선택했을 때만 새 앵커를 화면 안으로
  이동시킵니다.
- Hunk가 하나도 없으면 활성 앵커를 `null`로 두고 `0 / 0`을
  표시합니다. 이전·다음 버튼과 미니맵 표시를 끄고
  `현재 옵션으로 표시할 변경이 없습니다` 상태를 보여줍니다.

### diff 알고리즘

알고리즘을 고르면 patch만 다시 읽습니다. 파일 내용, Blame, History는
그대로 둡니다. 새 결과를 기다리는 동안 마지막으로 성공한 patch를
보여줍니다. 실패하면 이전 알고리즘과 patch로 되돌리고 메뉴 근처에
오류를 표시합니다.

요청한 옵션과 마지막으로 성공해 화면에 적용한 옵션은 따로 보관합니다.
빠르게 여러 옵션을 골라도 가장 최근 patch 요청만 받을 수 있습니다.
이전 요청의 성공이나 실패는 새 옵션을 덮거나 되돌리지 않습니다.
활성 앵커도 가장 최근 요청이 성공했을 때만 새 Hunk에 맞춥니다.

### 공백 무시

공백 변경 무시는 Git의 `--ignore-all-space`에 대응합니다. 시안처럼
버튼의 선택 상태를 바꾸고 patch만 다시 읽습니다. 화면에서 행을
숨기는 방식으로 결과를 흉내 내지 않습니다.

### 줄바꿈

줄바꿈은 화면 표시만 바꿉니다. 꺼진 상태에서는 소스 행을 한 줄로
말줄임하고 켜면 단어 중간에서도 다음 줄로 넘깁니다. 줄바꿈 뒤에도
소스 행 기반 앵커를 사용하므로 변경 이동과 미니맵 선택은 같은 곳을
가리킵니다.

### 편집기로 열기

현재 작업 트리에 실제 파일이 있을 때만 사용합니다. 과거 커밋의 파일을
임시로 만들지 않습니다.

1. 저장소 루트 안의 일반 파일인지 확인합니다.
2. `VISUAL`, `EDITOR` 순서로 실행 가능한 편집기를 찾습니다.
3. 제한된 POSIX 단어 해석기로 프로그램과 인자를 나눕니다. 명령 치환,
   파이프, 리다이렉션, 명령 구분자와 닫히지 않은 따옴표는
   거부합니다.
4. 쉘로 다시 실행하는 대체 경로는 두지 않습니다.
5. VS Code 계열, Sublime, Vim/Neovim, Emacs 계열은 현재 행을 여는
   인자를 붙입니다.
6. 설정된 편집기가 없으면 macOS `NSWorkspace`로 연결된 앱을 엽니다.

경로를 정규화한 뒤 저장소 밖을 가리키는 심볼릭 링크는 거부합니다.
검증한 절대 경로를 한 인자로 전달하므로 공백, 따옴표, 세미콜론 또는
`-`로 시작하는 이름도 편집기 옵션으로 해석되지 않습니다.
`NSWorkspace`에는 명령 문자열이 아닌 file URL을 전달합니다. 실행에
실패해도 현재 콘텐츠를 지우지 않고 버튼 옆에 오류를 표시합니다.

### 미니맵

미니맵은 콘텐츠 오른쪽의 고정 18px 열입니다.

- Hunk마다 표시 중인 파일 쪽의 소스 행 비율에 맞춘 3px 높이 표시를
  둡니다. 일반 파일은 결과 쪽, 삭제 파일은 이전 쪽 좌표를 사용합니다.
- 추가·혼합 변경은 파란색, 삭제 변경은 주황색으로 표시합니다.
- `Inline`, `Split`, `File`, `Blame`의 현재 화면 범위는 전체 스크롤
  길이에 대한 비율로 계산하고 파란 테두리와 옅은 채움으로 그립니다.
- `Hunk`에서는 스크롤 길이가 아니라 활성 Hunk가 차지하는 소스 행
  범위를 화면 범위로 표시합니다. 화면 범위를 끌면 존재하지 않는
  내용을 스크롤하지 않고 가장 가까운 Hunk를 선택합니다.
- 변경 표시를 누르면 해당 Hunk를 선택하고 화면에 보이게 합니다.
- 빈 트랙을 누르면 가장 가까운 Hunk로 이동합니다.
- 스크롤 가능한 화면에서 화면 범위 표시를 끌면 전체 파일 위치가 함께
  움직입니다.
- `History`에서는 미니맵을 숨깁니다.

### 키보드

타임라인 미리보기와 Full Diff는 같은 페이지 스크롤 명령과 48px 이동
상수를 사용합니다.

- Up/Down: 변경 파일 이동
- Command-Up/Command-Down: 주변 커밋 이동
- Option-Up/Option-Down: 이전·다음 변경
- Command-Shift-Up/Command-Shift-Down: 현재 콘텐츠를 48px씩 이동
- Command-Shift-F: 집중 모드 전환

메뉴, 선택 가능한 텍스트, History 목록이 키 입력을 쓰고 있으면 해당

움직이며 키를 누르고 있을 때는 입력이 밀리지 않도록 즉시 이동합니다.

## 데이터와 Git 경계

### 핵심 모델

`DiffDocument`는 patch 메타데이터, 이전·결과 경로, 파일 상태, 바이너리
표시, 개행 없음 표시, Hunk, unified 행, Split 행 쌍과 소스 행 좌표를
보관합니다.

`DiffAnchor`는 Hunk 순서뿐 아니라 이전 파일 행과 결과 파일 행을
가리킵니다. 화면 전환, 이전·다음 이동, 스크롤에 따른 선택, 미니맵이
같은 좌표를 사용합니다.

별도 모델은 다음 책임만 가집니다.

- `FileDocument`: 원본 바이트, 내용 종류, 이전·결과 쪽, revision, 경로,
  행, 마지막 개행 여부
- `BlameDocument`: 파일과 각 행의 blame 정보
- `FileHistoryEntry`: 전체 커밋 정보, 당시 경로, 이전 경로, 파일 상태

### 파일 내용 판별

- 원본 바이트는 엄격한 UTF-8로 해석합니다.
- Git numstat이 바이너리로 표시했거나 NUL 바이트가 있으면 `Binary`로
  분류합니다.
- 바이너리 신호 없이 UTF-8로 해석할 수 없으면
  `Unsupported encoding`입니다.
- 지원하지 않는 텍스트를 바이너리로 잘못 표시하지 않습니다.

### Git 명령

Git 호출은 쉘을 쓰지 않고 인자 배열로 실행합니다.

- patch와 파일 목록은 `--find-renames=50%`를 사용합니다. 저장소 전체
  파일 목록에는 경로를 제한하지 않습니다. 선택한 이름 변경 파일의
  patch만 읽을 때는 이전 경로와 결과 경로를 모두 pathspec으로
  넘깁니다.
- 파일 원본: 커밋 파일은 Git blob의 바이트, 작업 트리는 검증한 경로의
  바이트를 읽습니다.
- History: `git log --follow --find-renames=50% --date-order`를
  사용하고 NUL 구분 출력으로 경로를 해석합니다.

비교 대상과 파일 원본은 다음 표로 고정합니다.

| 선택 상태 | patch 비교 | File 원본 |
| --- | --- | --- |
| 일반 커밋의 수정·추가 | 첫 부모 또는 선택한 부모 → 대상 커밋 | 대상 커밋의 결과 경로 blob |
| 루트 커밋 | Git의 빈 트리 → 대상 커밋 | 대상 커밋의 결과 경로 blob |
| 머지 커밋 | 사용자가 고른 부모 → 머지 커밋 | 머지 커밋의 결과 경로 blob |
| 이름 변경·복사 | 부모의 이전 경로 → 대상의 결과 경로 | 대상 커밋의 결과 경로 blob |
| 커밋에서 삭제 | 부모의 이전 경로 → 빈 파일 | 선택한 부모의 이전 경로 blob |
| 추적 중인 작업 트리 파일 | `HEAD` → 인덱스와 작업 트리를 합친 현재 내용 | 검증한 디스크 경로 |
| 작업 트리에서 삭제 | `HEAD`의 이전 경로 → 빈 파일 | `HEAD`의 이전 경로 blob |
| 추적하지 않는 작업 트리 파일 | 빈 파일 → 디스크 내용으로 만든 추가 patch | 검증한 디스크 경로 |

추적하지 않는 파일은 `git ls-files --others --exclude-standard -z`로
찾습니다. Git diff가 파일을 포함하지 않으므로 디스크 바이트에서 모든
행이 추가된 `DiffDocument`를 만듭니다. 이 경우 알고리즘과 공백 무시
옵션은 결과를 바꾸지 않습니다.

Blame은 파일 상태에 맞춰 다음처럼 읽습니다.

- 커밋 결과: `git blame --line-porcelain <target> -- <newPath>`
- 삭제 파일: `git blame --line-porcelain <selectedParent> -- <oldPath>`
- 추적 중인 작업 트리:
  `git blame --line-porcelain --contents <absolutePath> HEAD -- <path>`
- 추적하지 않는 파일: 모든 행을 `Uncommitted`로 생성

Blame 행 수는 엄격한 UTF-8로 해석한 파일 행 수와 같아야 합니다. 다르면
파일 화면은 유지하고 Blame 화면에만 정렬 오류를 표시합니다. 작업 트리
Blame은 읽은 파일 바이트의 지문과 요청 번호가 모두 맞을 때만
받습니다.

History가 현재 타임라인 페이지 밖의 커밋을 선택할 수 있으므로 선택한
커밋은 목록 번호가 아닌 `GitCommit` 객체로 보관합니다.

## 컨트롤러와 비동기 처리

별도 상태 관리 패키지를 추가하지 않습니다. `ChangeNotifier`를 쓰는
`FullDiffSessionController` 하나가 다음 상태를 관리합니다.

- 선택한 커밋·부모·이전 경로·결과 경로
- 주 화면과 Diff 표시 방식
- 활성 `DiffAnchor`
- 알고리즘·공백 변경 무시·줄바꿈·집중 모드
- 파일 목록, patch, 파일 내용, Blame, History의 독립된 로딩·오류
- 커밋된 데이터의 제한된 세션 캐시

커밋·부모·경로가 바뀔 때 선택 세대 번호를 올립니다. 파일 목록, patch,
파일 내용, Blame, History에는 각자의 요청 번호를 둡니다. 결과를 받을
때 선택 키와 요청 번호가 모두 현재 값인지 확인합니다. 이전 요청이
늦게 끝나도 현재 화면을 덮을 수 없습니다.

파일을 선택하면 patch와 파일 원본 바이트를 동시에 읽습니다. 파일 원본
종류를 확인하는 동안 인코딩 배지 자리에는 `Loading`을 표시합니다.
Blame은 정상 UTF-8 `FileDocument`가 준비된 뒤 필요할 때 읽습니다.
History는 파일 원본과 관계없이 필요할 때 읽습니다.

같은 선택 키에서 알고리즘이나 공백 옵션만 바꿀 때는 마지막으로 성공한
patch를 유지합니다. 커밋·부모·경로가 바뀌면 이전 patch, 파일 원본,
Blame과 History를 즉시 숨깁니다. 새 파일 머리글 아래에 이전 파일
내용이 보이면 안 됩니다.

캐시 키는 다음 값으로 고정합니다.

- patch: base, target, parent, oldPath, newPath, algorithm,
  ignoreWhitespace
- 파일 원본: revision, path, 이전·결과 쪽
- Blame: revision, path
- History: 시작 revision, path

각 캐시는 세션마다 최근 사용 항목 32개까지만 보관합니다. patch와 파일
원본의 원본 바이트 합계가 64MiB를 넘으면 가장 오래 쓰지 않은 항목부터
뺍니다. 커밋된 데이터만 캐시하고 작업 트리 patch, 파일 내용과 Blame은
매번 다시 읽습니다. 실패한 Future는 캐시에서 빼서 다시 시도할 수 있게
합니다.

## 설정

Settings의 Full Diff 영역에서 새 화면을 열 때의 기본값을 고릅니다.

```dart
enum FullDiffInitialView { hunk, fullFile }
```

- `Hunk`: `Diff`와 `Hunk`를 선택해서 엽니다. 기본값입니다.
- `Full file focused on first change`: `File`을 선택하고 첫 변경 위치를
  보여줍니다.

JSON 키는 `fullDiffInitialView`, 값은 `hunk` 또는 `fullFile`입니다.
값이 없거나 올바르지 않으면 `hunk`를 사용합니다. 설정은 새 Full Diff
화면에만 적용합니다. 이미 열린 화면과 사용자가 그 화면에서 고른 주
화면·표시 방식은 바꾸지 않습니다.

## 로딩·오류·특수 파일

- 같은 선택 키에서 옵션을 다시 읽을 때만 마지막으로 성공한 데이터를
  유지하고 해당 영역에 로딩 상태를 표시합니다. 커밋·부모·경로가
  바뀌면 이전 선택의 데이터는 숨깁니다.
- 한 화면의 오류가 다른 화면에서 읽은 데이터를 지우지 않습니다.
- 변경 없음, 빈 파일, 삭제 파일, 바이너리, 지원하지 않는 인코딩,
  지나치게 큰 파일에 각각 구분되는 안내를 표시합니다.
- 바이너리와 지원하지 않는 인코딩은 텍스트 `File`과 `Blame`을
  제공하지 않습니다. History와 가능한 편집기 열기는 유지합니다.
- 2MiB 또는 50,000행을 넘으면 구문·단어 강조를 끄고 필요한 행만
  만듭니다.
- 10MiB 또는 200,000행을 넘으면 파일 전체 텍스트를 그리지 않습니다.
  파일 정보, Hunk 요약, History와 가능한 편집기 열기는 유지합니다.

## 접근성

- 모든 버튼에 읽을 수 있는 이름, 선택 상태와 사용 가능 상태를
  제공합니다.
- 선택된 두 버튼 묶음은 각각 하나의 선택 그룹으로 읽힙니다.
- 아이콘만 있는 이전·다음 버튼에는 `이전 변경 구간`,
  `다음 변경 구간` 이름을 둡니다.
- 선택한 커밋·파일·History 행의 상태를 알립니다.
- 색상만으로 추가·삭제·현재 위치를 구분하지 않습니다. 줄 번호,
  `+`·`−`, 현재 행 선을 함께 사용합니다.
- 시스템 글자 크기가 달라도 조작 요소가 잘리지 않으며 머리글은
  정해진 순서를 유지한 채 줄을 바꿉니다.

- 다섯 알고리즘과 공백 변경 무시의 정확한 Git 인자
- 알고리즘 실패 뒤 이전 결과와 선택값 복원
- 커밋·작업 트리·삭제·새 파일 Blame
- 두 번 이상 이름이 바뀐 파일 History와 특수 문자가 든 경로
- 이전 요청이 현재 선택을 덮지 못하는지 확인
- 미니맵 위치, 클릭, 끌기와 스크롤 순환 방지
- 편집기 인자 분리, 안전하지 않은 설정 거부, macOS 대체 열기
- Settings 저장·복원과 손상된 값의 Hunk 기본값
- 구문 파일명 매핑과 확장 문법 크기·속도 기준

### 위젯·통합 테스트

- `File / Diff / Blame / History` 전환 뒤 앵커와 표시 방식 유지
- `Hunk / Inline / Split`의 내용과 선택 상태
- History 행은 포커스 이동만으로 선택되지 않고 Enter나 클릭으로
  확정되는지 확인
- 이전·다음 변경의 끝 제한과 화면 이동
- 스크롤에 따른 변경 번호 갱신이 화면을 되돌리지 않는지 확인
- 집중 모드에서 열 숨김과 너비·선택 복원
- 651px, 650px, 481px, 480px 경계의 열 표시
- 480px Split에서 이전 쪽 열을 숨기고 결과 쪽만 남기는지 확인
- 줄바꿈·공백 무시·알고리즘 메뉴의 이름과 상태
- 타임라인 미리보기와 같은 페이지 스크롤 명령·이동량
- 메뉴와 텍스트 선택의 원래 키 동작 유지
- 파일 상태별 머리글 배지와 편집기 버튼 사용 가능 상태
- DRL 고정 fixture에서 모든 화면과 조작을 연속 실행하는 흐름

### 이미지 검수

구현 화면을
[Full Diff 시각 검수 기준](2026-07-27-full-diff-visual-qa-reference.md)의
각 이미지와 같은 크기·상태로 캡처합니다. 이미지별로 나란히 보고 차이
이미지도 만듭니다. 메뉴 이름·순서·아이콘·선택 상태·단색·테두리·
반응형 열이 다르면 테스트 성공 여부와 관계없이 완료로 처리하지
않습니다.

## 구현 경계와 병렬 작업

공유 계약을 먼저 한 번 확정한 뒤 서로 다른 파일을 맡아 작업합니다.

1. 순차 작업: `full_diff_model.dart`, 저장소 인터페이스,
   `FullDiffSessionController` 상태 계약, `DiffScreen` 조립 규칙
2. 병렬 작업 A: 파일 원본·인코딩·Blame·History Git 기능과 테스트
3. 병렬 작업 B: Hunk/Inline/Split/File/Blame/History 표시 위젯과 테스트
4. 병렬 작업 C: 머리글·미니맵·반응형·외부 편집기·macOS 연결과
   이미지 테스트
5. 순차 통합: 컨트롤러 연결, 화면 조립, 전체 테스트, 이미지 대조,
   DRL 수동 검증

`git.dart`, `full_diff_model.dart`, `full_diff_controller.dart`,
`diff_screen.dart`와 공용 테스트 대역은 동시에 수정하지 않습니다.
통합 순서는 모델·인터페이스, Git, 컨트롤러, 하위 위젯, 화면 조립,
통합·이미지 검수입니다.

## 범위 밖

- 화면 안에서 파일 편집, stage, discard 또는 커밋
- 머지 충돌 해결
- 임의 문자 인코딩 변환
- 사용자 정의 구문 색상과 도구 모음 배치
- 과거 파일을 임시로 만들어 외부 편집기로 여는 기능
- 지나치게 큰 파일에서 아직 만들지 않은 행까지 가로지르는 텍스트 선택

위 항목은 승인된 웹 시안에 없고 현재 Full Diff의 목적에도 필요하지
않으므로 이번 작업에 넣지 않습니다.
