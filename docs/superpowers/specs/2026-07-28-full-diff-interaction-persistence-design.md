# Full Diff 상호작용과 옵션 저장 설계

## 목표

미리보기의 파일 목록과 코드 diff를 따로 스크롤할 수 있게 만들고 Full Diff에서
마지막으로 사용한 화면과 표시 옵션을 다시 열 때 복원한다. diff 표시 방식과 Hunk
범위를 서로 독립된 옵션으로 정리하며 알고리즘 설명, Blame 줄 선택, 패널 폭 조절,
페이지 스크롤을 한 흐름으로 다듬는다.

## 확인한 현재 동작

- 미리보기는 커밋 정보, 파일 목록, 코드 diff를 하나의
  `SingleChildScrollView`로 감싸고 있어 함께 스크롤된다.
- Full Diff의 표시 방식은 `Hunk`, `Inline`, `Split` 중 하나를 고르는 구조다.
  `Hunk`는 현재 선택한 Hunk 하나만 표시한다.
- Myers, Minimal, Patience, Histogram을 선택하면 각각
  `--diff-algorithm=…` 인자가 실제 Git 명령에 전달된다.
- 공백 무시를 켜면 `--ignore-all-space`가 실제 Git 명령에 전달된다.
- 새 파일이나 추적하지 않는 파일은 전체가 추가된 내용이라 알고리즘에 따른 결과
  차이가 생기지 않는다.
- Git blame의 porcelain 결과에는 줄마다 짧은 설명으로 사용할 커밋 제목이 이미
  포함되어 있다. Blame 상세 카드 때문에 Git을 다시 호출할 필요는 없다.
- 파일 목록 폭은 조절할 수 있지만 History 목록 폭은 고정되어 있다. History
  목록에는 바깥쪽 12px 여백이 있다.
- `⌘⇧↑/↓` 페이지 스크롤은 현재 고정된 48px만 이동한다.

## 범위

### 포함

- 미리보기 파일 목록 영역과 코드 diff 영역의 독립 스크롤
- Full Diff 화면과 옵션의 영구 저장
- Unified / Side-by-side 배치와 Hunk 범위의 분리
- 한 파일의 모든 Hunk를 한 스크롤 화면에 표시
- Hunk를 끈 전체 파일 diff
- 실제 Git 알고리즘 적용 상태 유지와 즉시 반응하는 설명창
- Command 키를 누르는 동안 나타나는 단축키 안내
- Blame 줄 호버, 선택, 키보드 이동, 커밋 상세 카드
- 화면 높이의 50%만 이동하는 페이지 스크롤
- 파일·History·diff 패널 사이의 구분선과 폭 조절
- History 목록의 바깥 여백 제거

### 제외

- 마지막으로 선택한 파일 저장
- Blame에서 마지막으로 선택한 줄 저장
- 집중 모드 저장
- Git과 다른 자체 diff 알고리즘 도입
- 커밋 본문의 추가 조회
- 미리보기의 커밋 정보 배치 변경

## 용어와 옵션 구조

현재 `DiffPresentation.hunk`, `inline`, `split` 구조를 다음 두 축으로 나눈다.

```dart
enum DiffLayout { unified, sideBySide }
enum DiffScope { hunks, fullFile }
```

- **Unified**: 기존 Inline을 대체한다. 삭제와 추가를 한 열에 이어 표시한다.
- **Side-by-side**: 기존 Split을 대체한다. 이전 내용과 이후 내용을 두 열에
  나란히 표시한다.
- **Hunk 켬**: `DiffScope.hunks`다. 변경 주변의 문맥만 표시한다.
- **Hunk 끔**: `DiffScope.fullFile`이다. 파일 전체를 diff에 포함한다.

Unified와 Side-by-side는 둘 중 하나가 항상 선택된다. Hunk는 두 배치와 동시에
선택할 수 있는 별도 토글이며 기본값은 켬이다.

## 옵션 저장

`AppSettings`에 `FullDiffPreferences`를 추가한다.

```dart
class FullDiffPreferences {
  const FullDiffPreferences({
    this.view = FullDiffView.diff,
    this.layout = DiffLayout.unified,
    this.scope = DiffScope.hunks,
    this.algorithm = DiffAlgorithm.gitSetting,
    this.ignoreWhitespace = false,
    this.wrapLines = true,
  });

  final FullDiffView view;
  final DiffLayout layout;
  final DiffScope scope;
  final DiffAlgorithm algorithm;
  final bool ignoreWhitespace;
  final bool wrapLines;
}
```

저장하는 값은 다음과 같다.

- File / Diff / Blame / History 중 마지막 화면
- Unified / Side-by-side 중 마지막 배치
- Hunk 켜짐 여부
- diff 알고리즘
- 공백 무시
- 줄바꿈

Full Diff를 새로 열면 저장한 값으로 새 세션을 만든다. 파일과 Blame 선택 줄은
새 문서에 그대로 적용할 수 없으므로 저장하지 않는다. 집중 모드도 화면을 닫을
때 해제한다.

화면 선택, 배치, 줄바꿈은 즉시 저장한다. Hunk 범위, 알고리즘, 공백 무시는 Git
diff를 다시 읽어야 하므로 새 결과를 성공적으로 받은 뒤 저장한다. Git 호출이
실패하면 마지막으로 화면에 적용된 값과 diff를 유지하며 실패한 선택은 저장하지
않는다.

설정 파일에 없는 값이나 알 수 없는 enum 문자열이 있으면 위 기본값을 사용한다.

## diff 읽기와 표시

`FullDiffRepository.loadDiff`는 알고리즘과 공백 옵션 외에 `DiffScope`를 받는다.
패치 캐시 키에도 범위를 포함해 Hunk 결과와 전체 파일 결과가 섞이지 않게 한다.

### Hunk 켬

- Git에는 기존과 같이 `--unified=3`을 전달한다.
- Unified와 Side-by-side 모두 문서 안의 모든 Hunk를 파일 위치 순서대로 하나의
  `ListView`에 넣는다.
- Hunk 사이에 별도 페이지나 빈 화면을 만들지 않는다.
- 이전·다음 변경 버튼과 `⌥↑/↓`는 페이지를 바꾸지 않고 같은 목록 안의 Hunk
  위치로 스크롤한다.
- 활성 Hunk는 현재와 같은 배경과 미니맵 표시로 구분한다.

### Hunk 끔

- Git에는 `fullDiffTextLineLimit`과 같은 크기의 문맥 범위를 `--unified`로
  전달한다. 지원하는 최대 파일 행 수보다 문맥이 넓으므로 변경 파일 전체가
  결과에 포함된다.
- Unified는 전체 파일의 문맥, 삭제, 추가를 한 열에 표시한다.
- Side-by-side는 전체 문맥을 포함한 이전·이후 열을 표시한다.
- 파일 크기와 행 수 제한은 기존 Full Diff 제한을 그대로 사용한다.

두 범위 모두 선택한 `DiffAlgorithm.gitArguments`와 공백 무시 인자를 같은 Git
명령에 전달한다. 추적하지 않는 파일과 새 파일은 모두 추가된 파일로 표시하므로
알고리즘에 따른 차이가 없는 것이 정상이다.

## 도구 모음과 단축키

표시 방식은 Hunk 토글과 Unified / Side-by-side 선택 그룹으로 보인다. Hunk는
선택 배경을 가진 토글이며 Unified와 Side-by-side는 항상 한쪽만 선택되는
분할 버튼으로 표현한다.

| 동작 | 단축키 |
| --- | --- |
| File | `⌘1` |
| Diff | `⌘2` |
| Blame | `⌘3` |
| History | `⌘4` |
| Unified / Side-by-side 전환 | `⌘U` |
| Hunk 켜기·끄기 | `⌘⇧H` |
| diff 알고리즘 선택창 | `⌘⇧A` |
| 공백 무시 | `⌘⇧Space` |
| 줄바꿈 | `⌘⇧L` |
| 집중 모드 | `⌘⇧F` |
| 페이지 위·아래 이동 | `⌘⇧↑/↓` |
| 이전·다음 Hunk | `⌥↑/↓` |
| 이전·다음 파일 | `⌘↑/↓` |

`⌘U`를 누를 때마다 Unified와 Side-by-side를 번갈아 선택한다. 별도의
Side-by-side 단축키는 두지 않는다.

Command 키를 누르고 있는 동안 각 옵션 아래에 단축키를 작은 배지로 표시한다.
배지는 오버레이로 그려 도구 모음 높이와 버튼 위치를 바꾸지 않는다.
Unified / Side-by-side 그룹은 두 버튼 아래 중앙에 `⌘U`를 한 번만 표시한다.
Command 키를 놓으면 즉시 숨긴다.

단축키는 텍스트 선택이나 알고리즘 선택창이 입력을 처리하고 있을 때 해당 입력을
우선한다. 운영체제가 사용하는 단축키와 충돌하는 조합은 사용하지 않는다.

## diff 알고리즘 선택창

기존 `PopupMenuButton`을 도구 모음 버튼에 붙는 설명창으로 교체한다.

- 왼쪽에는 Git setting, Myers, Minimal, Patience, Histogram 목록을 표시한다.
- 오른쪽에는 가리키는 알고리즘의 이름, 간략한 설명, 적합한 상황, 짧은 비교
  예시를 표시한다.
- 마우스를 올리거나 `↑/↓`로 이동하면 기다리는 시간 없이 오른쪽 내용이 바뀐다.
- 클릭하거나 Enter를 누를 때만 실제 diff에 적용한다.
- Esc를 누르면 값을 바꾸지 않고 닫는다.
- 현재 적용된 값은 체크 표시로 나타내고 설명을 미리 보는 값은 별도 호버·포커스
  배경으로 구분한다.
- `⌘⇧A`로 설명창을 열면 현재 적용된 항목에 키보드 포커스를 둔다.

설명 예시는 네 줄 안에서 같은 입력이 어떤 변경 묶음으로 보일 수 있는지
간단히 보여준다. Git setting은 저장소 설정을 따르며 별도 설정이 없으면 Git의
기본 동작을 사용한다고 설명한다. 실제 diff는 설명용 예시가 아니라 선택한
Git 알고리즘이 만든 결과를 사용한다.

## 미리보기 독립 스크롤

현재 하나인 `_previewScrollController`를 파일 영역과 diff 영역용 컨트롤러로
나눈다.

- 커밋 정보와 파일 목록은 하나의 스크롤 영역을 사용한다.
- 선택한 파일의 코드 diff는 별도 스크롤 영역을 사용한다.
- 좌측·우측 미리보기에서는 두 영역을 위아래로 배치하고 각각 스크롤한다.
- 하단 미리보기에서는 파일 영역과 diff 영역을 좌우로 배치하고 각각
  스크롤한다.
- 두 영역 사이에는 1px 구분선을 표시한다.
- 파일을 바꿔도 파일 목록의 스크롤 위치는 유지하며 새 diff는 맨 위에서
  시작한다.

마지막으로 클릭하거나 마우스 휠을 사용한 영역을 활성 스크롤 영역으로 기억한다.
`⌘⇧↑/↓`는 활성 영역을 화면 높이의 50%만큼 이동한다. 아직 상호작용한 영역이
없으면 코드 diff를 이동한다.

## 페이지 스크롤

고정된 `pageScrollStep = 48`을 사용하지 않는다. 이동 거리는 현재 스크롤
위치가 가진 `viewportDimension * 0.5`로 계산한다.

```dart
final distance = position.viewportDimension * 0.5;
final target = position.pixels + direction * distance;
```

최솟값과 최댓값에서 기존처럼 범위를 제한한다. 키를 누른 첫 동작은 짧게
애니메이션하고 키를 계속 누를 때는 즉시 이동해 입력이 밀리지 않게 한다. Full
Diff에서는 코드 또는 상세 영역을 이동하며 파일 목록과 History 목록의
`↑/↓` 선택 동작은 그대로 유지한다.

## Blame 줄 선택

`FullBlameView`는 자체 FocusNode와 선택 줄, 호버 줄을 관리한다. 이 상태는
화면을 닫을 때 버린다.

- 마우스를 올린 줄에는 옅은 배경을 표시한다.
- 줄을 클릭하면 해당 줄을 선택하고 Blame 목록에 포커스를 둔다.
- 포커스가 있을 때 `↑/↓`로 이전·다음 줄을 선택한다.
- 키보드로 선택한 줄 자체만 화면 밖에 있지 않도록 이동한다.
- 활성 Hunk 배경과 선택 배경이 겹치면 선택 배경을 우선하며 Hunk 상태는
  미니맵과 변경 색으로 계속 구분한다.

선택한 줄의 화면 좌표를 기준으로 두 행 높이 아래에 커밋 상세 카드를 오버레이로
그린다.

- 카드는 목록 행의 높이를 늘리거나 뒤의 줄을 아래로 밀지 않는다.
- 바로 다음 줄은 가리지 않고 그 아래 줄부터 겹칠 수 있다.
- 짧은 해시, 작성자, 작성 날짜, 커밋 제목을 표시한다.
- 카드가 화면 아래에서 잘려도 위치를 위로 바꾸지 않는다. 사용자가 목록을
  스크롤해 확인한다.
- 카드가 겹친 줄을 클릭할 수 있도록 포인터 입력은 뒤의 Blame 목록으로
  통과시킨다.
- 스크롤할 때 선택 줄과 같은 속도로 이동하고 Blame 뷰포트 밖에서는 잘린다.

커밋 제목은 `BlameLine.summary`를 사용하므로 추가 Git 호출과 별도 캐시는
필요하지 않다.

## 패널 구분과 폭 조절

Full Diff의 파일 목록, History 목록, diff 상세 영역 사이에 항상 보이는 1px
세로 구분선을 둔다. 각 선에는 시각적 폭과 별개로 8px 크기의 투명한 드래그
영역을 겹쳐 놓는다.

- 파일 목록 폭과 History 목록 폭을 각각 조절한다.
- 드래그가 끝날 때 값을 저장한다.
- 구분선에 키보드 포커스가 있으면 `←/→`로 8px씩 조절할 수 있다.
- 좁은 창에서는 diff 상세 영역의 최소 폭을 먼저 보장하고 목록 폭을 제한한다.
- 집중 모드는 저장된 폭을 덮어쓰지 않으며 해제하면 이전 폭으로 돌아간다.

`FullDiffColumnWidths`는 파일 폭과 History 폭을 명시적으로 저장한다. 기존
설정의 `commits` 값은 History 폭의 이전 값으로 읽어 설정 파일을 자동으로
옮긴다.

History `ListView`의 바깥 `EdgeInsets.all(12)`를 제거한다. 선택 배경과 포커스
테두리는 패널 가장자리까지 채우며 행의 텍스트와 배지에만 내부 여백을 둔다.

## 오류 처리

- 알고리즘, Hunk 범위, 공백 무시 적용이 실패하면 기존 diff와 기존 옵션을
  유지한다.
- 설명창은 오류가 난 값으로 체크 표시를 옮기지 않는다.
- 설정 저장 실패는 현재 세션의 화면을 되돌리지 않는다. 다음 실행에서 마지막으로
  저장에 성공한 값이 복원된다.
- 파일 전체 diff가 기존 크기나 행 수 제한을 넘으면 현재 구조화된 안내 화면과
  다시 시도 동작을 사용한다.
- Blame 데이터에 커밋 제목이 없으면 해시, 작성자, 날짜만 표시한다.

## 성능과 캐시

- 패치 캐시 키에 `DiffScope`를 넣어 Hunk와 전체 파일 결과를 각각 재사용한다.
- 알고리즘 설명은 정적 데이터라 비동기 조회와 지연 타이머를 사용하지 않는다.
- Blame 호버는 현재 줄 번호만 갱신한다. 커밋 데이터와 코드 토큰을 다시
  계산하지 않는다.
- 패널 폭은 드래그 중 메모리 상태만 바꾸고 드래그가 끝날 때 한 번 저장한다.
- 전체 파일 diff는 기존 파일 크기, 행 수, 원시 캐시 용량 제한 안에서만
  처리한다.

## 접근성

- Unified / Side-by-side는 하나만 선택되는 라디오 그룹으로 알린다.
- Hunk, 공백 무시, 줄바꿈, 집중 모드는 켜짐 상태를 가진 토글로 알린다.
- 알고리즘 설명창의 목록은 현재 적용 값과 키보드 포커스 값을 각각 알린다.
- Blame 줄은 줄 번호와 커밋 제목을 포함한 선택 가능한 행으로 알린다.
- 패널 크기 조절 영역에는 대상 패널 이름과 현재 폭을 알린다.
- 단축키 안내 배지는 시각적 보조 정보이며 각 컨트롤의 접근성 힌트에도 같은
  단축키를 포함한다.

## 테스트

### 단위 테스트

- 설정 JSON 왕복, 알 수 없는 값의 기본 처리, 기존 `commits` 폭 이전
- `DiffScope`에 따른 `--unified` 값과 캐시 키 구분
- 모든 알고리즘과 공백 무시 인자가 같은 Git 명령에 포함되는지 확인
- 페이지 스크롤이 뷰포트 높이의 50%만큼 이동하고 양 끝에서 멈추는지 확인
- 실패한 비동기 옵션이 이전 적용 값으로 돌아가며 저장 콜백을 부르지 않는지 확인

### 위젯 테스트

- 미리보기 파일 영역과 diff 영역의 스크롤 위치가 서로 영향을 주지 않는지 확인
- Full Diff를 닫고 다시 열거나 앱을 다시 만들었을 때 마지막 옵션 복원
- `⌘1`부터 `⌘4`, `⌘U`, 각 토글 단축키 동작
- Command 키를 누르는 동안에만 단축키 배지가 보이고 레이아웃이 움직이지 않는지
  확인
- Hunk를 켰을 때 한 파일의 모든 Hunk가 같은 목록에 순서대로 나타나는지 확인
- Hunk를 끄면 앞뒤 전체 문맥이 Unified와 Side-by-side에 나타나는지 확인
- 알고리즘 목록의 호버와 키보드 이동이 오른쪽 설명을 즉시 바꾸는지 확인
- Blame 호버, 클릭 선택, `↑/↓` 이동, 두 줄 아래 카드 위치와 비확장 레이아웃
- 파일·History·diff 구분선, 두 폭의 드래그와 키보드 조절
- History 목록 선택면이 위·왼쪽·오른쪽 가장자리까지 닿는지 확인

### 통합 테스트

- 실제 임시 Git 저장소에서 알고리즘마다 기대한 인자가 전달되고 결과가 바뀌는
  사례 확인
- Hunk와 전체 파일 범위를 오간 뒤 캐시된 결과가 서로 섞이지 않는지 확인
- 저장소를 바꾸거나 다른 커밋을 열어도 표시 옵션은 유지하고 선택 파일은 새로
  정하는지 확인

## 완료 기준

1. 미리보기 파일 영역과 코드 diff 영역을 독립적으로 스크롤할 수 있다.
2. Full Diff를 다시 열면 마지막 화면과 표시 옵션이 복원된다.
3. Unified와 Side-by-side 중 하나가 항상 선택되며 `⌘U`로 전환된다.
4. Hunk는 별도 토글이고 기본값은 켬이다.
5. Hunk를 켜면 파일의 모든 Hunk가 한 스크롤 화면에 위치 순서대로 표시된다.
6. Hunk를 끄면 전체 파일 문맥이 Unified와 Side-by-side에 표시된다.
7. 선택한 Git diff 알고리즘과 공백 옵션이 실제 명령에 적용된다.
8. 알고리즘 설명창의 오른쪽 설명이 호버와 키보드 이동에 즉시 반응한다.
9. Command 키를 누르면 옵션 아래에 단축키가 나타나며 화면 배치가 움직이지
   않는다.
10. Blame 줄을 호버·클릭·키보드로 선택할 수 있고 커밋 상세 카드가 두 줄 아래에
    다른 줄을 밀지 않고 나타난다.
11. `⌘⇧↑/↓`는 활성 스크롤 영역을 현재 보이는 높이의 50%만큼 이동한다.
12. 파일·History·diff 패널 사이에 세로선이 있으며 각 목록 폭을 조절하고
    복원할 수 있다.
13. History 목록은 패널 바깥 여백 없이 가장자리에 붙는다.
