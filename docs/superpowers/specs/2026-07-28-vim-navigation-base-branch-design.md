# Vim 이동키와 기준 브랜치 설계

## 목표

- 방향키로 이동할 수 있는 앱의 목록과 패널에서 `h`, `j`, `k`, `l`도 각각 왼쪽, 아래, 위, 오른쪽 이동키로 쓸 수 있게 한다.
- 저장소 선택 오른쪽에 로컬 기준 브랜치 선택기를 둔다.
- 선택한 기준 브랜치의 첫 번째 부모 흐름을 타임라인 그래프의 가장 왼쪽 레인에 둔다.
- 기준 브랜치는 저장소별로 기억한다.

## 범위

### 포함

- 타임라인, 커밋 상세 화면, 전체 diff 화면에서 직접 처리하는 방향키 이동
- 파일·히스토리·blame 목록, 미니맵, 패널 크기 조절 손잡이의 방향키 이동
- 로컬 브랜치 선택기
- 기준 브랜치에 맞춘 그래프 레인 계산
- 저장소별 기준 브랜치 설정 저장

### 제외

- 원격 브랜치와 태그를 기준 브랜치 선택 목록에 표시하는 기능
- 선택한 기준 브랜치로 체크아웃하는 기능
- Git 로그의 커밋 정렬 순서나 페이지 크기를 바꾸는 기능
- 수정키와 함께 누른 `h`, `j`, `k`, `l`을 방향키 조합으로 바꾸는 기능
- 팝업 메뉴가 열린 동안 메뉴의 기본 키 처리를 바꾸는 기능

## Vim 이동키

방향키를 직접 비교하는 각 키 처리 지점은 공통 변환 함수를 사용한다. 수정키를 누르지 않은 다음 키만 변환한다.

| 입력 | 처리할 방향키 |
| --- | --- |
| `h` | `←` |
| `j` | `↓` |
| `k` | `↑` |
| `l` | `→` |

공통 함수는 키의 의미만 바꾼다. 이동량, 반복 입력, 애니메이션, 포커스 전환은 기존 화면이 지금처럼 결정한다. 따라서 타임라인에서 `j`를 길게 누르면 `↓`를 길게 누른 것처럼 커밋 선택이 연속으로 이동한다.

다음 상황에서는 변환하지 않는다.

- `Command`, `Control`, `Option`, `Shift` 가운데 하나라도 눌린 경우
- `TextField`나 그 밖의 편집 가능한 입력란이 키 입력을 받고 있는 경우
- 팝업 메뉴가 열려 있어서 메뉴가 키를 처리하는 경우

Flutter 위젯이 기본으로 제공하는 방향키 탐색은 그대로 둔다. 이 작업은 앱 코드가 직접 방향키를 처리하는 곳에만 Vim 이동키를 더한다.

## 툴바와 기준 브랜치 선택기

툴바 왼쪽에서 저장소 선택과 기준 브랜치 선택을 한 덩어리로 배치한다.

1. `저장소` 항목은 현재 저장소 이름과 아래쪽 화살표를 보여준다. 누르면 기존 폴더 선택기를 연다.
2. 오른쪽의 `기준 브랜치` 항목은 선택한 로컬 브랜치 이름과 아래쪽 화살표를 보여준다.
3. 브랜치 항목을 누르면 로컬 브랜치만 들어 있는 메뉴를 연다. 선택한 브랜치는 메뉴에서도 구분해 표시한다.
4. 긴 저장소 이름과 브랜치 이름은 말줄임표로 줄이고 툴팁에는 전체 이름을 넣는다.
5. 기존 창 이동 영역과 wordmark는 남은 너비를 사용한다. 최소 창 너비에서도 오른쪽 도구 모음과 겹치지 않도록 wordmark가 먼저 작아지거나 숨는 기존 규칙을 유지한다.

refs를 아직 읽고 있으면 브랜치 항목을 비활성화한다. 로컬 브랜치가 없으면 `브랜치 없음`, refs를 읽지 못하면 `불러오기 실패`를 표시한다. 어느 경우에도 타임라인 자체는 계속 사용할 수 있다.

## 기준 브랜치 결정과 저장

설정에는 `저장소 절대 경로 → 로컬 브랜치 이름` 맵을 추가한다. 기존 설정 파일에 이 값이 없어도 빈 맵으로 읽는다.

저장소를 열면 다음 순서로 기준 브랜치를 결정한다.

1. 저장된 브랜치가 현재 로컬 브랜치 목록에 있으면 그 브랜치를 사용한다.
2. 현재 체크아웃한 브랜치가 있으면 그 브랜치를 사용한다.
3. 로컬 브랜치가 하나 이상이면 목록의 첫 번째 브랜치를 사용한다.
4. 로컬 브랜치가 없으면 기준 브랜치를 두지 않는다.

저장값 대신 2번이나 3번을 쓴 경우에는 결정된 값을 새 설정으로 저장한다. 사용자가 선택기에서 브랜치를 고르면 현재 저장소 항목만 갱신한다. 다른 저장소에 저장된 값은 유지한다.

기준 브랜치를 바꿀 때 다음 상태는 유지한다.

- 선택한 커밋
- 타임라인 스크롤 위치
- 열려 있는 미리보기와 미리보기 안의 선택
- 이미 읽은 커밋 페이지

Git 로그를 다시 읽지 않고 그래프 행과 레인 색상만 다시 계산한다.

## 그래프 계산

`layoutGraph`는 선택 사항인 `preferredTip` 커밋 SHA를 받는다. 값이 없으면 기존 계산 결과를 그대로 내야 한다.

`preferredTip`이 있으면 0번 레인을 해당 SHA를 위한 자리로 예약한다. 다른 커밋은 1번 레인부터 배치한다. 먼저 읽은 자식 커밋의 첫 번째 부모나 머지 부모가 아직 읽지 않은 `preferredTip`이면 그 부모 선을 즉시 0번 레인으로 연결한다. 나중에 기준 브랜치의 끝 커밋을 읽으면 이미 그려 둔 선을 이어받고 이후 첫 번째 부모도 같은 레인을 쓴다. 기준 브랜치가 병합 커밋을 포함해도 첫 번째 부모 흐름은 계속 0번 레인에 남는다.

작업 트리 행은 다음 규칙을 따른다.

- 작업 트리 행의 부모가 `preferredTip`이면 작업 트리 행부터 0번 레인을 쓴다.
- 다른 브랜치를 기준으로 골랐다면 작업 트리 행은 일반 브랜치처럼 1번 이후의 레인을 쓴다.

기준 브랜치 끝 커밋이 아직 다음 페이지에 있고 먼저 읽은 커밋도 그 SHA를 부모로 가리키지 않으면 0번 레인이 비어 있을 수 있다. 반대로 먼저 읽은 자식이 그 SHA를 첫 번째 부모나 머지 부모로 가리키면 자식의 부모 선부터 0번 레인을 쓴다. 나중에 끝 커밋을 읽어도 이 선에 합류하므로 위쪽 행의 레인, 브랜치 식별자, 전이선은 바뀌지 않는다.

그래프가 끝난 뒤 레인 번호를 바꾸거나 Git 로그 순서를 재정렬하지 않는다. 두 방법 모두 기존 선 연결과 시간순 탐색을 흔들 수 있다.

## 상태 흐름

1. `YogitApp`이 설정에서 현재 저장소에 저장된 기준 브랜치 이름을 읽어 `TimelineScreen`에 넘긴다.
2. `TimelineScreen`이 refs를 읽고 실제로 쓸 기준 브랜치를 정한다.
3. refs의 tip SHA를 `layoutGraph`의 `preferredTip`으로 넘긴다.
4. 브랜치를 새로 선택하면 현재 커밋 목록으로 그래프를 다시 계산한다.
5. `TimelineScreen`이 변경 콜백을 호출하면 `YogitApp`이 저장소별 설정 맵을 저장한다.
6. 저장소를 바꾸면 새 저장소 경로를 키로 삼아 같은 절차를 다시 수행한다.

## 오류 처리

- refs를 읽지 못하면 사이드바는 지금처럼 비어 있고 기준 브랜치 선택기만 실패 상태를 표시한다.
- 선택한 브랜치가 사라졌으면 다음에 refs를 읽을 때 기본 선택 순서로 돌아간다.
- 설정 저장에 실패해도 현재 세션의 선택과 그래프는 유지한다. 별도 오류 창은 추가하지 않고 기존 설정 저장 방식과 같은 정책을 쓴다.
- 유효한 기준 브랜치 tip SHA를 찾지 못하면 기존 그래프 계산을 사용한다.

## 코드 구성

- `lib/vim_navigation.dart`: 수정키 상태를 확인하고 Vim 이동키를 방향키로 바꾸는 공통 함수
- `lib/repository_branch_selector.dart`: 저장소와 기준 브랜치 선택 영역의 표시와 메뉴
- `lib/git.dart`: 기준 브랜치 tip을 위한 0번 레인 예약과 기존 그래프 계산 유지
- `lib/settings.dart`: 저장소별 기준 브랜치 맵의 직렬화, 역직렬화, 복사, 동등성
- `lib/main.dart`: 현재 저장소의 저장값을 `TimelineScreen`에 전달하고 변경값 저장
- `lib/timeline.dart`: refs 상태, 실제 기준 브랜치 결정, 그래프 다시 계산, 툴바 연결
- 방향키를 직접 처리하는 기존 전체 diff 관련 파일: 공통 Vim 이동키 변환 적용

큰 기존 파일을 이 작업과 무관하게 나누지는 않는다. 새 파일은 여러 화면이 함께 쓰는 키 변환과 독립적으로 테스트할 수 있는 툴바 선택기만 맡는다.

## 테스트

### 공통 키 변환

- 수정키가 없을 때 `h`, `j`, `k`, `l`을 올바른 방향키로 바꾼다.
- 방향키와 다른 일반 키는 바꾸지 않는다.
- 수정키가 있으면 Vim 이동키를 바꾸지 않는다.

### 화면별 키 동작

- 타임라인에서 `j`, `k`가 `↓`, `↑`과 같은 선택 이동과 반복 입력을 수행한다.
- 파일 목록에서 `j`, `k`, `l`이 아래, 위, 오른쪽 이동과 같은 결과를 낸다.
- 히스토리와 blame 목록, 미니맵에서 `h`, `j`, `k`가 해당 방향키와 같은 결과를 낸다.
- 타임라인과 전체 diff의 패널 크기 조절 손잡이에서 `h`, `l`이 `←`, `→`와 같은 폭 변경을 수행한다.
- diff 알고리즘 메뉴가 열린 동안에는 메뉴의 기존 키 처리가 우선한다.
- 텍스트 입력란에서는 `h`, `j`, `k`, `l`을 문자로 입력할 수 있다.

### 기준 브랜치와 그래프

- 현재 체크아웃 브랜치를 첫 기본값으로 고른다.
- 저장된 로컬 브랜치를 복원하고 사라진 저장값은 안전하게 대체한다.
- 선택기는 원격 브랜치와 태그를 표시하지 않는다.
- 기준 브랜치의 끝 커밋과 첫 번째 부모 흐름이 0번 레인을 쓴다.
- 더 최신인 다른 브랜치 커밋이 위에 있어도 0번 레인을 차지하지 않는다.
- 기준 브랜치가 현재 브랜치일 때 작업 트리 행이 0번 레인을 쓴다.
- 다른 기준 브랜치를 고르면 작업 트리 행이 0번 이후의 레인을 쓴다.
- 페이지 추가 전후에 이미 표시한 행의 레인과 선 연결이 안정적이다.
- 기준 브랜치가 없을 때 기존 `layoutGraph` 결과가 유지된다.

### 설정과 툴바

- 저장소별 브랜치 맵이 JSON을 왕복하고 기존 설정 JSON도 읽는다.
- 두 저장소의 선택값을 서로 덮어쓰지 않는다.
- 브랜치를 바꿔도 선택한 커밋, 스크롤, 미리보기가 유지된다.
- 툴바는 최소 지원 너비에서 넘치지 않는다.
- refs 로딩, 빈 목록, 실패 상태를 구분해 표시한다.
