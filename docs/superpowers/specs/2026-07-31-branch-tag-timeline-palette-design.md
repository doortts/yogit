# Branch / Tag 타임라인 팔레트 설계

## 목표

Branch / Tag 이름 칩에 GitHub Enterprise 이슈 라벨에서 확인한 다섯 가지
색상 조합을 기본값으로 적용한다. 같은 이름은 저장소나 실행 시점이 달라도
항상 같은 색상 조합을 사용한다.

이름 칩과 연결된 그래프 선, 곡선, 화살표, 노드도 같은 Text 색상을
공유한다. 현재 그래프가 브랜치별로 한 색상을 공유하는 구조는 그대로
사용한다.

## 기준 팔레트

`https://oss.navercorp.com/pi/arc-agent/issues`에서 확인한 실제 CSS 값을
기준으로 삼는다.

| 순서 | 참고 라벨 | Base | Text |
| --- | --- | --- | --- |
| 1 | `epic:foundation` | `#1D76DB` | `#68A7EA` |
| 2 | `security` | `#E99695` | `#E89292` |
| 3 | `task` | `#C5DEF5` | `#C2DDF4` |
| 4 | `feature` | `#0E8A16` | `#18E022` |
| 5 | `epic` | `#5319E7` | `#DACFFA` |

칩은 GitHub Enterprise에서 확인한 합성 규칙도 그대로 따른다.

- 배경: Base 색상, 불투명도 18%
- 테두리: Text 색상, 불투명도 30%
- 글자와 HEAD/Tag 기호: Text 색상, 불투명도 100%
- 그래프 선·곡선·연결선·화살표·점·링: 같은 Text 색상, 불투명도 100%

따라서 칩 테두리와 그래프는 같은 원본 Text 색상을 사용한다. 테두리에만
GitHub CSS의 30% 불투명도를 적용한다.

## 색상 선택

ref 이름의 UTF-16 코드 단위를 순서대로 읽어 `hash = hash * 31 + codeUnit`
방식으로 양수 해시를 만든다. 팔레트 인덱스는 `hash % 5`다. Dart의
`String.hashCode`는 사용하지 않는다. 이 규칙으로 같은 Branch/Tag 이름은
저장소와 앱 실행이 달라져도 같은 색상을 고른다.

한 그래프 선에 여러 ref가 연결될 때 선을 대표할 이름은 다음 순서로
고른다.

1. 현재 HEAD
2. 로컬 브랜치
3. 리모트 브랜치
4. 태그
5. 로그 장식에서만 확인된 ref

같은 우선순위에서는 이름순으로 고른다. 대표 ref의 칩을 먼저 표시하고,
그래프 선과 화살표에는 대표 ref의 Text 색상을 적용한다. 나머지 칩은
각자 자기 이름으로 고른 색상 조합을 사용한다. 브랜치와 태그가 같은
커밋을 가리키면 브랜치가 선을 대표하고, 태그는 브랜치 선의 색상을
바꾸지 않는다.

불러온 범위 안에 이름이 없는 선은 현재 `assignBranchColors`가 고른
색상을 사용한다. 삭제된 브랜치나 아직 ref 정보를 읽지 못한 순간에도
그래프가 사라지지 않게 하는 예외 처리다.

브랜치 비교와 rebase 미리보기에서 충돌·가상 커밋을 구분하는 전용 색상은
그 의미를 유지한다. 실제 Branch/Tag가 가리키는 일반 선에만 이번
팔레트를 적용한다.

## 설정

기존 `Timeline colors` 영역에 `Branch / Tag palette`를 추가한다. 다섯
행에는 칩 미리보기와 Base/Text 6자리 16진수 입력란을 표시한다. 18%와
30% 불투명도는 GitHub 표현 규칙이므로 별도 설정으로 만들지 않는다.

올바른 값을 입력하면 설정과 타임라인에 바로 반영한다. 입력 중인 값이
완전한 6자리 색상이 아니면 마지막으로 저장된 값을 유지한다. 저장된
팔레트의 행 개수나 색상값이 잘못됐으면 다섯 가지 기본 팔레트 전체를
사용한다.

`Reset to defaults`는 Branch / Tag 팔레트만 위 표의 값으로 되돌리는
버튼을 따로 둔다. 기존 기준 브랜치·레인 색상 설정은 이름을 찾지 못한
그래프 선의 대체 색상으로 남긴다.

## 적용 흐름

`AppSettings`는 Base/Text 쌍 다섯 개를 저장한다. `TimelineScreen`은 설정을
받아 ref 이름별 칩 색상과 브랜치 ID별 대표 Text 색상을 계산한다.
계산한 Text 색상은 기존 `AvatarService.branchAssignments`에 넣는다.
`CommitGraphPainter`와 사이드바의 브랜치 점 등 기존 색상 사용처는 이
공통 값을 그대로 읽으므로 별도의 그래프 색상 경로를 추가하지 않는다.

설정이 바뀌거나 ref·기준 브랜치·커밋 페이지를 다시 읽으면 브랜치 색상
할당을 다시 계산한다. 이름 해시가 기준이므로 같은 선의 색상은 페이지를
더 불러와도 바뀌지 않는다.

## 검증

- 다섯 기본 Base/Text 값과 18%/30% 불투명도를 코드에서 정확히 읽는다.
- 같은 이름은 저장소 시드와 실행 시점이 달라도 같은 인덱스를 고른다.
- HEAD·로컬·리모트·태그 우선순위와 이름순 결정이 항상 같다.
- 팔레트를 설정 JSON에 저장하고 다시 읽을 수 있다.
- 잘못된 저장값은 기본 팔레트 전체로 돌아간다.
- 설정 화면에서 각 Base/Text 값을 수정하고 기본값으로 되돌릴 수 있다.
- 대표 ref의 칩 테두리, 연결선, 화살표, 그래프 선과 노드가 같은 Text
  색상을 사용한다.
- 같은 커밋의 보조 ref 칩은 자기 이름에 해당하는 팔레트를 사용한다.
- 이름이 없는 선과 가상·충돌 미리보기는 기존 대체 색상과 전용 색상을
  유지한다.

구현 뒤에는 다섯 칩을 모두 표시한 화면을 캡처한다. 각 칩의 배경·테두리·
글자와 연결된 그래프 선·화살표를 원본 CSS 값에서 계산한 색상과 비교한다.
안티앨리어싱 경계가 아닌 평평한 픽셀을 측정하며 RGB 채널별 오차는 1
이하여야 한다. 값이나 연결 관계가 다르면 원인을 고치고 같은 검증을
다시 통과시킨다.
