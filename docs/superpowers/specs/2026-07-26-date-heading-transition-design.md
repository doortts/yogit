# 날짜 그룹 행을 지나는 그래프 전환선 수정

## 문제

날짜 그룹 행은 커밋 사이에 별도 타임라인 항목으로 들어간다. 현재
`CommitGraphPainter`는 한 `GraphRow`의 전환선이 바로 다음 타임라인 항목의
중앙에서 끝난다고 가정한다. 두 커밋 사이에 날짜 행이 들어가면 전환선은
실제 부모 커밋이 아니라 날짜 행 중앙에서 끝난다.

출발점에서 꺾이는 머지선은 눈에 띄는 문제가 없지만, 부모 커밋 가까이에서
꺾여야 하는 합류선은 날짜 행에서 한 행 일찍 꺾인다. 이후 목적지 레인이
부모 커밋까지 수직으로 이어져 그래프의 관계를 잘못 표현한다.

기존 날짜 행 테스트는 레일이 끊기지 않는지만 확인한다. 전환선이 어느
행에서 꺾이는지는 검사하지 않는다.

## 목표

- 날짜 그룹 행의 높이, 라벨, 선택 규칙은 그대로 둔다.
- 합류선과 첫 부모 꼬리는 날짜 행을 수직으로 지나 실제 부모 커밋에서
  꺾이게 한다.
- 출발 커밋에서 꺾이는 머지선은 지금처럼 출발점 가까이에서 꺾이게 한다.
- 레인과 전환선의 브랜치 색을 유지한다.
- 날짜 경계가 없는 그래프의 동작은 바꾸지 않는다.

## 범위에서 제외할 내용

- 날짜 그룹 행을 겹쳐 그리는 방식으로 바꾸지 않는다.
- `layoutGraph`의 커밋 레인 배치 알고리즘은 바꾸지 않는다.
- 여러 행을 한 번에 그리는 새 그래프 페인터를 만들지 않는다.
- 날짜 라벨의 모양이나 타임라인 행 높이를 바꾸지 않는다.

## 설계

### 1. 전환선 종류 판별을 함께 쓴다

현재 `CommitGraphPainter.isMergeEdge`가 전환선의 색과 굴곡 방향을
판별한다. 같은 판별을 날짜 행을 만들 때도 써야 하므로 순수 함수로
분리한다.

- 출발점에서 꺾임: 커밋 자신의 레인에서 둘째 이후 부모 레인으로 가는
  머지선
- 도착점에서 꺾임: 다른 레인이 부모로 합류하는 선과 커밋 자신의 첫
  부모 꼬리

페인터와 `timelineEntries`가 이 함수를 함께 써서 분류가 어긋나지 않게
한다.

### 2. 날짜 행에서 합류 전환을 한 단계 늦춘다

`timelineEntries`가 날짜 경계를 만나면 바로 위 `GraphRow`의 전환선을 두
종류로 나눈다.

- 출발점에서 꺾이는 전환은 위 커밋 행에 남긴다.
- 도착점에서 꺾이는 전환은 합성 날짜 행으로 옮긴다.

옮길 전환이 있으면 화면에 쓰는 위 커밋 행의 `nextLanes` 상태를 전환 직전
상태로 되돌린다. 합성 날짜 행은 이 중간 상태를 `activeLanes`로 받고 원래
위 커밋 행의 `nextLanes`를 최종 상태로 내보낸다. 옮긴 전환선은 날짜 행의
중앙에서 시작해 아래 부모 커밋의 중앙에서 끝난다.

중간 상태는 원래 최종 상태에서 옮길 전환을 역으로 적용해 만든다.

- 출발 레인에는 전환 대상 SHA와 출발 브랜치 정보를 복원한다.
- 목적지 레인이 전환 전에도 다른 선을 담고 있었다면 기존 선을
  복원한다.
- 전환 때문에 새로 생긴 목적지 레인이면 중간 상태에서 제거한다.

이렇게 하면 위 커밋의 아래쪽 절반과 날짜 행의 위쪽 절반에서는 출발
레인이 수직으로 이어진다. 날짜 행의 아래쪽 절반부터 기존 전환 경로를
그리므로 선은 실제 부모 커밋 중앙에서 꺾인다.

옮길 전환이 없으면 현재의 단순 통과 행을 그대로 만든다.

### 3. 원본 그래프는 바꾸지 않는다

`layoutGraph`가 만든 `_rows`는 브랜치 색 배정과 페이지 추가에 계속 쓴다.
날짜 행 때문에 필요한 행 복사본은 `timelineEntries` 안에서만 만든다.
따라서 저장소의 그래프 배치 결과와 페이지별 브랜치 번호는 달라지지
않는다.

## 데이터 흐름

1. `layoutGraph`가 실제 커밋만 포함한 `GraphRow` 목록을 만든다.
2. `timelineEntries`가 날짜 경계를 찾는다.
3. 경계 위 행에 도착점 굴곡 전환이 있으면 화면용 중간 상태를 만든다.
4. 위 커밋 행은 중간 상태까지 그리고 날짜 행이 전환을 이어받는다.
5. 아래 커밋 행은 날짜 행을 `previous`로 받아 전환선의 도착 절반을
   그린다.
6. 날짜 경계가 없으면 기존 경로를 그대로 쓴다.

## 예외와 안전한 기본 동작

새로운 입출력이나 비동기 오류는 생기지 않는다. 전환 정보가 없거나 날짜
행이 첫 커밋 위에 있으면 현재의 단순 통과 행을 만든다. 여러 전환이 같은
행에 있어도 각 전환을 따로 역적용하고 기존에 목적지 레인을 차지하던 선은
보존한다.
