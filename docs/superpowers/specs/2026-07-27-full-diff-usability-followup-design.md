# Full Diff 사용성 보완 설계

## 배경

현재 Full Diff 화면은 승인된 웹 시안의 기능과 구성을 구현했지만 실제
저장소를 오래 살펴볼 때 다음 문제가 남아 있습니다.

- 커밋·파일 목록과 diff 본문의 글자가 커서 한 화면에서 볼 수 있는
  정보가 적습니다.
- 타임라인으로 돌아가는 버튼이 상단에서 사라졌습니다.
- `Esc`가 포커스 상태와 집중 모드에 따라 타임라인으로 돌아가지
  않습니다.
- 닫힌 `diff 알고리즘` 메뉴만 보면 현재 선택값을 알 수 없습니다.
- 변경을 표시하지 못할 때 파일 정보 없이 짧은 문장만 보입니다.
- History 항목을 선택하면 목록 옆에서 해당 시점의 diff를 바로 비교할
  수 없습니다.

이 문서는 기존 Full Diff 구조와 시각 언어를 유지하면서 위 문제를
보완하는 범위를 정합니다.

## 목표

1. 목록과 diff의 정보 밀도를 높입니다.
2. 버튼과 키보드로 항상 타임라인에 돌아갈 수 있게 합니다.
3. 현재 diff 알고리즘과 의미를 메뉴를 열지 않고도 알 수 있게 합니다.
4. 표시할 수 없는 상태를 파일 정보와 정확한 사유로 설명합니다.
5. History 목록을 유지한 채 선택한 시점의 파일 diff를 오른쪽에서
   확인하게 합니다.
6. 기존 File·Diff·Blame, Hunk·Inline·Split, 미니맵, 복사, Git 캐시와
   비동기 요청 보호 동작을 깨뜨리지 않습니다.

## 범위에서 제외하는 내용

- 새로운 diff 알고리즘 추가
- 파일 편집이나 과거 커밋 복원
- 바이너리 전용 미리보기
- 지원하지 않는 인코딩을 자동 변환하는 기능
- Full Diff 전체 배색과 열 너비의 재설계
- History만을 위한 별도 Git 저장소 계층이나 중복 캐시

## 구현 접근

기존 `FullDiffSessionController`와 `DiffScreen`을 확장합니다. History
선택에도 기존 파일 목록, patch, 파일 내용 캐시와 알고리즘 설정을
사용합니다. History 전용 컨트롤러나 별도 화면은 만들지 않습니다.

이 접근은 다음 장점이 있습니다.

- History 오른쪽 diff가 일반 Diff와 같은 결과를 사용합니다.
- 알고리즘, 공백 무시, 줄바꿈과 Hunk·Inline·Split 동작이 자연스럽게
  공유됩니다.
- Git 요청 취소와 오래된 결과 차단 규칙을 한 군데에서 유지합니다.
- 현재 테스트와 검수 이미지를 작은 범위로 확장할 수 있습니다.

## 글자 크기

요청한 비율을 근사 정수로 바꿔 다음 값으로 고정합니다.

| 영역 | 현재 | 변경 | 비율 |
|---|---:|---:|---:|
| 커밋 제목 | 14 | 11 | 약 21% 감소 |
| 커밋 SHA·보조 정보 | 12 | 10 | 약 17% 감소 |
| 작은 커밋 메타 정보 | 11 | 9 | 약 18% 감소 |
| 선택한 커밋 제목 | 14 | 11 | 약 21% 감소 |
| 파일명 | 14 | 11 | 약 21% 감소 |
| 파일 추가·삭제 수와 상태 | 12 | 10 | 약 17% 감소 |
| 상단 파일 경로 | 14 | 11 | 약 21% 감소 |
| diff 코드 | 14 | 10 | 약 29% 감소 |
| diff 줄 번호와 기호 | 12 | 8 | 약 33% 감소 |
| Hunk 제목 | 14 | 10 | 약 29% 감소 |
| diff의 빈 상태·오류 안내 | 14 | 10 | 약 29% 감소 |

글자만 줄이고 기존 행 높이, Hunk 안쪽 여백, 목록 클릭 영역은
유지합니다. diff 코드의 줄 높이도 기존 21픽셀을 유지해 작은 글자가
붙어 보이지 않게 합니다. 기술 정보는 기존 Menlo 계열 고정폭 글꼴을
계속 사용합니다.

## 뒤로 가기와 `Esc`

### 버튼

`GlobalFileBar`의 가장 왼쪽에 `arrow_back` 아이콘 버튼을 둡니다. 파일
아이콘과 경로 칩은 그 오른쪽에 이어집니다.

- 접근성 이름: `타임라인으로 돌아가기`
- 도움말: `타임라인으로 돌아가기 (Esc)`
- 동작: 현재 Full Diff 경로에 `Navigator.maybePop()` 실행
- 크기와 색: 기존 상단 아이콘 버튼과 같은 32픽셀 클릭 영역과
  `fullDiffMuted`

### 키보드

Full Diff 경로의 최상위 포커스 영역에서 `Esc`를 처리합니다. 코드 선택
영역이나 History 목록에 포커스가 있어도 이벤트가 최상위 영역까지
전달되어야 합니다.

- 메뉴나 설명 팝오버가 열려 있으면 첫 번째 `Esc`는 열린 요소를
  닫습니다.
- 열린 요소가 없으면 `Esc`는 집중 모드 여부와 관계없이 타임라인으로
  돌아갑니다.
- 집중 모드는 `Cmd+Shift+F`와 `집중 모드` 버튼으로만 바꿉니다.
- 버튼과 `Esc`는 같은 `_returnToTimeline()` 경로를 호출합니다.

현재 구현은 `_handleEscape()`가 집중 모드를 먼저 끄며, 경로 안쪽의
`Focus(autofocus: true)`가 키보드 처리를 맡습니다. 최상위 경로의
포커스와 뒤로 가기 동작을 하나로 모아 두 문제를 함께 해결합니다.

## diff 알고리즘 표시와 설명

### 닫힌 버튼

일반 너비에서는 `diff 알고리즘 · Histogram`처럼 메뉴 이름과 현재
선택값을 함께 표시합니다. 480픽셀 이하에서는 한 줄 배치를 지키기 위해
`Histogram`처럼 선택값만 보이되 접근성 이름은
`diff 알고리즘: Histogram`으로 유지합니다.

요청 중인 알고리즘을 버튼에 표시합니다. Git 요청이 실패하면 기존
동작대로 마지막으로 성공한 알고리즘과 patch로 되돌아가므로 버튼도
성공한 선택값으로 복구됩니다.

### 마우스 호버 설명

버튼에 마우스를 올리면 비차단 설명 팝오버를 표시합니다. 팝오버는
제목, diff 알고리즘의 용도, 현재 선택값의 의미를 포함합니다.

예:

> Diff 알고리즘 · Histogram  
> Git이 변경 구간을 나누는 방식을 정합니다. Histogram은 빈도가 낮은
> 줄을 기준으로 삼아 반복이 많은 코드의 변경 경계를 찾습니다.

각 선택값 설명은 다음 문구를 사용합니다.

| 선택값 | 설명 |
|---|---|
| Git setting | Git 설정에 지정된 알고리즘을 사용합니다. 설정이 없으면 Git의 기본 동작을 따릅니다. |
| Myers | 일반적인 소스 변경을 빠르게 비교하는 Git의 기본 알고리즘입니다. |
| Minimal | 계산을 더 수행해 가능한 한 작은 변경 결과를 찾습니다. 큰 파일에서는 느릴 수 있습니다. |
| Patience | 고유한 줄을 기준으로 삼아 이동하거나 재구성한 코드의 경계를 읽기 쉽게 만듭니다. |
| Histogram | 빈도가 낮은 줄을 기준으로 삼아 반복이 많은 코드의 변경 경계를 찾습니다. |

메뉴 항목은 기존 이름과 체크 표시를 유지합니다. 호버 팝오버는 메뉴를
열지 않으며 포인터 이동을 막지 않습니다.

## 표시할 수 없는 상태

`FullDiffUnavailablePanel`을 하나 만들고 Hunk·Inline·Split의 빈 변경
상태와 File 내용 제한 상태가 함께 사용합니다.

패널은 다음 순서로 정보를 보여줍니다.

1. 파일 경로
2. 파일 상태와 변경 통계: 예 `M · +12 −4`
3. 속성 칩: 예 `UTF-8`, `Binary`, `Unsupported encoding`,
   `10 MiB 초과`, `100,000줄 초과`
4. 표시하지 못하는 이유
5. 적용 가능한 경우 현재 알고리즘과 공백 무시 상태
6. Git 조회 오류인 경우 `다시 시도` 버튼

### 사유별 문구

| 상태 | 안내 |
|---|---|
| 현재 옵션에서 Hunk 없음 | `현재 옵션으로 표시할 변경이 없습니다.` |
| Binary | `바이너리 파일이라 텍스트 diff를 표시할 수 없습니다.` |
| Unsupported encoding | `UTF-8로 해석할 수 없는 파일이라 텍스트 diff를 표시할 수 없습니다.` |
| 10 MiB 초과 | `파일이 10 MiB 제한을 초과해 내용을 표시하지 않습니다.` |
| 100,000줄 초과 | `파일이 100,000줄 제한을 초과해 내용을 표시하지 않습니다.` |
| Git 조회 실패 | `Git에서 이 파일의 변경 내용을 읽지 못했습니다.` 뒤에 오류 세부 정보 |

`FileContentKind.tooLarge`만으로는 바이트 제한과 줄 제한을 구분할 수
없습니다. `FileDocument`에 제한 사유를 추가하고
`FileDocument.fromBytes()`에서 분류할 때 확정합니다. 파일을
10 MiB보다 한 바이트 더 읽어 제한을 판정한 경우 실제 크기처럼
표시하지 않고 `10 MiB 초과`로 표시합니다.

빈 Hunk의 사유는 `DiffDocument.hunks.isEmpty`와 현재 알고리즘·공백
무시 설정에서 얻습니다. 파일 내용 상태와 Git 오류는 섞지 않습니다.

## History 목록과 오른쪽 diff

### 화면 구성

History 콘텐츠를 다음 두 영역으로 나눕니다.

- 왼쪽: 파일 History 목록
- 오른쪽: 선택한 커밋과 첫 번째 부모 사이의 해당 파일 diff

콘텐츠 너비가 760픽셀 이상이면 History 목록 너비는 280픽셀입니다.
그보다 좁으면 전체 너비의 35%를 사용하되 180~240픽셀 안에서
제한합니다. 두 영역 사이에는 기존 `fullDiffDivider` 1픽셀 선을
사용합니다.

오른쪽 영역은 현재 선택한 `Hunk`, `Inline`, `Split` 방식을 그대로
사용합니다. 알고리즘, 공백 무시, 줄바꿈도 일반 Diff와 같습니다.
History에서도 상단 표시 방식 버튼을 계속 사용할 수 있습니다.

### 첫 표시

History를 열면 왼쪽에 현재 파일의 변경 이력을 표시합니다. 현재
커밋이 목록에 있으면 해당 행을 선택 상태로 두고 오른쪽에는 이미 읽은
현재 파일 diff를 표시합니다. 목록에 현재 커밋이 없으면 첫 행을
자동으로 확정하지 않으며 오른쪽은 현재 파일 diff를 유지합니다.

### 항목 선택

마우스 클릭이나 포커스된 행의 `Enter`로 항목을 확정합니다.

1. History 목록과 원래 조회 경로를 유지합니다.
2. 선택한 History 커밋과 첫 번째 부모를 선택합니다.
3. 당시 경로나 이전 경로가 일치하는 `GitFileChange`를 찾습니다.
4. 파일 정보, patch와 파일 내용을 기존 캐시에서 읽거나 새로
   요청합니다.
5. 오른쪽 diff를 갱신합니다.
6. 주변 커밋과 변경 파일 목록도 확정된 시점에 맞춰 갱신합니다.

History 선택 때문에 `state.history`를 비우거나 같은 목록을 다시
조회하지 않습니다. 사용자가 다른 파일, 다른 커밋 또는 부모를
History 밖에서 선택한 경우에만 History 문맥을 버립니다.

### 비동기 안전성

History 항목을 빠르게 연속해서 선택할 수 있으므로 기존
`selectionGeneration`과 요청 번호를 그대로 적용합니다. 마지막으로
확정한 커밋·부모·파일과 일치하지 않는 파일 목록, patch와 파일 내용은
화면에 반영하지 않습니다.

선택한 History 항목에서 파일을 찾지 못하거나 Git 조회가 실패하면
목록은 유지하고 오른쪽 영역에 오류와 `다시 시도`를 표시합니다.

## 구성 요소 변경

### `GlobalFileBar`

- `VoidCallback onBack` 추가
- 왼쪽 뒤로 가기 버튼 추가
- 파일 경로 글자 크기 11로 변경

### `GlobalDiffToolbar`

- 알고리즘 버튼에 현재 선택값 표시
- 현재 알고리즘 설명 팝오버 추가
- 좁은 화면용 선택값 전용 이름 추가

### `FullDiffSessionState`

- 확정한 History 항목 보관
- History 목록을 조회한 원래 커밋·경로 문맥 보관
- 파일 표시 제한의 정확한 사유 전달

### `FullDiffSessionController`

- 일반 선택과 History 상세 선택을 구분
- History 상세 선택에서는 이미 읽은 목록과 원래 조회 문맥 유지
- History 상세 재시도 경로 제공
- 알고리즘과 공백 무시 변경 시 오른쪽 상세 diff 재사용

### `FullHistoryView`

- 목록만 그리는 책임 유지
- 선택 행 접근성 상태와 `Enter` 확정 유지
- 작은 글자 크기 적용

### `FullHistoryWorkspace`

- History 목록과 오른쪽 diff 배치
- 반응형 목록 너비 적용
- 상세 로딩·빈 상태·오류 표시

### `FullDiffUnavailablePanel`

- 파일명, 속성, 변경 통계와 사유 표시
- 빈 변경, 바이너리, 인코딩과 크기 제한 공통 처리
- 오류 재시도 동작 제공

## 접근성

- 뒤로 가기 버튼은 버튼 역할과 `타임라인으로 돌아가기` 이름을
  제공합니다.
- 알고리즘 버튼의 접근성 이름에는 현재 선택값을 포함합니다.
- 설명 팝오버의 본문은 알고리즘 버튼의 추가 설명으로도 노출합니다.
- 표시 불가 안내는 파일 경로, 속성과 사유 순서로 읽힙니다.
- History 행은 포커스 이동만으로 확정되지 않습니다. 클릭이나
  `Enter`로만 오른쪽 diff를 바꿉니다.
- 선택한 History 행은 기존 시각 언어를 유지하면서 선택 상태를
  의미 정보로 제공합니다.

## 테스트

### 단위·위젯 테스트

- 커밋·파일 목록, 파일 경로, diff 코드, 줄 번호와 Hunk 제목의 정확한
  글자 크기
- 뒤로 가기 버튼의 위치, 접근성 이름과 `Navigator.maybePop()` 호출
- 코드 선택 영역과 History 목록에 포커스가 있을 때 `Esc`
