Pull과 Push — 기준 브랜치의 upstream 동기화

묻기 전에 답해 둔다. 기준 브랜치가 upstream과 어긋나 있으면 그 사실이 이미 재어져 있고, 버튼은 ‘무엇을 하겠다’가 아니라 ‘하면 어떻게 되는지’를 입고 있다. 동기화되어 있을 때는 아무것도 말하지 않는다 — 침묵이 곧 ‘다 맞다’는 대답이다.

자리 툴바 · 기준 브랜치 곁

이 상태는 기준 브랜치의 속성이므로 기준 브랜치 선택기 바로 오른쪽에 선다. 사이드바 스트립은 커서가 짚은 ref의 것이고 상태바는 부고란이다 — 대표 기능은 브랜치 이름 옆에서 그 브랜치를 말해야 한다. 창이 좁아지면 장식(문구·키캡)이 먼저 물러나고 캡슐은 남는다.

동기화 캡슐. 두 동사가 각자의 판정 색을 입는다 — 초록: 그대로 됨 · 주황: 받아 얹기(--rebase)를 거치면 됨 · 빨강: 충돌. 한 자리만 예외다: 충돌 상태의 두 번째 칸은 판정이 아니라 해결 화면으로 나가는 문이라, 그 낱말만 초록을 입고 해결하기라고 적는다 — 막힌 사실은 빨강이 말하고, 나가는 길은 초록이 말한다. 개수는 판정에 딸린 사실이라 문 위에서도 빨강으로 남는다. 캡슐이 두 줄로 서는 배치는 docs/toolbar-selectors-mockup.html이 잇는다.

상태 여섯 한 사실, 두 문

판정의 재료는 upstream 대비 ahead(로컬에만 있는 커밋)와 behind(원격에만 있는 커밋) 둘뿐이고, 어긋났을 때(ahead>0 ∧ behind>0)의 물음은 하나로 수렴한다 — 로컬 커밋이 원격 끝 위에 깨끗이 얹히는가. 숨은 worktree에서 한 번 재연해 보면(브랜치 diff의 재배치 미리보기와 같은 부품) Pull과 Push 두 버튼의 답이 동시에 나온다.

upstream 없음 ↑ 처음 Push tooltip: origin에 main을 만들고 추적을 연결합니다 (push -u)

재는 동안은 판정 색 없이 숫자만 희미하게 서고, 동사 자리에는 도는 것 하나가 선다 — 무엇을 하게 될지가 아직 답이 아니라서다. 판정은 fetch가 끝날 때, 그리고 두 끝(tip) 중 하나가 움직일 때마다 다시 잰다.

누르면 확인 한 번, 실행 한 번

Pull(빨리감기)은 로컬만 움직이니 확인 없이 바로 실행한다. Push는 원격을 움직이므로 확인을 거치는데, 그 확인창은 저장소가 밖에서 바뀌었을 때와 같은 형식으로 오갈 커밋의 목록을 보여 준다 — 무엇이 올라가는지 읽은 뒤에 답하는 순서다. 빨간 버튼은 실행이 아니라 충돌 해결 흐름으로 들어가는 문이다.

받아 얹고 Push

받아 얹고 Push — 두 걸음이 블록 둘로 서고, 물음은 맨 끝이다. 확인 한 번에 두 걸음이 이어서 실행되고, 받아 얹기가 예상과 달리 충돌하면 거기서 멈추고 충돌 해결 흐름이 열린다.

충돌이면 해결 흐름으로

  • 빨간 버튼을 누르면 브랜치 diff의 충돌 해결 흐름이 그대로 열린다: 숨은 worktree의 재연이 충돌 지점에 멈춰 있고, 충돌 파일 목록에서 파일을 골라 고치고, 다 풀리면 이어서 진행한다 — 재배치 미리보기가 쓰는 그 화면, 그 부품이다.
  • 해결을 마치면 캡슐이 주황으로 돌아온다: 받아 얹기는 이미 실현됐고 남은 것은 Push뿐이니, Push 확인창에는 올라갈 커밋만 선다.
  • 중간에 그만두면 worktree만 버려지고 로컬 브랜치는 그대로다 — 반쯤 얹힌 역사가 남지 않는다.

실행 방식 — 체크아웃을 옮기지 않는다

  • 기준 브랜치가 체크아웃되어 있지 않을 때: Pull(빨리감기)은 git fetch origin main:main으로 ref만 전진시키고, 받아 얹기는 브랜치 diff 적용과 같은 숨은 worktree에서 재연을 실현한 뒤 ref만 옮긴다. 작업 트리는 더럽든 말든 상관없다 — 이 앱의 기존 약속 그대로.
  • 체크아웃되어 있을 때: 작업 트리를 실제로 움직여야 하므로, 트리가 더럽고 받을 내용과 겹치면 실행을 거절하고 이유를 말한다. 몰래 stash하지 않는다.
  • 재연(dry-run)은 기준 브랜치 하나에 대해서만, 어긋났을 때만, 한 번에 하나만 돈다. (로컬 tip, 원격 tip) 쌍이 같으면 다시 재지 않는다. fetch가 끝나면 자동으로 잰다.

계약

  • 동기화 상태에서 캡슐은 동사를 보이지 않는다 — 점 하나뿐.
  • ahead만 있으면 Push 하나, behind만 있으면 Pull 하나. 개수는 항상 판정 색과 함께.
  • 어긋나면 재연이 끝날 때까지 숫자는 무채색이고, 끝나면 두 버튼이 같은 판정을 입는다.
  • Push는 항상 확인을 거치고, 확인창에는 올라갈 커밋의 목록이 저장소 변경 알림과 같은 형식으로 서고, 원격 ref가 어디서 어디로 움직이는지 해시가 적힌다.
  • 받아 얹고 Push는 확인 한 번에 두 걸음이 이어지고, 확인창에 두 걸음이 블록 둘로 선다.
  • 빨간 버튼은 충돌 해결 흐름을 연다. 해결을 마치면 남은 걸음(Push)만 남고, 그만두면 로컬 브랜치에 아무 자국도 남지 않는다.
  • Pull(빨리감기)은 확인 없이 즉시. 완료는 상태바가 아니라 타임라인 자체가 말한다 — 행이 늘어난다.
  • tooltip에는 언제 잰 판정인지가 적힌다.

결정 확정

  1. 주황 Push의 한 번 누름 — 받아 얹기와 Push를 확인 한 번으로 묶어 실행. ✓
  2. 재연 자동 실행 — fetch 후 어긋남이 보이면 자동으로 잰다. ✓
  3. 충돌의 다음 단계 — 목록에서 멈추지 않고 브랜치 diff의 충돌 해결 흐름으로 연결. ✓
  4. 표기 — 버튼 동사는 Pull / Push. 설명 산문에서는 ‘받아 얹기(--rebase)’ 같은 우리말이 흐름을 설명한다. ✓
