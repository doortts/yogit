# 미리보기 파일 선택 스크롤 설계

## 목표

타임라인 미리보기에서 `⌘↑/↓`로 변경 파일을 이동할 때 선택한 파일 행이
파일 목록 화면 밖으로 사라지지 않게 한다.

## 현재 동작과 원인

`_stepPreviewFile`은 다음 파일 경로를 정한 뒤 `_selectPreviewFile`로 선택만
바꾼다. `_selectPreviewFile`은 새 diff를 맨 위에서 보여주기 위해
`_previewDiffScrollController`만 조정한다. 파일 목록을 제어하는
`_previewFilesScrollController`에는 아무 동작도 하지 않으므로 선택 행이
현재 화면 아래나 위로 벗어날 수 있다.

## 상호작용

- 선택 행이 이미 보이면 파일 목록을 움직이지 않는다.
- 아래로 이동한 선택 행이 화면 아래로 벗어나면 목록을 필요한 만큼만 내려서
  행의 아래쪽을 화면에 맞춘다.
- 위로 이동한 선택 행이 화면 위로 벗어나면 목록을 필요한 만큼만 올려서 행의
  위쪽을 화면에 맞춘다.
- 키를 한 번 누르면 기존 타임라인 이동과 같은 짧은 애니메이션을 사용한다.
- 키를 길게 눌러 반복 입력이 들어오면 즉시 이동해 애니메이션이 입력보다
  뒤처지지 않게 한다.
- 목록의 처음과 끝에서는 기존처럼 선택을 더 이동하지 않으며 스크롤도
  추가로 움직이지 않는다.
- 마우스로 파일을 선택할 때는 파일 목록의 현재 스크롤 위치를 유지한다.
- 파일을 바꾸면 코드 diff를 맨 위로 돌리는 기존 동작은 유지한다.

## 구현 구조

선택된 미리보기 파일 행 하나에만 `GlobalKey`를 붙인다. 모든 행의 키를
보관하지 않아 파일 수에 따라 상태가 늘어나지 않게 한다.

`_stepPreviewFile`은 이동 방향과 입력이 반복 입력인지
`_selectPreviewFile`에 전달한다. 선택 상태를 반영한 다음 프레임에서 선택 행의
`BuildContext`를 가져와 `Scrollable.ensureVisible`을 호출한다.

- 아래로 이동할 때는
  `ScrollPositionAlignmentPolicy.keepVisibleAtEnd`를 사용한다.
- 위로 이동할 때는
  `ScrollPositionAlignmentPolicy.keepVisibleAtStart`를 사용한다.
- 일반 입력은 100ms 동안 움직이고 반복 입력은 `Duration.zero`로 즉시
  이동한다.
- 마우스 클릭은 이동 방향을 전달하지 않으므로 선택 행을 화면에 맞추는 동작을
  실행하지 않는다.

선택 행의 문맥을 아직 얻을 수 없거나 위젯이 해제된 경우에는 스크롤을 건너뛴다.
다음 입력에서 다시 현재 선택 행을 기준으로 판단할 수 있으므로 별도의 재시도나
오류 표시는 두지 않는다.

## 테스트

`test/app_test.dart`에 높이가 제한된 미리보기와 화면을 넘는 파일 목록을 만든다.

1. `⌘↓`를 반복해 선택 행이 원래 화면 아래에 놓일 지점까지 이동한다.
2. 파일 목록의 스크롤 위치가 증가하고 선택 행 전체가 목록 화면 안에 있는지
   확인한다.
3. `⌘↑`를 반복해 위로 돌아가며 선택 행이 계속 보이고 스크롤 위치도
   줄어드는지 확인한다.
4. 이미 보이는 행 사이를 이동할 때 스크롤 위치가 바뀌지 않는지 확인한다.
5. 마우스로 보이는 파일을 선택하면 파일 목록 위치는 유지되고 코드 diff만
   맨 위로 돌아가는지 기존 독립 스크롤 테스트와 함께 확인한다.

기존 미리보기 파일 이동, 독립 스크롤, 페이지 스크롤 테스트도 함께 실행해
서로 영향을 주지 않는지 확인한다.

## 제외 범위

- 일반 `↑/↓`가 커밋을 이동하는 타임라인 단축키는 바꾸지 않는다.
- 미리보기의 커밋 정보와 파일 목록을 하나의 스크롤 영역으로 두는 구조는
  유지한다.
- Full Diff 화면의 파일 목록 동작은 이번 변경에 포함하지 않는다.
