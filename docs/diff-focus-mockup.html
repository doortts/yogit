지금 규칙: 키보드를 쥔 pane의 선택만 색을 갖는다. 그런데 diff에는 "선택된 행"이 없어서 포커스가 와도 화면이 그대로다. 아래 넷 중 하나로 그 순간을 말한다. 각 안은 왼쪽 = 포커스 있음 / 오른쪽 = 없음.

비교

1안 실선가장 눈에 잘 띄고 pane 단위로 일관된다. 새 요소를 하나 들이는 값을 치른다.
2안 현재 막대이미 있는 요소를 쓰고, 화살표가 움직일 대상까지 같이 말한다. 변화가 3px이라 조용한 편.
3안 hunk 커서앱의 "선택된 행" 문법을 그대로 물려받는다. 화살표=hunk 이동과 가장 정확히 맞물린다.
4안 카운터가장 작다. 툴바를 안 보고 있으면 놓친다.
섞어도 된다1안(어느 칸인지) + 3안(그 칸의 어디인지)은 서로 다른 것을 말하니 함께 써도 시끄럽지 않다.
