# 브랜치 diff, 체리픽, Monaco Editor 설계

## 목표

Yogit의 기존 타임라인을 중심으로 다음 기능을 추가한다.

- 기준 브랜치와 다른 로컬 또는 원격 브랜치를 비교한다.
- 타임라인에서 두 브랜치의 공통 기반과 서로 다른 커밋을 보여준다.
- 미리보기에서 두 브랜치 끝 상태 사이의 전체 파일 diff를 보여준다.
- 병합 충돌 파일과 리베이스 중 처음 충돌하는 커밋·파일을 실제 Git
  동작에 가깝게 검사한다.
- 다른 브랜치의 커밋 하나를 현재 체크아웃한 브랜치로 체리픽한다.
- 체리픽 충돌을 앱에서 이어서 해결하거나 중단할 수 있게 한다.
- 전체 diff와 체리픽 충돌 화면에서 내장 에디터 또는 외부 에디터를
  선택해 파일을 연다.
- 로컬 브랜치와 같은 이름의 `origin` 브랜치 사이에 커밋 차이가 있을
  때만 좌측 브랜치 행에 방향별 숫자를 표시한다.

## 범위

### 포함

- `기준 브랜치` 옆의 검색 가능한 `브랜치 diff` 선택기
- 로컬 브랜치와 원격 브랜치 비교
- 두 브랜치의 직접 부모 관계, 공통 기반, 고유 커밋
- 두 브랜치 끝 상태 사이의 파일 diff
- 병합 충돌 검사
- 임시 작업 공간에서 실행하는 정확한 리베이스 검사
- 커밋 하나씩 체리픽
- 커밋 메뉴와 현재 브랜치 행으로 끄는 동작
- 체리픽 충돌 파일 목록, 계속, 중단
- 내장 에디터와 기존 외부 에디터 선택
- 저장과 동시에 해결된 충돌 파일 스테이징
- 저장소를 열 때와 5분마다 실행하는 `origin` fetch
- `origin/<로컬 브랜치>`와의 `↑N`, `↓N` 표시

### 제외

- 여러 커밋 동시 선택과 일괄 체리픽
- 체크아웃하지 않은 로컬 브랜치로 체리픽
- 태그를 브랜치 비교 대상으로 사용
- 비교 결과나 비교 브랜치를 설정에 저장
- Monaco의 LSP 연결, 다중 탭, 확장 기능
- 과거 커밋 내용을 현재 작업 트리에 덮어쓰기
- 병합이나 리베이스를 실제 브랜치에 실행하는 기능
- 모든 브랜치 쌍의 비교 결과를 미리 계산하는 기능

## 확정한 제품 결정

- 충돌 검사는 빠른 추정이 아니라 실제 Git 동작을 이용한다.
- 체리픽 대상은 현재 체크아웃한 브랜치로 제한한다.
- 체리픽은 커밋 하나씩 실행한다.
- 브랜치 차이는 `↑N`, `↓N`으로 나누고 서로 다른 색을 사용한다.
- 브랜치 비교 대상은 로컬·원격 브랜치다.
- 브랜치 비교는 별도 화면이나 모달이 아니라 기존 타임라인을 바꾼다.
- 미리보기는 비교 중에 두 브랜치 전체의 파일 diff를 유지한다.
- 체리픽 충돌은 앱에서 계속하거나 중단할 수 있다.
- `편집기로 열기`는 항상 내장·외부 편집기 선택 메뉴를 연다.
- Monaco 파일은 앱에 포함해 오프라인에서도 쓸 수 있게 한다.
- 현재 작업 트리 파일은 수정할 수 있고 과거 커밋 파일은 읽기
  전용으로 연다.
- Monaco에서 해결한 충돌 파일을 저장하면 해당 파일을 스테이징한다.
- `origin`은 저장소를 열 때와 5분마다 자동으로 fetch한다.

## 전체 구조

기존 `GitRepository`에 필요한 Git 동작을 직접 추가한다. 하나뿐인
구현을 위한 새 저장소 인터페이스나 Git 서비스 계층은 만들지 않는다.

`TimelineScreen`은 다음 세션 상태를 가진다.

- 선택한 비교 브랜치
- 현재 브랜치 비교 결과와 로딩·오류 상태
- 자동 fetch 타이머와 진행 상태
- 체리픽 진행·충돌 상태

비교 브랜치를 선택하지 않았을 때는 기존 커밋 목록, 그래프, 미리보기
동작을 그대로 사용한다. 비교 브랜치를 선택하면 같은 화면이 비교
전용 데이터로 바뀐다. 비교 선택을 지우면 기존 데이터를 다시
표시하며 이미 읽은 일반 타임라인 페이지는 버리지 않는다.

Monaco는 `flutter_monaco` 패키지로 넣는다. 패키지가 제공하는 macOS
WKWebView 연결과 앱 내 Monaco 자산을 사용한다. 직접 JavaScript 통신
계층이나 Monaco 자산 추출기를 만들지 않는다.

## 데이터 모델

`RepoRefs`에 다음 값을 추가한다.

- `aheadBehind`: 로컬 브랜치 이름에서 `ahead`, `behind` 수로 가는 맵

자동 fetch 오류는 ref 데이터가 아니라 `TimelineScreen`의 세션
상태로 둔다. 실패한 fetch가 기존 `RepoRefs`를 오염시키지 않게 한다.

비교 결과는 다음 값을 한 묶음으로 전달한다.

- 기준 브랜치 이름과 끝 SHA
- 비교 브랜치 이름과 끝 SHA
- 두 끝 커밋의 첫 번째 부모 SHA와 동일 여부
- Git이 찾은 모든 공통 기반 SHA
- 타임라인에 표시할 비교 커밋과 `baseOnly`, `compareOnly`,
  `commonBoundary` 구분
- 기준 끝에서 비교 끝으로 계산한 파일 변경 목록
- 병합 충돌 파일 목록
- 리베이스 가능 여부
- 리베이스가 멈춘 첫 커밋 SHA와 충돌 파일 목록

공통 기반이 여러 개면 하나로 축약하지 않는다. 상태 영역에는 개수를
표시하고 타임라인에는 Git이 돌려준 공통 경계 커밋을 모두 표시한다.

비교 결과는 현재 선택에만 속한다. 다른 브랜치를 고르거나 저장소를
바꾸면 이전 비동기 결과는 화면에 반영하지 않는다.

## 원격 갱신과 브랜치 차이

저장소를 열면 `origin`이 있는지 확인하고 자동 fetch를 한 번
실행한다. 이후 `TimelineScreen`이 살아 있는 동안 5분마다 다시
실행한다.

- 명령은 터미널 입력을 요구하지 않는 방식으로 실행한다.
- 앞선 fetch가 끝나지 않았으면 다음 차례는 건너뛴다.
- 체리픽이 진행 중이면 fetch를 미룬다.
- 실패해도 기존 ref와 차이 숫자를 유지한다.
- 같은 오류 창을 반복하지 않고 상태 영역에 짧게 표시한다.
- 수동으로 다시 시도할 수 있는 새로고침 동작을 제공한다.

fetch가 끝나면 refs와 브랜치 차이를 다시 읽는다. 로컬 브랜치
`name`과 `refs/remotes/origin/name`이 모두 있을 때 다음 의미로
계산한다.

```text
git rev-list --left-right --count name...refs/remotes/origin/name
```

- 왼쪽 수: 로컬에만 있는 커밋, `↑N`
- 오른쪽 수: `origin`에만 있는 커밋, `↓N`

0인 방향은 표시하지 않는다. 두 값이 모두 0이거나 같은 이름의
`origin` 브랜치가 없으면 아무 표시도 하지 않는다. `↑`는 초록 계열,
`↓`는 주황 계열을 사용한다. 화살표와 숫자도 함께 보여 색만으로
의미를 전달하지 않는다.

## 브랜치 diff 선택기

기존 툴바의 `기준 브랜치` 오른쪽에 `브랜치 diff` 항목을 붙인다.
항목을 누르면 검색 입력란이 있는 메뉴가 열린다.

- 로컬과 원격을 구분해 표시한다.
- 현재 기준 브랜치와 완전히 같은 ref는 제외한다.
- `main`과 `origin/main`은 서로 다른 ref이므로 비교할 수 있다.
- 태그는 표시하지 않는다.
- 전체 ref 이름을 검색한다.
- 선택한 비교 브랜치에는 체크 표시를 한다.
- 선택값을 지우는 동작을 제공한다.

refs를 읽는 중이면 선택기를 비활성화한다. refs를 읽지 못하면 기존
타임라인은 유지하고 선택기에 실패 상태를 표시한다.

## 비교 데이터 읽기

비교 브랜치를 고르면 다음 결과를 현재 ref 값에서 읽는다.

### 공통 기반과 커밋

`git merge-base --all`로 모든 공통 기반을 찾는다. 두 끝 커밋의 첫
번째 부모도 읽어 둘 다 존재하고 SHA가 같을 때만 직접 부모가 같다고
표시한다. 루트 커밋처럼 부모가 없으면 `부모 없음`으로 표시한다.

고유 커밋은 Git의 대칭 차집합과 위상 정렬을 사용한다. 각 커밋은 기준
브랜치 쪽, 비교 브랜치 쪽, 공통 경계 가운데 하나로 표시한다.
타임라인은 두 브랜치의 고유 커밋과 공통 경계만 받는다. 관계없는
브랜치의 커밋과 레인은 만들지 않는다.

그래프에는 두 브랜치 레인만 사용한다. `BRANCH / TAG` 영역과 행의
보조 표시에 `main만`, `feature만`, `공통`을 함께 보여준다.

### 전체 파일 diff

파일 diff 방향은 기준 브랜치 끝에서 비교 브랜치 끝으로 고정한다.
공통 기반부터 비교 브랜치까지의 변경만 보는 세 점 diff가 아니다.

```text
git diff <base-tip> <compare-tip>
```

따라서 미리보기의 추가·삭제 줄은 두 브랜치 끝 상태를 직접 비교한
결과다. 기존 파일 상태·통계·diff 파서를 재사용하고 명령에는 현재
안전한 diff 인수를 그대로 적용한다.

### 병합 충돌

다음 명령으로 작업 트리와 인덱스를 건드리지 않고 실제 병합 방식에
가까운 결과를 읽는다.

```text
git merge-tree --write-tree --name-only -z <base> <compare>
```

- 종료 코드 0: 충돌 없음
- 종료 코드 1: 출력에서 충돌 파일을 읽음
- 그 밖의 종료 코드: 검사를 완료하지 못한 오류

충돌 파일은 중복을 제거하되 Git의 순서를 유지한다.

### 리베이스 충돌

비교 브랜치의 고유 커밋을 기준 브랜치 위에 올리는 방향으로
검사한다. 실제 브랜치와 현재 작업 트리는 바꾸지 않는다.

1. 앱 전용 임시 디렉터리를 만든다.
2. 비교 브랜치 끝을 detached HEAD로 하는 임시 Git worktree를 만든다.
3. Git 훅, `rerere`, 자동 스태시, `--update-refs`를 끈 상태로
   기준 브랜치 위에 rebase한다.
4. 성공하면 충돌 없음으로 기록한다.
5. 실패하면 `REBASE_HEAD`에서 처음 멈춘 커밋을 읽고 unmerged index
   항목에서 충돌 파일을 읽는다.
6. 진행 중인 rebase를 중단하고 worktree를 제거한다.

모든 정리는 `finally` 경로에서 실행한다. 브랜치 선택이 바뀌어 결과가
필요 없어져도 실행 중인 검사 정리는 끝까지 수행한다. 앱이 비정상
종료해 남긴 앱 전용 임시 worktree는 다음 실행 때 앱이 만든 경로인지
확인한 뒤 정리한다. 사용자 worktree에는 손대지 않는다.

리베이스 결과는 커밋·파일 diff보다 늦게 도착할 수 있다. 타임라인과
파일 diff를 먼저 보여주고 상태 영역의 리베이스 항목만 `검사 중`으로
둔다.

## 비교 모드 화면

비교 모드에서도 기존 타임라인 화면을 유지한다.

- 좌측 ref 트리는 그대로 보인다.
- 툴바에는 기준 브랜치와 비교 브랜치가 나란히 보인다.
- 타임라인에는 양쪽 고유 커밋과 공통 경계만 보인다.
- 커밋 행과 그래프는 어느 쪽 커밋인지 함께 표시한다.
- 미리보기는 선택한 커밋과 관계없이 두 브랜치 전체 파일 diff를
  유지한다.
- 파일 목록에서 파일을 고르면 아래에 해당 파일 diff를 보여준다.
- 아래 상태 영역에는 직접 부모 동일 여부, 공통 기반, 양쪽 고유
  커밋 수, 병합 결과, 리베이스 결과를 표시한다.

비교 모드의 커밋 선택과 키보드 이동은 기존 타임라인 동작을
재사용한다. 비교 브랜치를 해제하면 선택 가능한 가장 가까운 기존
타임라인 행으로 돌아간다.

## 체리픽 시작

체리픽은 다음 두 경로가 같은 동작을 호출한다.

- 커밋 메뉴의 `현재 브랜치로 체리픽`
- 커밋을 좌측의 현재 체크아웃한 브랜치 행으로 끌기

다른 로컬 브랜치, 원격 브랜치, 태그는 놓기 대상이 되지 않는다.
작업 트리 행, 공통 경계 행, 이미 현재 HEAD의 조상인 커밋은 시작할 수
없다.

시작 전에 다음 조건을 검사한다.

- detached HEAD가 아님
- 현재 브랜치가 존재함
- 다른 체리픽·리베이스·병합이 진행 중이지 않음
- 작업 트리와 index가 깨끗함
- 선택한 SHA가 커밋으로 확인됨

확인 창에는 커밋 SHA, 제목, 대상 브랜치를 표시한다. 승인하면 다음
명령을 현재 작업 트리에서 실행한다.

```text
git cherry-pick <sha>
```

성공하면 refs, 일반 타임라인, 비교 결과, 브랜치 차이 숫자를 다시
읽고 새 HEAD를 선택한다.

선택한 변경이 이미 적용되어 빈 체리픽이 되면 빈 커밋을 만들지
않는다. 체리픽 상태를 안전하게 끝내고 `적용할 변경이 없습니다`라고
알린다.

## 체리픽 충돌

체리픽이 충돌로 멈추면 `CHERRY_PICK_HEAD`와 unmerged index 항목에서
진행 상태와 충돌 파일을 읽는다. 앱을 다시 열어도 같은 정보로 충돌
화면을 복원한다.

화면은 세 동작을 제공한다.

### 편집기로 열기

충돌 파일을 고른 뒤 `편집기로 열기`를 누르면 다음 메뉴를 연다.

- `내장 에디터`
- `외부 에디터`

내장 에디터가 지원하지 않는 파일이면 해당 항목을 비활성화하고
이유를 보여준다. 외부 편집기는 기존 `ExternalEditorService`를 그대로
사용한다.

### 계속

unmerged index 항목이 하나도 없을 때만 활성화한다. 실행 시 Git이
편집기 입력을 기다리지 않도록 한 뒤 다음 명령을 실행한다.

```text
git cherry-pick --continue
```

성공하면 일반 성공 흐름과 같이 화면을 다시 읽는다. 명령이 실패하면
진행 상태와 파일 목록을 다시 읽어 사용자가 이어서 처리할 수 있게
한다.

### 체리픽 중단

확인을 받은 뒤 다음 명령으로 시작 전 상태로 복구한다.

```text
git cherry-pick --abort
```

성공하면 충돌 화면을 닫고 타임라인과 미리보기를 다시 읽는다.

## Monaco Editor

`flutter_monaco`가 제공하는 Monaco 자산을 앱에 포함한다. 편집기는
화면을 열 때 하나만 만들고 닫을 때 폐기한다. 네트워크 연결, 외부
페이지 이동, LSP 연결은 허용하지 않는다.

### 편집기로 열기 메뉴

전체 diff와 체리픽 충돌 화면의 `편집기로 열기`는 모두 같은 선택
메뉴를 사용한다. 선택을 기억하지 않고 매번 다음 중 하나를 고르게
한다.

- 내장 에디터
- 외부 에디터

### 수정 가능한 파일

현재 작업 트리에 있는 일반 텍스트 파일은 수정할 수 있다.

- 기존 `ExternalEditorService`의 저장소 경계 검사를 공통 함수로
  옮겨 내장·외부 편집기가 함께 사용한다.
- 심볼릭 링크를 해석한 실제 경로가 저장소 밖이면 열지 않는다.
- 일반 파일이 아니면 열지 않는다.
- UTF-8로 읽을 수 없는 파일과 바이너리는 내장 편집기를 비활성화한다.
- 원래 UTF-8 BOM과 CRLF/LF 줄바꿈 방식을 기억해 저장할 때 유지한다.
- `Command-S`와 화면의 저장 동작은 같은 저장 함수를 호출한다.

체리픽 충돌 파일을 저장하면 남은 충돌 표시를 확인한다. Git이
`leftover conflict marker`로 판단하는 줄이 없을 때만 해당 경로를
다음 명령으로 스테이징한다.

```text
git add -- <path>
```

충돌 표시가 남아 있으면 파일 내용은 저장하되 해결된 것으로 표시하지
않는다. 다른 파일은 함께 스테이징하지 않는다.

삭제·수정 충돌처럼 작업 트리에 일반 파일이 없는 경우에는 내장
편집기를 열지 않는다. 이번 범위에서 ours/theirs 자동 선택 동작은
추가하지 않는다.

### 읽기 전용 파일

과거 커밋의 파일은 기존 blob 읽기 경로로 내용을 가져와 Monaco에서
읽기 전용으로 연다. 저장 동작을 표시하지 않는다. 과거 내용을 현재
작업 트리로 쓰는 동작은 제공하지 않는다.

## 오류와 취소

- fetch 실패: 기존 refs를 유지하고 상태 영역에 짧게 표시
- 비교 ref가 사라짐: 비교 모드를 끝내고 일반 타임라인 유지
- 공통 기반 없음: 서로 관련 없는 기록임을 표시하고 커밋·파일 diff는
  가능한 범위에서 보여줌
- 병합 검사 실패: 병합 상태만 실패로 표시
- 리베이스 검사 실패: 리베이스 상태만 실패로 표시하고 임시 worktree
  정리
- Monaco 준비 실패: 오류를 보여주고 외부 편집기를 선택할 수 있게 함
- Monaco 저장 실패: 스테이징하지 않고 편집 내용을 화면에 유지
- 외부 편집기 실패: 기존 편집기 오류 표시 재사용
- 체리픽 계속·중단 실패: 진행 상태를 다시 읽고 사용자가 재시도할 수
  있게 함

저장소나 비교 선택이 바뀌면 요청 번호를 올려 이전 결과를 버린다.
이 방식은 전체 diff의 기존 비동기 편집기 요청 무효화 흐름을
재사용한다.

## 접근성

- `↑`, `↓`, `main만`, `feature만`, `공통` 텍스트를 함께 써 색에만
  의존하지 않는다.
- 검색 메뉴, 체리픽 메뉴, 충돌 동작은 키보드로 접근할 수 있다.
- 커밋 끌기와 같은 기능을 메뉴에서도 똑같이 제공한다.
- 비교 로딩·실패·충돌 상태는 스크린 리더가 읽을 수 있는 문구를
  제공한다.
- Monaco가 읽기 전용일 때 화면과 접근성 설명에 모두 표시한다.

## 성능과 수명

- 선택한 브랜치 한 쌍만 계산한다.
- 빠른 커밋·파일 결과와 느린 리베이스 검사 결과를 따로 반영한다.
- 같은 ref 끝 SHA 조합의 비교 결과는 현재 세션에서만 재사용한다.
- fetch 뒤 SHA가 바뀌면 해당 비교 결과를 버리고 다시 읽는다.
- Monaco는 실제로 열 때까지 만들지 않는다.
- 자동 fetch, 비교 검사, 체리픽 명령은 같은 저장소에서 서로 충돌하지
  않도록 진행 상태를 확인한다.

## 테스트

### Git 통합 테스트

임시 저장소와 로컬 bare 원격을 사용해 다음을 확인한다.

- 저장소를 열 때 fetch와 5분 주기 중복 방지
- fetch 실패 뒤 기존 refs 유지
- `↑`, `↓`, 0, 같은 이름의 원격 브랜치 없음
- 직접 부모 동일 여부와 여러 공통 기반 처리
- 양쪽 고유 커밋과 공통 경계 순서
- 기준 끝에서 비교 끝으로 계산한 파일 diff
- 충돌 없는 병합과 충돌 파일
- 충돌 없는 리베이스
- 처음 충돌한 리베이스 커밋과 파일
- 리베이스 성공·실패·선택 변경 뒤 임시 worktree 정리
- 체리픽 성공과 새 HEAD
- 더러운 작업 트리에서 체리픽 차단
- 체리픽 충돌, 계속, 중단
- 빈 체리픽 처리
- `CHERRY_PICK_HEAD`에서 진행 상태 복원

### 화면 테스트

- `브랜치 diff` 검색과 로컬·원격 분류
- 같은 기준 ref 제외와 `origin/main` 허용
- 두 브랜치만 남은 커밋과 그래프
- 공통 경계와 양쪽 표시
- 비교 중 미리보기의 전체 파일 diff 유지
- 비교 해제 뒤 일반 타임라인 복원
- `↑`, `↓` 숨김 조건, 숫자, 서로 다른 색
- 메뉴와 끌기로 같은 체리픽 확인 창 열기
- 현재 브랜치 외의 놓기 대상 차단
- 충돌 파일 목록, 계속 활성화 조건, 중단 확인
- `편집기로 열기`의 내장·외부 선택
- Monaco 수정 가능·읽기 전용 표시
- 저장 뒤 해당 충돌 파일만 스테이징
- 남은 충돌 표시가 있을 때 스테이징 차단
- 바이너리, 잘못된 UTF-8, 저장소 밖 경로 차단
- 늦게 끝난 요청이 새 저장소나 새 비교 선택을 바꾸지 않음
