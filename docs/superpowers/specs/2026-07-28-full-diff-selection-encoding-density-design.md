# Full Diff 선택·인코딩·Blame 밀도 개선 설계

## 목적

Full Diff의 파일 탐색과 Blame 읽기 경험을 다음과 같이 다듬는다.

- 파일 목록과 History 목록에 같은 선택·포커스 표현을 사용한다.
- 일반 Full Diff 화면에서 `↑`와 `↓`만으로 파일을 이동한다.
- 인코딩을 읽는 동안 헤더가 좌우로 흔들리지 않게 한다.
- Blame을 일반 소스 파일에 가까운 줄 간격으로 표시한다.

이 문서는 기존 Full Diff 설계에서 정한 Blame 44px 행과 4px 컬러선 기준을
21px 행과 3px 컬러선으로 대체한다. 그 밖의 기존 Full Diff 설계는 유지한다.

## 선택 행 공통 컴포넌트

파일 행과 History 행은 `FullDiffSelectableRowSurface`를 함께 사용한다.
컴포넌트는 선택 상태와 포커스 상태만 표현하며 행의 내용과 입력 처리는 맡지
않는다.

- 선택된 행: `fullDiffSelection` 배경
- 현재 목록에 포커스가 있는 선택 행: `fullDiffAccent` 1px 테두리
- 선택되지 않은 행: 기존 캔버스 배경
- 테두리는 행 안쪽에 그려서 크기나 주변 배치를 바꾸지 않는다.

일반 Diff·File·Blame 화면에서는 파일 목록이 기본 탐색 대상이므로 선택 파일에
항상 포커스 테두리를 표시한다. History 화면에서는 파일 목록과 History 목록
가운데 실제 포커스를 가진 쪽에만 테두리를 표시한다.

## 파일 키보드 탐색

일반 Diff·File·Blame 화면에서는 `↑`와 `↓`를 이전·다음 파일 이동에 연결한다.
기존 `⌘↑`와 `⌘↓`도 유지한다.

History 화면에서는 기존 입력 우선순위를 유지한다.

- 파일 목록 포커스: `↑`·`↓`로 파일 이동, `→`로 History 목록 이동
- History 목록 포커스: `↑`·`↓`로 이력 이동, `←`로 파일 목록 이동
- 팝업 메뉴가 열려 있으면 메뉴가 화살표 키를 먼저 처리

파일 목록의 처음과 끝에서는 더 이동하지 않으며 순환하지 않는다.

## 인코딩 배치와 앱 실행 중 캐시

인코딩 배지는 오른쪽 화면 전환 버튼 묶음에서 제거하고 왼쪽 파일 정보 묶음의
마지막에 둔다.

`뒤로가기 → 파일 아이콘 → 파일 이름 → 변경분·크기 → 인코딩`

처음 보는 파일은 인코딩이 확인될 때까지 배지를 표시하지 않는다. `Loading`
문구나 별도의 진행 표시는 사용하지 않는다. 인코딩이 확인되면 배지를 추가한다.
배지의 너비가 달라져도 앞쪽 파일 이름과 변경분, 오른쪽 조작 버튼은 움직이지
않는다.

인코딩 캐시는 앱 프로세스가 살아 있는 동안 여러 Full Diff 화면에서 공유한다.
캐시 키는 다음 값을 포함한다.

- 저장소 루트
- 기준 리비전과 선택한 부모
- 파일 경로와 이전 경로
- 표시하는 파일 쪽(old/result)

커밋 파일은 캐시된 값을 즉시 표시하고 기존 파일 본문 캐시를 그대로 활용한다.
작업 트리 파일도 캐시된 값을 먼저 표시하지만, 파일을 선택할 때마다 뒤에서
본문을 다시 읽는다. 새로 판별한 인코딩이 캐시와 다를 때만 배지 문구를 바꾼다.
재확인에 실패하면 기존 캐시값을 유지한다. 앱을 종료하면 캐시는 사라진다.

캐시는 작은 인코딩 분류값만 보관하며 파일 본문을 추가로 복제하지 않는다.
테스트에서는 독립 캐시를 주입할 수 있어야 한다.

## Blame 밀도

Blame의 각 행은 소스 코드의 기본 줄 높이와 같은 21px로 표시한다.

- 행 높이: 21px
- 아바타: 20px
- 커밋 컬러선: 3px
- 메타데이터와 소스 텍스트는 세로 가운데 정렬
- 기존 열 순서와 너비, 말줄임, 선택 배경, 구문 강조는 유지

줄바꿈을 켠 긴 소스 줄은 내용에 필요한 높이를 사용할 수 있다. 줄바꿈이 없는
일반 행은 21px를 기준으로 한다.

## 오류 처리

- 첫 인코딩 판별에 실패하면 배지를 표시하지 않고 기존 오류 화면을 유지한다.
- 캐시가 있는 상태에서 재확인에 실패하면 캐시값을 지우지 않는다.
- 늦게 끝난 이전 파일의 판별 결과는 현재 선택 파일이나 캐시 항목을 덮어쓰지
  않는다.
- 포커스 이동은 파일 또는 History 선택만 바꾸며 현재 팝업과 텍스트 선택 동작을
  침범하지 않는다.

## 검증

구현은 테스트를 먼저 추가하고 실패를 확인한 뒤 진행한다.

1. 파일 행과 History 행이 공통 선택 컴포넌트를 사용하며 같은 배경과 1px
   포커스 테두리를 표시한다.
2. 일반 Full Diff 화면에서 콘텐츠에 포커스가 있어도 `↑`·`↓`가 파일을 이동한다.
3. History 화면의 좌우 포커스 이동과 화살표 키 동작은 그대로 유지된다.
4. 인코딩을 읽기 전에는 배지가 없고 확인 후 파일 정보 오른쪽에 나타난다.
5. 새 Full Diff 컨트롤러에서도 앱 실행 중 캐시값을 즉시 표시한다.
6. 작업 트리 파일의 인코딩이 바뀌면 캐시값을 먼저 표시한 뒤 새 값으로 갱신한다.
7. 인코딩 재확인 실패 시 기존 캐시값을 유지한다.
8. Blame 일반 행은 21px, 아바타는 20px, 컬러선은 3px다.
9. 관련 위젯·컨트롤러 테스트, 시각 계약 테스트와 전체 테스트를 통과한다.

## 범위에서 제외

- 앱 재실행 후에도 남는 인코딩 저장
- 파일 시스템 감시기 추가
- 파일·History 행 내용 자체의 재배치
- Blame 메타데이터 열의 가로 너비 변경
- Full Diff 이외 화면의 선택 디자인 변경
