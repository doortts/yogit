# 최근 참조 정렬과 Rebase 연결선 경계 설계

## 목표

- 기준 브랜치와 브랜치 diff 메뉴를 참조 종류별로 나누고 최근 항목부터 표시한다.
- Rebase 미리보기에서 같은 커밋을 잇는 선이 Graph 컬럼을 벗어나지 않게 한다.
- 기존 Git 조회와 그래프 그리기 구조를 재사용한다.

## 참조 메뉴

### 그룹

- 기준 브랜치 메뉴에는 로컬 브랜치만 표시한다.
- 브랜치 diff 메뉴에는 `LOCAL`, `REMOTE`, `TAG` 그룹을 이 순서로 표시한다.
- 검색 결과에서도 그룹과 그룹 안의 정렬 순서를 유지한다.

### 정렬

- 로컬 브랜치는 생성 시각과 끝 커밋 시각 중 더 최근 시각을 사용한다.
- 원격 브랜치는 끝 커밋 시각을 사용한다.
- 태그는 생성 시각을 사용한다.
- 시각을 알 수 있는 항목을 최신순으로 표시한다.
- 시각이 같거나 없는 항목은 이름순으로 표시한다.
- `git for-each-ref`가 이미 반환하는 시각을 저장하므로 메뉴를 열 때 Git을 다시 실행하지 않는다.

## Rebase 연결선

- 일반 커밋 레인의 간격은 바꾸지 않는다.
- 같은 커밋을 잇는 선의 간격만 기존 레인 간격의 50%로 줄인다.
- 선을 그리는 영역을 Graph 컬럼 경계로 자른다.
- Graph 컬럼에 모든 연결선이 들어가면 모두 표시한다.
- 모두 들어가지 않으면 현재 선택한 실제 또는 가상 커밋에 해당하는 연결선 하나만 표시한다.
- 선택한 커밋에 해당하는 연결선이 없으면 연결선을 표시하지 않는다.
- 마우스나 키보드로 커밋을 바꾸면 연결선도 즉시 다시 그린다.
- 기존 1픽셀 실선, 열린 화살표, 색상 단계는 유지한다.

## 검증

- 로컬·원격·태그가 정해진 그룹과 최신순으로 표시되는지 확인한다.
- 시각이 없거나 같은 항목이 이름순으로 안정적으로 표시되는지 확인한다.
- 연결선 간격이 절반으로 줄었는지 픽셀 단위로 확인한다.
- 좁은 Graph 컬럼에서는 선택한 커밋의 연결선만 남는지 확인한다.
- 연결선이 Graph 컬럼 밖에 그려지지 않는지 확인한다.
- 기존 브랜치 선택, Rebase 미리보기, 일반 타임라인 테스트를 함께 실행한다.
