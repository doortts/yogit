# Full Diff 탐색과 Side-by-side 분할선 개선 설계

## 배경

Full Diff의 History 화면에는 파일 목록과 파일 이력 목록이 함께 있지만, 상단 버튼이나 목록 행을 누른 뒤 화살표 키로 선택을 옮길 수 없다. 상단의 Diff, Blame, History 버튼도 같은 단계의 선택 항목처럼 보여서 History가 Diff 내용을 보조하는 기능이라는 관계가 드러나지 않는다.

Side-by-side 화면은 이전 파일과 이후 파일의 폭이 항상 같으며, 가운데 선을 드래그해 폭을 바꿀 수 없다. Command 키를 누르면 나타나는 단축키 안내 글자도 다른 작은 안내 글자보다 작다.

## 목표

- History 화면에서 파일 목록과 파일 이력 목록을 화살표 키로 이동한다.
- 상단 버튼을 눌러도 파일 또는 파일 이력 목록의 포커스를 유지한다.
- Diff와 Blame을 서로 붙어 있는 단일 선택 묶음으로 표현한다.
- Unified와 Side-by-side를 서로 붙어 있는 단일 선택 묶음으로 표현한다.
- History를 Diff 화면의 보조 기능으로 표현한다.
- Side-by-side 가운데 선을 마우스나 트랙패드로 드래그해 폭을 바꾼다.
- Command 키를 누를 때 나타나는 단축키 안내 글자를 1픽셀 키운다.

## 목표가 아닌 것

- Side-by-side 가운데 선을 키보드로 조절하지 않는다.
- Blame 화면의 내용이나 줄 선택 방식을 바꾸지 않는다.
- History에서 선택한 커밋의 diff 계산 방식을 바꾸지 않는다.
- 새 단축키를 추가하거나 기존 단축키 조합을 바꾸지 않는다.

## 확인한 원인

파일 목록과 파일 이력 목록에는 화살표 키 처리 코드가 이미 있다. 하지만 목록 행을 눌러도 해당 목록이 포커스를 다시 가져오지 않는다. 상단 버튼을 누르면 버튼이 포커스를 가져가며, 상위 단축키 처리기가 History 화면의 위·아래 화살표를 동작 없이 소비한다. 따라서 기존 목록 이동 코드까지 키 입력이 도달하지 않는다.

## 선택한 접근

기존 `FullDiffView.diff`, `FullDiffView.blame`, `FullDiffView.history` 상태는 유지한다. 저장 형식을 바꾸지 않으므로 이전 설정과 호환된다.

화면에서는 상태를 다음처럼 해석한다.

- `diff`: 상단에서 Diff 선택, History 해제
- `history`: 상단에서 Diff 선택, History 선택
- `blame`: 상단에서 Blame 선택, Diff 전용 도구 숨김

History를 위한 별도 상태 모델을 추가하는 방법도 검토했지만, 기존 설정 이전과 상태 전환 코드를 크게 바꿔야 한다. 현재 모델을 화면에서만 직교 상태처럼 표현하면 같은 동작을 더 작은 변경으로 구현할 수 있다.

## 화면 구성

### 첫 번째 줄

우측에는 `Diff | Blame` 두 버튼만 표시한다. 두 버튼은 간격 없이 붙이며 바깥쪽 모서리만 둥글게 처리한다. 항상 둘 중 하나만 선택된다.

History가 열린 상태에서도 Diff를 선택 상태로 표시한다. Blame을 누르면 History가 닫히고 Blame 화면으로 전환한다.

### 두 번째 줄

Diff 또는 History 상태에서만 다음 순서로 표시한다.

1. `Unified | Side-by-side`
2. `Hunk`
3. `History`

Unified와 Side-by-side는 간격 없이 붙이며 바깥쪽 모서리만 둥글게 처리한다. Hunk와 History는 각각 독립적으로 켜고 끌 수 있는 버튼 모양을 유지한다.

Blame 상태에서는 Unified, Side-by-side, Hunk, History를 모두 숨긴다. 두 번째 줄의 나머지 도구 배치는 이번 작업에서 바꾸지 않는다.

History를 다시 누르면 일반 Diff 화면으로 돌아간다. 기존 `Command 3`은 History를 여는 동작을 유지하며, History가 열린 상태에서 다시 누르면 일반 Diff로 돌아간다. `Command 1`은 일반 Diff 화면으로 전환하고 `Command 2`는 Blame 화면으로 전환한다.

## 목록 포커스와 키보드 이동

Full Diff 화면은 마지막으로 사용한 탐색 목록을 기억한다.

- 파일 목록에서 `↑`와 `↓`: 이전·다음 파일 선택
- 파일 목록에서 `→`: History가 열려 있으면 파일 이력 목록으로 이동
- 파일 이력 목록에서 `↑`와 `↓`: 이전·다음 이력 선택
- 파일 이력 목록에서 `←`: 파일 목록으로 이동

파일 행을 누르면 파일 목록이 포커스를 가져간다. 파일 이력 행을 누르면 파일 이력 목록이 포커스를 가져간다.

Diff, Blame, Unified, Side-by-side, Hunk, History 버튼을 누른 뒤에는 화면 갱신이 끝난 다음 마지막 탐색 목록으로 포커스를 돌려보낸다. History를 닫거나 Blame으로 전환해서 파일 이력 목록이 사라지면 파일 목록으로 포커스를 옮긴다. 집중 모드처럼 파일 목록 자체가 숨은 경우에는 포커스를 강제로 복원하지 않는다.

버튼을 누른 직후에도 화살표 키 이동이 이어지는지가 사용자 관점의 성공 기준이다. 버튼의 일시적인 내부 포커스 상태는 외부 동작으로 노출하지 않는다.

## Side-by-side 분할선

Side-by-side 화면은 이전 파일과 이후 파일 사이에 하나의 세로 분할선을 둔다.

- 보이는 선: 1픽셀
- 드래그 영역: 선을 중심으로 좌우에 여유를 둔 투명 영역
- 조작 방법: 마우스 또는 트랙패드 드래그
- 허용 범위: 이전 파일 영역이 전체 코드 영역의 20~80%
- 기본값: 50%

분할 비율은 `FullDiffColumnWidths`에 저장한다. 파일을 바꾸거나 Unified와 Side-by-side를 오가도 같은 비율을 사용하며, Full Diff를 다시 열어도 저장된 값을 먼저 적용한다. 이전 설정에 값이 없으면 50%를 사용한다.

각 diff 행과 빗금 영역은 같은 분할 비율을 사용한다. 분할선을 움직여도 세로 스크롤 위치, 선택한 Hunk, 코드 선택 영역은 유지한다. 폭이 480픽셀 이하라서 기존처럼 이전 파일 영역을 숨기는 화면에서는 분할선을 표시하지 않는다.

분할선은 키보드 포커스를 받지 않으며 화살표 키로 조절할 수 없다.

## 단축키 안내

`FullDiffShortcutHint`의 글자 크기를 10픽셀에서 11픽셀로 바꾼다. 안내 상자의 위치와 여백은 유지해 버튼 배치가 움직이지 않게 한다.

## 오류 처리와 경계 조건

- History 자료를 읽는 중이거나 읽지 못했더라도 파일 목록 포커스는 유지한다.
- 파일 이력이 비어 있으면 `→`를 눌러도 파일 목록 포커스를 유지한다.
- 첫 파일에서 `↑`, 마지막 파일에서 `↓`를 눌러도 선택은 경계를 넘지 않는다.
- 첫 이력에서 `↑`, 마지막 이력에서 `↓`를 눌러도 선택은 경계를 넘지 않는다.
- 창 폭이 줄어 파일 목록이나 분할선이 숨으면 보이지 않는 요소로 포커스를 보내지 않는다.
- 저장된 Side-by-side 비율이 범위를 벗어나면 읽을 때 20~80%로 제한한다.

## 테스트

구현 전에 다음 동작을 실패하는 테스트로 고정한다.

1. History에서 파일 목록의 `↑/↓`와 `→`가 동작한다.
2. 파일 이력 목록의 `↑/↓`와 `←`가 동작한다.
3. 목록 행을 누르면 해당 목록이 포커스를 가져간다.
4. Diff, Blame, Unified, Side-by-side, Hunk, History 버튼을 누른 뒤 목록 이동이 이어진다.
5. Diff와 Blame, Unified와 Side-by-side가 각각 붙어 있는 선택 묶음으로 렌더링된다.
6. History 상태에서도 Diff가 선택 상태로 보이며 History도 선택 상태로 보인다.
7. Blame에서는 두 번째 줄의 Diff 전용 도구가 보이지 않는다.
8. Side-by-side 분할선을 드래그하면 양쪽 폭이 바뀌고 비율이 저장된다.
9. 저장된 분할 비율이 다음 Full Diff와 다른 파일에도 적용된다.
10. 좁은 화면에서는 분할선이 보이지 않는다.
11. Command 키 안내 글자가 11픽셀이고 버튼 위치가 변하지 않는다.

영향 범위 테스트가 통과한 뒤 전체 Flutter 테스트, 시각 검수 테스트, 정적 검사, macOS 릴리스 빌드를 실행한다.

## 완료 기준

- 여섯 가지 사용자 요청을 모두 자동 테스트로 검증한다.
- 기존 Full Diff 설정 파일을 그대로 읽을 수 있다.
- History, Diff, Blame 전환 뒤에도 화살표 키 이동이 끊기지 않는다.
- Side-by-side 분할 비율이 저장되고 복원된다.
- Blame 화면에는 Diff 전용 도구가 표시되지 않는다.
- 시각 검수에서 버튼 배치와 선택 상태가 설계와 일치한다.
