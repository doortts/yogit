알림창 — 직각으로, 주소는 집을 수 있게, 명령어는 미리

세 가지를 함께 고친다. 모서리를 직각으로 세우고, 원격 주소 줄에서 키보드로 못 치는 글자를 없애고 주소를 끌어서 복사할 수 있게 하고, 버튼 바로 위에 실제로 돌아갈 git 명령을 미리 세운다 — 누르기 전에 무엇이 실행되는지 그 글자 그대로 읽는다.

2 · 원격 주소 origin: 주소 · 끌어서 복사

가운뎃점(·)은 키보드로 바로 못 치는 글자라 주소 줄에서 뺀다 — origin: 뒤에 주소가 바로 선다, 콜론 하나로. 주소는 끌어서 고를 수 있고 ⌘C로 복사된다. 고르는 것은 주소만이라, 복사한 것을 그대로 git remote add에 붙여도 origin · 같은 군더더기가 따라오지 않는다.

지금
main 브랜치를 origin에 Push할까요?
origin·https://github.com/doortts/yogit
주소는 글자일 뿐 — 고를 수도, 복사할 수도 없다.
시안
main 브랜치를 origin에 Push할까요?
origin:https://github.com/doortts/yogit
주소를 끌어 보세요 — 고르고 복사됩니다.

영수증 요약줄(main · push · 커밋 44개 올라감)의 가운뎃점은 그대로 둔다 — 그 줄은 치거나 복사할 글이 아니라 읽는 표다. 그쪽도 없애려면 말해 주세요.

3 · 실행할 명령 버튼 바로 위

각 확인창은 자기가 실제로 돌릴 git 명령을 그대로 세운다. 여러 걸음이면 여러 줄이고, 순서가 곧 실행 순서다. 이 상자도 끌어서 복사된다 — 터미널에서 직접 해 보고 싶을 때 그대로 붙인다.

Push만 (초록)
main 브랜치를 origin에 Push할까요?
origin:https://github.com/doortts/yogit
원격 main 브랜치가 ef8220d에서 f1862dc로 움직입니다.
실행할 명령git push origin f1862dc:refs/heads/main

실행할 명령git update-ref refs/heads/main ddd4444 aaa1111 git reset --hard # 체크아웃되어 있을 때만 git push origin ddd4444:refs/heads/main
취소받아 얹고 Push

받아 얹기가 git rebase로 서지 않는 이유: 재연은 이미 숨은 worktree에서 끝났고(그래서 ‘충돌 없음’을 말할 수 있다), 확인을 누른 뒤 남는 일은 브랜치 ref를 그 결과로 옮기는 것뿐이다. 있지도 않은 git pull --rebase를 적어 두면 확인창이 거짓을 말한다.

규칙

  • 모서리는 바꾸지 않는다 — 직각 안은 취소됐다.
  • 명령어 줄은 실제로 실행하는 인자 그대로다. 다만 자격증명 프롬프트를 막는 -c credential.interactive=never는 적지 않는다 — 그건 행위가 아니라 이 앱이 늘 두르는 안전장치다.
  • 해시는 확인창이 보인 그 해시다. 창이 열린 사이 브랜치가 움직였으면 실행이 거절되므로, 적힌 명령과 실제로 도는 명령이 어긋나는 일은 없다.
  • 명령이 없는 확인창(삭제 확인·프로필 편집처럼 git 한 줄로 안 떨어지는 것)에는 이 상자가 서지 않는다. 억지로 채우지 않는다.
  • 주소와 명령어 상자는 고를 수 있고(끌기·⌘C) 그 밖의 글자는 지금처럼 고를 수 없다 — 알림창에서 고르기가 필요한 자리는 이 둘뿐이다.
