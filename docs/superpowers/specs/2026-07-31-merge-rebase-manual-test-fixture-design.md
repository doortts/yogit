# Merge·Rebase 미리보기 수동 테스트 픽스처 설계

## 목표

Yogit의 Merge·Rebase 미리보기에서 성공, 충돌, 실제 적용, 원복을 직접
검증할 수 있는 재사용 가능한 Git 저장소를 만든다. 로컬 브랜치와 원격
추적 브랜치를 모두 비교 대상으로 제공한다.

## 커밋 구성

`main`은 공통 시작 커밋에서 갈라진 뒤 `shared.txt`와 기준 브랜치 전용
파일을 변경한다.

성공용 이력은 기준 브랜치와 겹치지 않는 파일을 세 커밋에 걸쳐
추가하거나 수정한다. Merge 미리보기에서는 가상 Merge 커밋과 최종 파일
목록을, Rebase 미리보기에서는 원본과 재작성 커밋 세 쌍을 확인할 수
있어야 한다.

충돌용 이력은 다음 순서로 만든다.

1. 기준 브랜치와 겹치지 않는 파일을 추가하는 정상 커밋
2. `shared.txt`의 같은 줄을 다르게 고쳐 충돌하는 커밋
3. 충돌 커밋 뒤에서 대기하는 정상 커밋

이 이력은 Merge 충돌 파일과 Rebase의 완료·현재·대기 진행 상태를 모두
보여준다. 충돌을 해결하고 계속하면 마지막 커밋까지 적용된 최종 결과를
확인할 수 있어야 한다.

## 브랜치와 태그

로컬 복제본에는 다음 브랜치를 둔다.

- `main`: 모든 시나리오의 기준 브랜치
- `local/clean`: 로컬 브랜치 성공 시나리오
- `local/conflict`: 로컬 브랜치 충돌 시나리오

원격에는 같은 커밋을 가리키는 다음 비교 브랜치를 추가한다. 로컬
복제본에는 대응하는 로컬 브랜치를 만들지 않아 원격 전용 흐름을
검증한다.

- `origin/remote/clean`
- `origin/remote/conflict`

초기 위치를 보존하는 태그는 다음과 같다.

- `fixture/base`
- `fixture/clean`
- `fixture/conflict`

## 복원 동작

`reset-fixture.sh`는 먼저 `main`으로 이동한 뒤 기준 태그를 사용해
`main`, `local/clean`, `local/conflict`를 초기 위치로 되돌린다. 원격
추적 정보를 다시 받아 원격 전용 브랜치도 원래 상태로 맞춘다.

Yogit의 실제 적용은 원격에 푸시하지 않으므로 복원 스크립트도 원격
브랜치를 강제로 덮어쓰지 않는다. 사용자가 픽스처 저장소에서 만든
추적하지 않는 파일도 삭제하지 않는다.

## 검증 범위

수동 테스트 절차는 다음 상태를 각각 다룬다.

1. 로컬 브랜치 Merge 성공, 실제 적용, 원복
2. 로컬 브랜치 Rebase 성공, 실제 적용, 원복
3. Merge 충돌, 파일 해결, 완료 결과 확인, 폐기
4. Rebase 충돌, 파일 해결, 계속, 완료 결과 확인, 폐기
5. 원격 전용 브랜치 Merge 성공, 실제 적용, 원복
6. 원격 전용 브랜치 Rebase 성공, 로컬 추적 브랜치 생성, 원복

각 절차는 시작 전에 `./reset-fixture.sh`를 실행한다. 파일 목록,
Unified/Side-by-side diff, 가상 커밋 표시, 브랜치 SHA 유지 여부도 함께
확인한다.

## 자동 확인

픽스처를 만든 뒤 Git 명령으로 다음 조건을 검사한다.

- 로컬 작업 트리가 깨끗하다.
- 로컬 브랜치와 원격 추적 브랜치가 의도한 태그를 가리킨다.
- `main`과 성공용 브랜치는 충돌 없이 Merge 및 Rebase할 수 있다.
- `main`과 충돌용 브랜치는 Merge 및 Rebase에서 `shared.txt` 충돌이 난다.
- 복원 스크립트를 실행하면 모든 로컬 브랜치가 기준 태그로 돌아온다.
