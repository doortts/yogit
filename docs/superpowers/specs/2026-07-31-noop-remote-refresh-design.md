# 원격 확인 시 불필요한 화면 갱신 방지 설계

## 문제

`TimelineScreen`은 앱을 연 직후와 이후 3분마다 관련 원격 저장소를 확인한다. 현재 `fetchRemote()`는 원격 추적 참조가 그대로여도 항상 `updated`를 반환한다. 그 결과 참조와 커밋 그래프를 매번 다시 계산하며, 브랜치 미리보기에서는 기존 비교 결과까지 비웠다가 다시 채운다.

## 목표

- 원격 추적 참조가 바뀌지 않으면 참조와 그래프를 다시 계산하지 않는다.
- 참조가 바뀌어도 비교 중인 두 브랜치의 tip SHA가 같으면 미리보기를 유지한다.
- 비교 대상 SHA가 바뀌면 기존 미리보기를 유지한 채 새 결과를 계산하고 준비가 끝났을 때 교체한다.
- 원격 확인의 진행·실패 상태는 상태표시줄만 다시 구성한다.

## 설계

### 원격 변경 판별

`git fetch --porcelain --prune <remote>`를 사용한다. 명령이 성공했을 때 표준 출력이 비어 있으면 `FetchOriginResult.unchanged`, 참조 변경 기록이 있으면 `updated`를 반환한다. 기존 `noOrigin`은 그대로 유지한다.

### 참조와 그래프 갱신

`_refreshRemotes()`는 한 곳이라도 `updated`를 반환한 경우에만 `_loadRefs()`를 호출한다. 변경이 없다면 현재 `RepoRefs`, 그래프, 선택 상태와 미리보기 캐시를 그대로 둔다.

`_loadRefs()`는 기존 비교 결과의 `baseTip`·`compareTip`을 새 참조의 SHA와 비교한다. 둘 다 같으면 비교를 다시 계산하지 않는다. 다르면 기존 비교 화면을 비우지 않고 `compareBranches()`를 실행한 뒤 새 결과를 한 번에 반영한다.

### 화면 갱신 범위

원격 확인의 진행 여부와 오류는 `ValueNotifier`로 관리한다. 상태표시줄의 해당 영역만 이를 구독한다. 정상적인 변경 없음 확인에서는 `TimelineScreen.setState()`를 호출하지 않는다.

## 오류 처리

원격 확인이 실패하면 기존 참조와 배지를 유지하고 상태표시줄에 다시 시도 동작을 제공한다. 일부 원격만 실패하고 다른 원격이 갱신된 경우에는 성공한 변경을 반영하면서 첫 번째 오류도 표시한다.

## 검증

- porcelain 출력이 없을 때 `unchanged`를 반환하는 저장소 테스트
- 출력이 있을 때 `updated`를 반환하는 저장소 테스트
- 3분 주기 확인 결과가 `unchanged`면 참조를 다시 읽지 않는 위젯 테스트
- 참조를 다시 읽어도 비교 SHA가 같으면 비교를 다시 계산하지 않는 위젯 테스트
- 비교 SHA가 바뀌면 이전 행을 유지하다가 새 결과로 교체하는 위젯 테스트
- 원격 확인 상태가 상태표시줄 범위에서만 바뀌는 위젯 테스트
