# Full Diff 커밋 정보 카드와 Blame 키보드 탐색 설계

## 배경

Blame 화면에서 선택한 라인의 커밋 정보 카드는 배경과 테두리의 명도 차이가 작아 경계가 잘 보이지 않는다. 카드의 왼쪽도 아바타 영역에 걸쳐 있어 라인 번호와 코드가 이루는 세로 흐름에서 벗어나 보인다.

파일 History 화면은 선택한 커밋의 제목과 간단한 작성 정보만 목록 행에 표시한다. 제목이 잘리면 전체 내용을 확인하기 어렵고, Blame과 History가 서로 다른 방식으로 커밋 정보를 보여준다.

Blame의 라인 목록은 내부적으로 위·아래 화살표 키를 처리하지만 Full Diff의 파일 목록에서 Blame으로 포커스를 옮길 방법이 없다. History의 파일 목록과 커밋 목록 사이에는 이미 좌우 화살표 이동 규칙이 있으므로 Blame도 같은 탐색 방식을 따라야 한다.

## 목표

- Blame과 History에서 같은 디자인과 정보 형식의 커밋 정보 카드를 사용한다.
- 전체 커밋 메시지를 최대 8줄까지 표시한다.
- 한 번 가져온 커밋 메시지는 앱이 종료될 때까지 재사용한다.
- 커밋 정보 카드를 목록 위에 겹쳐 표시해 기존 행의 위치를 바꾸지 않는다.
- Blame 카드의 경계를 분명히 표시하고 라인 번호 열과 왼쪽을 맞춘다.
- 파일 목록과 Blame 라인 목록 사이를 좌우 화살표 키로 이동한다.
- Blame 라인을 위·아래 화살표 키로 선택한다.

## 목표가 아닌 것

- 커밋 본문을 수정하거나 복사하기 위한 별도 화면은 추가하지 않는다.
- 커밋 메시지 캐시를 디스크에 저장하지 않는다.
- History에서 선택한 커밋의 diff 계산 방식은 바꾸지 않는다.
- Blame 행의 아바타, 커밋 제목, 날짜, 컬러 레일 배치는 바꾸지 않는다.
- 첫 줄과 마지막 줄을 연결하는 순환 탐색은 추가하지 않는다.

## 선택한 접근

공통 `FullDiffCommitInfoCard`가 커밋 메시지, 짧은 SHA, 작성자, 작성 시각을 표시한다. Blame과 History는 각자의 자료를 `FullDiffCommitInfo`로 바꿔 카드에 전달한다. 카드는 자료 표시만 맡고 선택 상태, 포커스, 위치 계산은 각 화면이 맡는다.

두 화면은 선택 행에 `LayerLink`를 연결하고 `CompositedTransformFollower`로 카드를 겹쳐 표시한다. 이 방식은 선택 행을 기준으로 위치를 계산하므로 목록이 스크롤되어도 카드가 선택 행을 따라간다. 카드를 목록의 자식 행으로 삽입하지 않으므로 다른 행을 아래로 밀지 않는다.

앱 전체에서 공유하는 `FullDiffCommitMessageCache`를 둔다. 캐시 키는 저장소 절대 경로와 커밋 SHA의 조합이다. `FullDiffRepository`는 SHA의 전체 커밋 메시지를 가져오는 기능을 제공하고 `GitRepository`는 `git show -s --format=%B <SHA>`를 실행한다.

## 공통 커밋 정보

`FullDiffCommitInfo`는 다음 값을 가진다.

- 전체 커밋 메시지
- 커밋 메시지를 아직 가져오지 못했을 때 사용할 제목 또는 Blame 요약
- 짧은 SHA
- 작성자 이름
- 작성 시각

카드의 첫 영역에는 제목과 본문을 포함한 전체 커밋 메시지를 표시한다. 최대 8줄까지 보여주며 8줄을 넘으면 마지막 줄을 말줄임표로 처리한다.

다음 줄에는 `짧은 SHA · 작성자 · YYYY-MM-DD HH:mm` 형식으로 표시한다. 시각은 앱이 실행되는 컴퓨터의 현지 시각으로 바꿔 표시한다. SHA는 기존 기술 정보용 고정폭 글꼴을 사용하고 나머지는 앱의 UI 글꼴을 따른다.

## 커밋 메시지 조회와 캐시

사용자가 Blame 라인이나 History 커밋을 선택하면 해당 SHA의 전체 커밋 메시지를 요청한다. 이미 캐시한 값이 있으면 Git 명령을 실행하지 않고 즉시 사용한다.

`FullDiffCommitMessageCache.shared`는 다음 규칙을 따른다.

- 키는 `저장소 절대 경로 + 커밋 SHA`다.
- 성공한 전체 메시지는 앱 프로세스가 종료될 때까지 메모리에 유지한다.
- 같은 키를 동시에 요청하면 실행 중인 요청 하나를 함께 기다린다.
- 실패한 요청은 캐시하지 않아 다음 선택 때 다시 시도할 수 있다.
- 결과가 비어 있으면 실패로 취급한다.
- 유효한 SHA가 없는 작업 디렉터리 항목은 조회하지 않는다.

메시지를 읽는 동안 별도의 `Loading` 문구를 표시하지 않는다. 목록에 있던 커밋 제목 또는 Blame 요약을 먼저 표시하고 조회가 끝나면 전체 메시지로 바꾼다. 선택이 빠르게 바뀌어 이전 요청이 늦게 끝나더라도 현재 선택한 카드의 내용을 덮어쓰지 않는다. 조회가 실패하면 기존 제목이나 요약을 그대로 유지한다.

## 카드 디자인과 배치

공통 카드는 다음 모양을 사용한다.

- 배경: 기존 Full Diff 헤더 배경색
- 테두리: 배경과 분명히 구분되는 1픽셀 강조색
- 모서리: 기존 카드와 같은 8픽셀 반지름
- 그림자: 기존 카드의 그림자를 유지
- 최대 너비: 420픽셀
- 커밋 메시지: 최대 8줄

Blame에서는 카드의 왼쪽을 라인 번호 열의 시작점에 맞춘다. 선택 행의 위쪽을 기준으로 두 행 아래에 표시하는 기존 세로 위치는 유지한다. 카드가 화면 오른쪽을 넘어갈 수 있는 좁은 화면에서는 사용 가능한 너비에 맞춰 줄인다.

History에서는 선택 행 바로 아래에 작은 간격을 두고 표시한다. 커밋 목록에 포커스가 있을 때만 보이며 파일 목록으로 포커스가 돌아가면 숨긴다. 선택한 커밋 자체는 유지한다.

두 화면 모두 카드가 다른 행의 높이와 위치를 바꾸지 않는다. 카드가 아래 내용을 가려도 목록을 강제로 이동하거나 빈 공간을 만들지 않는다. 사용자는 기존 스크롤 방식으로 가려진 내용을 볼 수 있다.

## Blame 키보드 탐색

`FullBlameView`는 상위 화면에서 전달한 포커스 노드와 파일 목록으로 돌아가는 동작을 사용한다. Full Diff는 파일 목록, History 목록과 함께 마지막으로 사용한 탐색 영역을 기억한다.

- 파일 목록에서 `↑`와 `↓`: 이전·다음 파일 선택
- Blame 화면의 파일 목록에서 `→`: Blame 라인 목록으로 이동
- Blame 라인 목록에서 `↑`와 `↓`: 이전·다음 라인 선택
- Blame 라인 목록에서 `←`: 파일 목록으로 이동

Blame 라인 목록으로 처음 이동할 때 선택된 라인이 없으면 현재 변경 위치와 가장 가까운 라인을 선택한다. 현재 변경 위치를 구할 수 없으면 첫 번째 라인을 선택한다. 첫 줄에서 `↑`, 마지막 줄에서 `↓`를 눌러도 선택은 경계를 넘지 않는다.

마우스로 Blame 라인을 누르면 해당 라인을 선택하고 Blame 라인 목록이 포커스를 가져간다. 상단 버튼을 사용한 뒤 Blame 화면으로 돌아오면 기존 Full Diff 포커스 복원 규칙에 따라 마지막 탐색 영역을 복원한다.

## History 상호작용

History의 기존 탐색 규칙은 유지한다.

- 파일 목록에서 `→`: 커밋 목록으로 이동
- 커밋 목록에서 `↑`와 `↓`: 이전·다음 커밋 선택
- 커밋 목록에서 `←`: 파일 목록으로 이동

커밋 목록이 포커스를 얻으면 선택 행 아래에 공통 커밋 정보 카드를 표시한다. 위·아래 화살표 키나 마우스로 다른 커밋을 고르면 카드 내용과 위치가 새 선택을 따라간다. 파일 목록으로 돌아가면 카드는 숨기되 선택한 커밋과 오른쪽 diff 내용은 유지한다.

## 오류 처리와 경계 조건

- Blame이나 History 자료를 읽는 동안에는 커밋 정보 카드를 표시하지 않는다.
- 커밋 메시지 조회가 실패하면 기존 제목이나 요약을 표시한다.
- 같은 SHA의 실패한 조회는 다음 선택 때 다시 시도한다.
- 저장소가 다르면 같은 SHA라도 캐시를 공유하지 않는다.
- 선택 행이 화면 밖으로 이동하면 기존 목록 탐색 코드가 행을 보이게 한 뒤 카드가 새 위치를 따라간다.
- 좁은 화면에서는 카드 너비를 줄이되 상세 정보가 화면 밖으로 넘치지 않게 한다.
- Blame 파일에 라인이 없으면 `→`를 눌러도 파일 목록 포커스를 유지한다.
- 선택이 바뀌거나 화면이 닫힌 뒤 끝난 비동기 결과는 사라진 화면이나 다른 선택을 갱신하지 않는다.

## 테스트

구현 전에 다음 동작을 실패하는 테스트로 고정한다.

1. 공통 카드가 커밋 메시지, 짧은 SHA, 작성자, 현지 시각을 표시한다.
2. 커밋 메시지는 최대 8줄이며 이후 내용은 말줄임표로 처리한다.
3. Blame 카드의 테두리가 1픽셀 강조색으로 표시된다.
4. Blame 카드의 왼쪽이 라인 번호 열의 시작점과 맞는다.
5. Blame 카드를 표시해도 다른 라인의 위치가 바뀌지 않는다.
6. 파일 목록의 `→`가 Blame 라인 목록으로 포커스를 옮긴다.
7. Blame의 `↑/↓`가 라인을 선택하고 카드를 함께 옮긴다.
8. Blame의 `←`가 파일 목록으로 포커스를 돌려보낸다.
9. Blame에 처음 진입하면 현재 변경 위치와 가장 가까운 라인 또는 첫 줄을 선택한다.
10. History 카드가 커밋 목록에 포커스가 있을 때만 표시된다.
11. History 선택을 바꾸면 카드 내용과 위치가 바뀌고 목록 행의 위치는 유지된다.
12. History에서 파일 목록으로 돌아가면 카드는 숨고 커밋 선택은 유지된다.
13. 같은 저장소와 SHA를 다시 선택하면 Git 조회를 한 번만 실행한다.
14. 두 요청이 동시에 같은 저장소와 SHA를 읽으면 Git 조회를 하나만 실행한다.
15. 저장소가 다르면 같은 SHA도 각각 조회한다.
16. 조회 실패는 캐시하지 않으며 다음 요청에서 다시 시도한다.
17. 조회 중에는 기존 제목이나 요약을 표시하고 성공 후 전체 메시지로 바꾼다.
18. 늦게 끝난 이전 선택의 결과가 현재 카드를 덮어쓰지 않는다.
19. 커밋 메시지를 캐시한 뒤 Full Diff 화면을 다시 열어도 추가 Git 조회 없이 사용한다.

영향 범위 테스트가 통과한 뒤 전체 Flutter 테스트, 정적 검사, 시각 검수 테스트, macOS 릴리스 빌드를 실행한다.

## 완료 기준

- Blame과 History가 같은 커밋 정보 카드를 사용한다.
- 카드의 커밋 메시지가 최대 8줄까지 표시된다.
- 성공적으로 가져온 커밋 메시지가 앱 종료 시까지 저장소와 SHA별로 캐시된다.
- Blame 카드의 테두리와 정렬이 요청한 위치와 대비를 만족한다.
- 파일 목록과 Blame 라인 목록 사이의 좌우 이동과 라인 위·아래 이동이 동작한다.
- History 카드가 선택 행을 따라가며 기존 목록 배치를 바꾸지 않는다.
- 기존 Full Diff 포커스, History, Diff, Blame 동작이 깨지지 않는다.
