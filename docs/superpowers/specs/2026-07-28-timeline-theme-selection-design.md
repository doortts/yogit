# 기본 화면 테마 선택 설계

## 목표

기본 타임라인 화면에서 짙은 남색으로 느껴지는 배경을 걷어내고 Apple
플랫폼에 자연스럽게 어울리는 어두운 회색 계열로 바꾼다. 사용자가 고른
`System Graphite`를 기본값으로 삼고 기존 시안의 `Warm Graphite`와
`Carbon`도 설정에서 선택할 수 있게 한다.

세 테마는 같은 화면 계층과 상태 의미를 유지한다. 레이아웃, 간격, 글꼴
크기, 기능, 키보드 조작은 바꾸지 않는다.

## Apple 디자인 원칙

- 배경과 앞쪽 표면은 서로 다른 명도의 중립색으로 나눠 깊이를 드러낸다.
- 작은 글자는 배경과 최소 4.5:1 이상의 대비를 갖게 한다.
- 각 테마의 강조색은 선택 상태와 조작 가능한 요소에만 제한해서 쓴다.
- 경계선은 얇고 차분하게 유지한다. 경계선만으로 구역을 나누기보다 표면
  명도 차이를 함께 쓴다.
- 브랜치, 태그, 파일 상태처럼 의미가 있는 기존 색은 보존한다.
- 설정은 macOS 앱에서 익숙한 별도 `Appearance` 항목에 둔다.

참고:

- [Apple Human Interface Guidelines: Dark Mode](https://developer.apple.com/design/human-interface-guidelines/dark-mode)
- [Apple Human Interface Guidelines: Color](https://developer.apple.com/design/human-interface-guidelines/color)
- [Apple Human Interface Guidelines: Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)

## 범위

### 포함

- 기본 화면 바탕과 타임라인 목록
- 상단 도구 막대와 하단 상태 막대
- 왼쪽 브랜치·원격·태그 사이드바
- 열 머리글, 검색 입력창, 키 표시, 중립 상태 칩
- 기본 화면에 붙어 열리는 미리보기 패널
- 기본 화면에서 사용하는 저장소·기준 브랜치 메뉴
- 설정 사이드바의 `Appearance` 항목
- 세 가지 테마 미리보기 카드, 선택, 즉시 적용, 저장과 복원

### 제외

- Full Diff 화면의 전용 색상
- 설정 화면 자체의 전용 색상
- 구문 강조, 추가·삭제, 브랜치 그래프 색의 의미 체계
- 레이아웃, 크기, 애니메이션, 탐색 동작 변경
- 밝은 테마나 시스템 모양 자동 추종
- 실제 Liquid Glass나 흐림 효과 추가

## 테마

| 역할 | System Graphite | Warm Graphite | Carbon |
| --- | --- | --- | --- |
| 기본 바탕 | `#1C1C1E` | `#1D1C1B` | `#121213` |
| 도구·상태 막대 | `#242426` | `#282624` | `#1C1C1E` |
| 사이드바·열 머리글 | `#202022` | `#232220` | `#181819` |
| 입력창·앞쪽 표면 | `#2C2C2E` | `#302E2B` | `#272729` |
| 경계선 | `#38383A` | `#403E3A` | `#303033` |
| 기본 글자 | `#F2F2F7` | `#F3F1EE` | `#F5F5F7` |
| 보조 글자·아이콘 | `#AEAEB2` | `#B4B0AA` | `#B8B8BD` |
| 중립 칩 | `#2C2C2E` | `#302E2B` | `#272729` |
| 선택 행 | `#234D72` | `#44413C` | `#38383B` |
| 조작 강조 | `#0A84FF` | `#FF9F0A` | `#64D2FF` |

`System Graphite`의 선택 행은 시스템 블루를 중립 바탕과 섞어 채도를
낮춘다. `Warm Graphite`는 오렌지를 선택 표시와 조작 요소에만 쓰고
`Carbon`은 회색 선택 행에 밝은 청록 강조를 곁들인다. 날짜, 해시, 그래프
선처럼 Git 정보를 구분하는 기존 색에는 테마 강조색을 일괄 적용하지
않는다.

글자 대비는 다음과 같다.

| 테마 | 기본 글자/바탕 | 보조 글자/바탕 | 기본 글자/선택 행 |
| --- | ---: | ---: | ---: |
| System Graphite | 15.25:1 | 7.69:1 | 7.92:1 |
| Warm Graphite | 15.09:1 | 7.88:1 | 9.01:1 |
| Carbon | 17.19:1 | 9.48:1 | 10.73:1 |

## 설정 화면

현재 설정 사이드바에 `Appearance` 항목을 추가한다. `Appearance`를 열면
`System Graphite`, `Warm Graphite`, `Carbon` 카드가 같은 크기로 보인다.
각 카드에는 이름, 짧은 설명, 네 단계 표면색과 강조색을 압축한 미리보기를
넣는다.

카드를 누르면 선택 표시가 즉시 옮겨간다. 설정 화면 자체는 기존 전용
색상을 유지하고 미리보기 카드만 각 테마 색을 보여준다. 선택한 테마는
설정 뒤의 기본 화면에 바로 적용되며 `Done`으로 돌아왔을 때 이미 바뀐
상태가 보인다.

키보드 초점, Enter와 Space 선택, 선택 상태를 알리는 의미 정보도
제공한다. 색만으로 현재 테마를 구분하지 않고 선택 표시와 테마 이름을
함께 쓴다.

## 화면 요소별 적용

### 창과 도구 막대

도구 막대와 상태 막대는 각 팔레트의 앞쪽 표면색을 쓴다. 저장소와 기준
브랜치 조작부는 현재 구조를 유지한다. 눌림 영역이나 키 표시는 팔레트의
입력창 색을 써서 조작 가능한 요소임을 명도로 구분한다.

macOS 창 제어 버튼과 Yogit 글자색은 브랜드 요소이므로 그대로 둔다.

### 사이드바

사이드바는 팔레트의 사이드바 색으로 바탕과 구분한다. 섹션 아이콘과 개수,
접기 화살표는 팔레트의 보조 글자색을 쓴다. 브랜치 끝점의 그래프 색과
태그 상태색은 정보를 나타내므로 바꾸지 않는다.

선택한 브랜치 행은 현재 테마의 선택 행 색을 쓴다. 선택되지 않은 행에는
강조색 배경을 넣지 않는다.

### 타임라인

열 머리글은 사이드바와 같은 표면색을 써서 기능 영역으로 묶는다. 커밋
목록은 현재 테마의 기본 바탕을 쓴다. 날짜 구분, 해시, 브랜치 선, 파일
상태색은 뜻이 있는 색이므로 현재 값을 유지한다.

선택 행은 팔레트의 선택 행 색으로 채우고 기본 글자색으로 표시한다. 선택
행 외곽이나 강한 그림자는 추가하지 않는다.

### 미리보기

미리보기 패널도 기본 화면에 속하므로 바탕, 제목 영역, 경계선, 파일 선택
행을 같은 팔레트로 바꾼다. diff의 추가·삭제 색과 파일 상태 글자색은
유지한다. 미리보기에서 Full Diff로 전환하면 Full Diff 전용 테마를 그대로
쓴다.

## 구현 구조

### 선택한 방식

`ThemeExtension`으로 기본 화면 팔레트를 제공한다. 앱 전체의 `ThemeData`를
교체하면 Full Diff와 설정까지 영향을 받을 수 있고 색을 위젯마다 인자로
넘기면 타임라인의 여러 하위 위젯과 페인터에 전달할 값이 지나치게 많아진다.
전역 변경 가능한 팔레트는 테스트가 서로 영향을 줄 수 있어 쓰지 않는다.

`TimelineThemeKind`는 저장값과 사용자용 이름을 가진다.
`TimelineThemePalette`는 열 가지 역할 색을 불변 값으로 제공한다. 기본
화면은 현재 설정에 맞는 확장을 넣은 지역 `Theme` 아래에서 그린다. 직접
색을 받는 페인터와 순수 함수에는 현재 팔레트의 필요한 색만 생성 시점에
넘긴다.

Full Diff의 `full_diff_theme.dart`와 설정 화면의 전용 색상은 바꾸지 않는다.
설정의 테마 카드만 세 팔레트를 직접 미리보기로 사용한다.

### 설정 저장

`AppSettings`에 `timelineTheme`을 추가한다. 저장값은 다음과 같다.

- `systemGraphite`
- `warmGraphite`
- `carbon`

설정 파일에 값이 없거나 알 수 없는 값이면 `systemGraphite`를 쓴다. 기존
사용자는 별도 변환 절차 없이 새 기본값을 받는다.

### 변경 흐름

1. 앱이 설정 파일에서 `timelineTheme`을 읽는다.
2. 기본 화면에 해당 팔레트가 들어간 지역 `Theme`을 적용한다.
3. 사용자가 `Settings > Appearance`에서 카드를 선택한다.
4. `AppSettings.copyWith`가 새 값을 만들고 현재 저장 흐름으로 전달한다.
5. 기본 화면이 새 팔레트로 다시 그려지고 설정 파일에 값이 저장된다.
6. 저장에 실패해도 현재 실행 중 선택은 유지하는 기존 정책을 따른다.

## 상태와 오류 처리

로딩, 비활성, 오류 상태는 기존 문구와 아이콘을 유지하되 현재 팔레트의
기본 글자와 보조 글자 색을 적용한다. 손상된 테마 저장값은 오류를 띄우지
않고 `System Graphite`로 돌아간다.

## 구현 순서

1. `System Graphite`를 기본 팔레트로 만들고 기본 화면의 기존 색을 역할별
   팔레트 참조로 바꾼다.
2. `Warm Graphite`와 `Carbon` 팔레트를 추가한다.
3. 설정 저장과 `Appearance` 선택 화면을 연결한다.
4. 세 테마와 기존 화면을 함께 검증한다.

중간 단계에서 기본 테마만 동작하더라도 최종 결과는 세 테마 선택과 저장을
한 번에 포함한다.

## 검증

- 세 팔레트의 역할 색과 대비를 단위 테스트로 확인한다.
- 설정값이 JSON을 왕복하고 누락되거나 손상된 값이 기본값으로 돌아가는지
  확인한다.
- `Appearance` 카드가 현재 값을 표시하고 마우스와 키보드 선택을
  `onChanged`에 전달하는지 확인한다.
- 테마를 바꿔도 타임라인 선택, 스크롤, 미리보기 상태가 유지되는지
  확인한다.
- 각 테마에서 기본 화면, 사이드바 선택, 타임라인 선택, 미리보기 선택
  상태를 확인한다.
- Full Diff와 설정 화면의 전용 팔레트가 바뀌지 않았는지 관련 테스트로
  확인한다.
- `flutter analyze`와 전체 `flutter test`를 실행한다.
- 기본 화면을 세 테마로 캡처해 승인된 시안과 나란히 비교한다.

## 완료 조건

1. 새 설치와 기존 사용자의 기본 화면은 `System Graphite`로 열린다.
2. 설정의 `Appearance`에서 세 테마를 선택할 수 있다.
3. 선택 즉시 기본 화면에 적용되고 다음 실행에도 유지된다.
4. 세 테마 모두 남색 중심 배경 대신 승인된 어두운 회색 계층을 쓴다.
5. Git 상태와 브랜치 그래프의 의미 색은 유지된다.
6. Full Diff와 설정 화면은 기존 전용 테마를 유지한다.
7. 기존 조작과 테스트가 그대로 통과한다.
