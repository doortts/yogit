커밋 찾기 — 글자에서 낱말로

지금 ⌘F 찾기는 제목을 글자 단위로 훑는다. 질의의 글자가 순서만 지키면 어디에 흩어져 있어도 찾은 것으로 친다. 이름을 고를 때는 쓸 만한 규칙이지만, 문장 하나를 두고 쓰면 아무 관계 없는 커밋이 결과에 섞인다. 규칙을 낱말 단위로 바꾸고, 질의에 공백이 있으면 낱말마다 따로 찾아 순서를 묻지 않는다. 아래 예시는 손으로 적은 것이 아니라 이 저장소의 커밋 500개에 규칙을 실제로 돌린 결과다.

⌕ name hover 1/3 ⌃ ⌄ ✕

찾기 줄은 그대로다. 바뀌는 것은 그 안에서 무엇을 결과로 삼느냐뿐이다.

규칙 제목

  1. 질의를 공백으로 쪼갠다. name hover는 낱말 둘이다. 공백이 없으면 낱말 하나.
  2. 대상도 낱말로 쪼갠다. 글자와 숫자의 연속이 낱말이고, 나머지는 모두 구분자다 — fix(merge):는 fix와 merge, full_diff는 full과 diff.
  3. 질의의 낱말이 대상의 어느 낱말 안에 통째로 들어 있으면 그 낱말은 찾힌 것이다. 낱말 안 어디든 좋다: nam은 name에서, 커밋은 커밋을에서 찾힌다.
  4. 질의의 낱말이 모두 찾히면 그 행이 결과다. 어느 낱말이 대상의 어느 낱말에서 찾히든 순서는 묻지 않는다 — name hover와 hover name은 같은 결과를 낸다.
  5. 대소문자는 무시한다. 빈 질의는 아무것도 찾지 않는다 — 지금과 같다.

한 낱말이 여러 낱말에 걸쳐 있을 수는 없다. mrgfix는 이제 아무것도 찾지 못한다. 그것이 이 변경의 값이자 값이 치르는 대가다: 흩어진 글자로 얻던 관용을 잃고, 대신 결과에 든 행은 모두 이유를 하나씩 보여 준다.

칠해진 글자가 곧 불이 켜질 자리다. 분홍 표시가 붙은 줄이 두 규칙의 답이 갈리는 자리이고, 모두 이 저장소에 실제로 있는 커밋 제목이다.

해시는 그대로 변경 없음

해시는 산문이 아니라서 낱말로 쪼개지 않는다. 지난 수정 그대로, 그린 일곱 자리 안에 들어 있으면 그 자리에 불이 켜지고, 통째로 붙여 넣은 긴 해시는 앞자리로 알아본다. 질의에 낱말이 여럿이면 낱말 하나하나가 제목에서든 해시에서든 답을 찾으면 된다 — 89d 카드처럼 해시와 제목을 함께 좁힐 수 있다.

같은 질의를 이 저장소의 커밋 500개에 돌린 결과다. 글자 단위는 해시까지 훑던 시절의 숫자가 아니라 제목과 해시를 지금 규칙대로 센 것이다.

fix처럼 정말 흔한 낱말은 두 규칙 모두 많이 잡는다. 갈리는 것은 card·nam처럼 짧은 질의다 — 글자 단위는 아무 문장에서나 그 글자들을 주워 담는다.

안 바꾸는 것

  1. 사이드바 브랜치·태그 필터와 저장소 고르기는 지금의 글자 단위 그대로 둔다. 거기서 notsp가 notes-split-pane을 찾는 것은 이름을 고르는 자리에서 실제로 쓰이는 관용이다. 바뀌는 것은 커밋 찾기 하나다.
  2. 불이 켜지는 방식, 결과 사이를 걷는 Enter·⇧Enter, 세는 3/17, 행을 거르지 않는다는 것 — 모두 그대로다.

정해 주셔야 할 것 하나

낱말 안 어디든(nam → name, 진행 → 재진행) 찾을지, 낱말의 앞에서만 찾을지입니다. 위 예시는 모두 안 어디든으로 돌린 것입니다. 앞에서만 찾게 하면 결과가 더 줄지만 한국어의 앞가지 (재-)와 영어의 접두(sub-)를 놓칩니다.
