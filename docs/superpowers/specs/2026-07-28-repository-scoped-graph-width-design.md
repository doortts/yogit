# 저장소별 그래프 컬럼 폭 설계

## 목표

타임라인을 처음 열 때 그래프 컬럼을 자동으로 맞추되, 가장 오른쪽에 그려지는 커밋 노드와 해시 컬럼 왼쪽의 컬러선 사이에 최소 3픽셀을 남긴다. 사용자가 그래프 컬럼 폭을 직접 조절한 저장소는 마지막 수동 폭을 앱을 다시 실행한 뒤에도 그대로 복원한다.

## 현재 동작

- `TimelineColumnWidths.graph`가 `null`이면 화면에 나타난 가장 깊은 그래프 레인을 기준으로 컬럼 폭을 자동 계산한다.
- 사용자가 그래프 컬럼 구분선을 움직이면 `TimelineColumnWidths.graph`에 고정 폭을 저장한다.
- 현재 고정 폭은 모든 저장소가 공유하는 `columnWidths.graph`에 저장된다. 따라서 한 저장소에서 조절한 폭이 다른 저장소에도 적용된다.
- 자동 폭은 가장 오른쪽 노드의 반지름 뒤에 2픽셀만 남긴다.

## 선택한 방식

기존 `settings.json`에 저장소 루트별 그래프 폭을 저장하는 표를 추가한다. 나머지 타임라인 컬럼 폭은 지금처럼 모든 저장소가 공유한다.

```json
{
  "columnWidths": {
    "refs": 156,
    "hash": 78
  },
  "repositoryGraphWidths": {
    "/Users/example/repos/project-a": 142,
    "/Users/example/repos/project-b": 188
  }
}
```

저장소 키는 Git 저장소를 열 때 이미 확인한 절대 루트 경로를 그대로 사용한다. 같은 저장소를 하위 디렉터리에서 열어도 Git 루트가 같으므로 같은 폭을 복원한다. 별도 워크트리는 루트 경로가 다르므로 각자 폭을 저장한다.

## 설정 모델

`AppSettings`에 `Map<String, double> repositoryGraphWidths`를 추가한다.

- JSON에서 숫자인 값만 읽는다.
- 저장된 폭은 그래프 컬럼 범위인 40~260픽셀로 제한한다.
- 빈 경로와 숫자가 아닌 값은 버린다.
- 직렬화할 때는 저장소별 폭을 `repositoryGraphWidths`에 기록한다.
- 전역 `columnWidths.graph`는 새 형식으로 저장하지 않는다.

현재 저장소에 적용할 폭과 수동 변경을 저장하는 동작은 `AppSettings`의 작은 메서드로 묶는다.

- `columnWidthsForRepository(root)`는 공통 컬럼 설정에 해당 저장소의 그래프 폭만 합쳐 반환한다.
- `withRepositoryColumnWidths(root, widths)`는 공통 컬럼 설정을 갱신하고 `widths.graph`가 있으면 해당 저장소의 그래프 폭을 함께 갱신한다.

이 경계 덕분에 `TimelineScreen`은 기존처럼 `TimelineColumnWidths`만 사용하며 저장소별 설정 구조를 알 필요가 없다.

## 이전 버전 설정 이전

이전 버전의 `columnWidths.graph`에 전역 수동 폭이 남아 있고 `repositoryGraphWidths`가 비어 있으면, 업데이트 후 처음 연 저장소에 그 폭을 한 번 이전한다.

1. 설정을 읽은 뒤 현재 저장소 루트에 이전 전역 폭을 기록한다.
2. 공통 `columnWidths.graph`는 `null`로 바꾼다.
3. 변환한 설정을 즉시 저장한다.

이미 저장소별 폭이 하나라도 있으면 이전이 끝난 설정으로 보고 전역 폭을 다시 사용하지 않는다. 손상된 설정 때문에 두 값이 함께 남아 있더라도 저장소별 값이 우선한다.

## 자동 폭 계산

자동 맞춤은 현재 화면에 나타난 가장 깊은 레인을 기준으로 기존처럼 한 방향으로만 넓어진다. 최소 폭 96픽셀과 최대 폭 260픽셀도 유지한다.

가장 오른쪽에 그려질 수 있는 요소는 지름 22픽셀의 커밋 노드다. 노드 중심에서 오른쪽 끝까지 11픽셀이고, 컬럼 경계가 해시 컬럼 컬러선의 시작점이므로 자동 폭은 다음과 같이 계산한다.

```text
레인 중심 위치 + 노드 반지름 11픽셀 + 여백 3픽셀
```

따라서 자동 폭 계산에 쓰는 오른쪽 여유는 기존 13픽셀에서 14픽셀로 바뀐다. 사용자가 저장한 수동 폭에는 이 보정을 적용하지 않는다. 수동 폭은 사용자가 정한 값을 그대로 복원한다.

## 데이터 흐름

1. 앱이 설정과 현재 Git 저장소 루트를 읽는다.
2. 이전 형식의 전역 그래프 폭이 있으면 현재 저장소 값으로 이전한다.
3. 현재 저장소의 수동 폭이 있으면 `TimelineScreen`에 고정 폭으로 전달한다.
4. 수동 폭이 없으면 `graph: null`을 전달해 자동 맞춤을 사용한다.
5. 사용자가 그래프 구분선을 움직이면 현재 저장소 루트에 새 폭을 저장한다.
6. 저장소를 바꾸면 새 루트로 설정을 다시 조회한다.

## 오류 처리

- 설정 파일이 없거나 JSON이 손상되면 기존 기본 설정을 사용한다.
- 저장소별 폭 표의 일부 항목만 잘못된 경우 올바른 항목은 유지하고 잘못된 항목만 버린다.
- 설정 저장 실패는 현재 앱의 오류 처리 방식을 유지한다. 화면에는 이미 적용한 폭을 유지하고 앱 동작을 막지 않는다.

## 테스트

다음 동작을 자동 테스트로 고정한다.

1. 저장소별 그래프 폭이 JSON을 거쳐 그대로 복원되고 범위를 벗어난 값은 제한된다.
2. 이전 전역 폭이 업데이트 후 처음 연 저장소로 한 번 이전된다.
3. 저장소 A에서 조절한 폭은 A를 다시 열 때 복원된다.
4. 저장소 A의 폭이 저장소 B에 적용되지 않으며 B는 자동 맞춤으로 시작한다.
5. 저장소 B에서 별도로 조절한 폭도 A의 값과 독립적으로 저장된다.
6. 자동 맞춤 폭은 가장 오른쪽 22픽셀 노드와 해시 컬러선 사이에 정확히 3픽셀 이상을 확보한다.
7. 기존 그래프 폭 조절, 컬럼 설정 저장, 저장소 전환 테스트가 계속 통과한다.

## 범위 밖

- 다른 타임라인 컬럼을 저장소별로 나누지 않는다.
- 사용자가 저장소별 폭을 초기화하는 별도 메뉴를 추가하지 않는다.
- 저장소 설정을 `.git/config`나 저장소 내부 파일에 기록하지 않는다.
- 수동 폭을 자동으로 보정하거나 다시 계산하지 않는다.
