머리줄은 정확한 수를 말해야 한다. 목록이 여덟에서 잘려도 “42개 들어옴”은 42여야 한다.		 git 1회
오간 커밋 git log --left-right --oneline -n 9 old...new
한 번에 양쪽을 </>로 갈라 준다. 아홉을 읽어 여덟을 세우면 아홉째의 존재가 곧 “더 있다”는 뜻이다.		 git 1회

움직인 브랜치 하나당 git 3회, 그것도 변화가 감지된 순간에만. 커밋 목록은 브랜치가 하나만 움직였을 때만 가져오므로 그 경우가 3회, 여럿이면 브랜치마다 2회다. 자세히 묻는 브랜치는 셋까지다 — 터미널이 열둘을 건드려도 스물넷을 넘지 않는다. 그 직후 앱은 어차피 타임라인 전체를 다시 읽으므로 이 몇 번은 그 재적재에 묻힌다.

실패하면 계약 6번으로 물러난다 — 감시자가 화면을 깨는 물건이 되어서는 안 된다.
