받기와 올리기 — 기준 브랜치의 upstream 동기화

묻기 전에 답해 둔다. 기준 브랜치가 upstream과 어긋나 있으면 그 사실이 이미 재어져 있고, 버튼은 ‘무엇을 하겠다’가 아니라 ‘하면 어떻게 되는지’를 입고 있다. 동기화되어 있을 때는 아무것도 말하지 않는다 — 침묵이 곧 ‘다 맞다’는 대답이다.

자리 툴바 · 기준 브랜치 곁

이 상태는 기준 브랜치의 속성이므로 기준 브랜치 선택기 바로 오른쪽에 선다. 사이드바 스트립은 커서가 짚은 ref의 것이고 상태바는 부고란이다 — 대표 기능은 브랜치 이름 옆에서 그 브랜치를 말해야 한다. 창이 좁아지면 장식(문구·키캡)이 먼저 물러나고 캡슐은 남는다.

상태 여섯 한 사실, 두 문

판정의 재료는 upstream 대비 ahead(로컬에만 있는 커밋)와 behind(원격에만 있는 커밋) 둘뿐이고, 어긋났을 때(ahead>0 ∧ behind>0)의 물음은 하나로 수렴한다 — 로컬 커밋이 원격 끝 위에 깨끗이 얹히는가. 숨은 worktree에서 한 번 재연해 보면(브랜치 diff의 재배치 미리보기와 같은 부품) 받기와 올리기 두 버튼의 답이 동시에 나온다.

동기화됨 · ahead 0, behind 0 tooltip: origin/main과 같습니다 · 4분 전에 확인
올릴 것만 · ahead 3, behind 0 ↑ 3 올리기 tooltip: 그대로 올릴 수 있습니다 — 커밋 3개
받을 것만 · ahead 0, behind 2 ↓ 2 받기 tooltip: 빨리감기로 받습니다 — 커밋 2개
어긋남, 깨끗 · 3↕2, 재연 성공 ↓ 2 받아 얹기 ↑ 3 올리기 tooltip(올리기): 2개를 받아 얹은 뒤 충돌 없이 올릴 수 있습니다
어긋남, 충돌 · 3↕2, 재연 실패 ↓ 2 충돌 2파일 ↑ 3 tooltip: 빨리감기는 불가, 받아 얹으면 lib/a.dart 외 1개가 충돌합니다
upstream 없음 ↑ 처음 올리기 tooltip: origin에 main을 만들고 추적을 연결합니다 (push -u)

재는 동안은 판정 색 없이 숫자만 희미하게 선다(↓ 2 ↑ 3 …) — 스피너 없음. 판정은 fetch가 끝날 때, 그리고 두 끝(tip) 중 하나가 움직일 때마다 다시 잰다.

누르면 확인 한 번, 실행 한 번

초록 버튼은 묻지 않고 해도 안전한 일이지만, 원격을 움직이는 일은 되돌리기 어려우므로 올리기만 확인을 거친다. 받기(빨리감기)는 로컬만 움직이니 바로 실행한다. 주황 올리기는 두 걸음(받아 얹기 → 올리기)을 하나의 물음으로 묶는다. 빨간 버튼은 실행이 아니라 충돌 파일 목록을 여는 문이다 — 해결 흐름은 다음 단계.

실행 방식 — 체크아웃을 옮기지 않는다

  • 기준 브랜치가 체크아웃되어 있지 않을 때: 받기(빨리감기)는 git fetch origin main:main으로 ref만 전진시키고, 받아 얹기는 브랜치 diff 적용과 같은 숨은 worktree에서 재연을 실현한 뒤 ref만 옮긴다. 작업 트리는 더럽든 말든 상관없다 — 이 앱의 기존 약속 그대로.
  • 체크아웃되어 있을 때: 작업 트리를 실제로 움직여야 하므로, 트리가 더럽고 받을 내용과 겹치면 실행을 거절하고 이유를 말한다. 몰래 stash하지 않는다.
  • 재연(dry-run)은 기준 브랜치 하나에 대해서만, 어긋났을 때만, 한 번에 하나만 돈다. (로컬 tip, 원격 tip) 쌍이 같으면 다시 재지 않는다.

계약

  • 동기화 상태에서 캡슐은 동사를 보이지 않는다 — 점 하나뿐.
  • ahead만 있으면 올리기 하나, behind만 있으면 받기 하나. 개수는 항상 판정 색과 함께.
  • 어긋나면 재연이 끝날 때까지 숫자는 무채색이고, 끝나면 두 버튼이 같은 판정을 입는다.
  • 빨간 버튼을 눌러도 아무것도 실행되지 않는다 — 충돌 파일 목록만 연다.
  • 올리기는 항상 확인을 거치고, 확인문에는 원격 ref가 어디서 어디로 움직이는지 해시가 적힌다.
  • 받기(빨리감기)는 확인 없이 즉시. 완료는 상태바가 아니라 타임라인 자체가 말한다 — 행이 늘어난다.
  • tooltip에는 언제 잰 판정인지가 적힌다.

정해 주셔야 할 것

  1. 주황 올리기의 한 번 누름 — 받아 얹기와 올리기를 한 확인으로 묶어 실행(시안) vs 알려만 주고 실행은 두 단계로.
  2. 재연 자동 실행 — fetch 후 어긋남이 보이면 자동으로 잰다(시안) vs 캡슐에 커서를 올릴 때 잰다.
  3. 충돌 파일 목록의 다음 단계 — v1은 목록만(시안) vs 브랜치 diff의 충돌 해결 흐름으로 바로 연결.
