# 브랜치 병합 결과 미리보기 설계

## 목표

브랜치 비교 결과를 하단 상태 표시줄에서 커밋 타임라인 상단으로 옮긴다. 비교 화면의 첫 행에는 가상 머지 커밋을 표시하고 사용자가 이 행을 선택하면 기준 브랜치에 비교 브랜치를 병합했을 때 생길 파일 목록과 diff를 미리보기에서 확인할 수 있어야 한다.

이 기능은 실제 브랜치, 인덱스, 작업 트리, 커밋을 변경하지 않는다.

## 확정한 화면 구성

브랜치 비교를 시작하면 타임라인 열 제목 아래에 비교 요약 영역을 표시한다.

- 병합 방향: `비교 브랜치 → 기준 브랜치`
- 기준 브랜치에만 있는 커밋 수
- 비교 브랜치에만 있는 커밋 수
- 공통 조상 수
- 병합 충돌 여부
- 리베이스 가능 여부

기존 비교 상태 표시줄에 있던 정보는 모두 이 영역으로 옮긴다. 하단 상태 표시줄은 일반 타임라인과 같은 범례와 현재 선택 정보를 표시한다.

비교 요약 아래 첫 행에는 `MERGE PREVIEW` 가상 행을 추가한다.

- 두 브랜치 선이 빈 점선 노드로 합쳐져 실제 머지 커밋과 구분된다.
- 해시 칸에는 `VIRTUAL`을 표시한다.
- 메시지는 `Merge <compare> into <base>` 형식을 사용한다.
- 브랜치 비교를 열면 이 행을 기본 선택한다.
- 위·아래 화살표 이동 순서에 포함한다.
- 가상 행은 실제 Git 커밋이 아니며 복사, 전체 diff 열기, 커밋 메시지 조회 같은 커밋 전용 기능을 실행하지 않는다.

미리보기 헤더는 가상 행을 선택했을 때 `병합 결과 미리보기`로 바뀐다. 본문에는 다음 내용을 표시한다.

- 병합 충돌 여부
- 병합 방향
- 기준 브랜치와 비교한 변경 파일 수, 추가 줄 수, 삭제 줄 수
- 병합 결과의 변경 파일 목록
- 선택한 파일의 병합 결과 diff

일반 비교 커밋을 선택했을 때의 기존 브랜치 diff 미리보기는 유지한다.

## 병합 결과 계산

현재 `GitRepository.compareBranches`는 이미 `git merge-tree --write-tree`로 충돌 여부를 검사한다. 같은 명령의 성공 결과에 포함된 트리 SHA를 버리지 않고 병합 미리보기에 사용한다.

충돌이 없는 흐름은 다음과 같다.

1. `git merge-tree --write-tree --name-only -z <baseTip> <compareTip>`를 실행한다.
2. 출력의 첫 필드에서 병합 결과 트리 SHA를 읽는다.
3. 기존 파일 비교 로직으로 `<baseTip>`과 병합 결과 트리를 비교해 파일 목록과 통계를 만든다.
4. 파일을 선택하면 기존 `loadDiffBetween`에 `<baseTip>`과 병합 결과 트리 SHA를 넘겨 diff를 읽는다.

병합 결과는 반드시 기준 브랜치의 tip과 비교한다. 현재처럼 기준 브랜치 tip과 비교 브랜치 tip을 직접 비교하면 기준 브랜치에만 있는 변경까지 제거된 것처럼 보일 수 있어서 실제 병합 결과와 다르다.

`BranchComparisonResult`에는 충돌이 없을 때만 다음 값을 보관한다.

- 병합 결과 트리 SHA
- 기준 브랜치와 병합 결과 트리 사이의 변경 파일 목록

새 저장소 계층이나 임시 worktree는 만들지 않는다. 기존 `merge-tree`, 파일 목록 파서, `loadDiffBetween`을 그대로 사용한다.

## 타임라인과 선택 상태

가상 머지 행은 비교 타임라인에만 존재하는 UI용 합성 항목이다. 실제 커밋과 섞여도 커밋 전용 Git 명령에 전달되지 않도록 명시적인 `isMergePreview` 표식을 둔다.

선택에 따른 미리보기 데이터는 다음처럼 나눈다.

| 선택 항목 | 파일 목록과 diff |
| --- | --- |
| 가상 머지 행 | `baseTip → mergedTree` |
| 일반 비교 커밋 | 기존 브랜치 비교 동작 |

비교 브랜치나 기준 브랜치가 바뀌면 기존 직렬 번호 검사를 그대로 사용해 이전 요청의 늦은 응답을 버린다. 새 비교가 시작되면 가상 행을 선택하고 파일 선택과 diff 캐시를 새 비교 키로 분리한다.

## 상태별 동작

### 계산 중

비교 요약에는 `브랜치 비교 중`과 `병합 검사 중`을 표시한다. 병합 결과 트리가 아직 없으므로 가상 행의 파일 목록에는 로딩 상태를 표시한다.

### 충돌 없음

가상 행을 선택할 수 있고 최종 파일 목록과 diff를 표시한다. fast-forward가 가능한 경우에도 최종 상태를 확인하는 목적은 같으므로 가상 행을 유지한다.

### 충돌 발생

해결 방법이 정해지기 전에는 하나의 최종 트리가 존재하지 않는다. 따라서 완성된 diff를 가장하지 않는다.

- 가상 행은 `MERGE CONFLICT`로 표시한다.
- 미리보기에는 충돌 파일 목록을 표시한다.
- diff 영역에는 `충돌을 해결해야 최종 결과를 계산할 수 있습니다`를 표시한다.

### 검사 실패

비교 요약에 `병합 검사 실패`를 표시한다. 가상 행은 만들지 않고 기존 비교 커밋은 계속 볼 수 있게 한다.

## 키보드와 접근성

- 비교 화면을 열면 가상 머지 행이 선택된다.
- 위·아래 화살표로 가상 행과 실제 비교 커밋 사이를 이동한다.
- `Enter`와 `Space`는 기존처럼 미리보기를 열고 닫는다.
- 가상 행과 충돌 상태는 색만으로 구분하지 않고 `MERGE PREVIEW`, `MERGE CONFLICT`, `VIRTUAL` 문구를 함께 표시한다.
- 비교 요약의 상태 문구는 화면 읽기 도구가 한 덩어리의 비교 결과로 읽을 수 있게 의미 단위로 구성한다.

## 변경 범위

- `lib/git.dart`
  - `merge-tree`가 반환한 병합 결과 트리 SHA 보존
  - 기준 브랜치와 병합 결과 트리 사이의 파일 목록 계산
- `lib/timeline.dart`
  - 타임라인 상단 비교 요약
  - 가상 머지 행과 선택 처리
  - 병합 결과 파일 목록과 diff 미리보기
  - 비교 결과를 하단 상태 표시줄에서 제거
- `test/git_test.dart`
  - 병합 결과 트리와 파일 목록 검증
- `test/app_test.dart`
  - 상단 요약, 가상 행, 키보드 이동, 미리보기, 충돌 상태 검증

새 의존성은 추가하지 않는다.

## 테스트 기준

다음 동작을 자동 테스트로 남긴다.

1. 충돌이 없으면 `merge-tree`의 트리 SHA를 읽고 `baseTip → mergedTree` 파일 목록을 반환한다.
2. 기준 브랜치에만 있는 변경은 병합 결과 diff에서 삭제로 나타나지 않는다.
3. 비교 화면 상단에 요약이 보이고 하단에는 비교 지표가 남지 않는다.
4. 가상 머지 행이 첫 행으로 선택되며 아래 화살표로 첫 실제 커밋으로 이동한다.
5. 가상 행의 파일 목록과 diff는 병합 결과 트리를 사용한다.
6. 충돌이 나면 충돌 파일 목록만 보이고 최종 diff를 표시하지 않는다.
7. 검사 실패 뒤에도 실제 비교 커밋은 계속 탐색할 수 있다.

## 완료 조건

- 브랜치 비교 결과를 타임라인 상단에서 한눈에 확인할 수 있다.
- 가상 머지 행을 선택하면 실제 변경 없이 병합 후 파일 목록과 diff를 확인할 수 있다.
- 충돌이 있을 때 존재하지 않는 최종 결과를 표시하지 않는다.
- 일반 타임라인과 기존 브랜치 비교 탐색 동작이 깨지지 않는다.

## 제외 범위

- 실제 merge, rebase, commit 실행
- 충돌 해결 편집기
- 가상 머지 결과의 전체 Diff 화면
- 비교 요약 접기와 크기 저장
