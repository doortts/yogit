# 삭제된 브랜치 이름 복구 설계

## 목표

현재 Git 참조가 사라져 타임라인에 이름이 나오지 않는 브랜치 선의
이름을 가능한 범위에서 복구한다. 사용자가 해당 선의 커밋을 선택하면
`BRANCH / TAG` 칸에 옅은 붉은색 `삭제됨` 배지와 찾은 브랜치 이름을
표시한다.

이름은 필요한 순간에만 조회한다. 한 번 찾은 결과는 저장소별로
캐시에 저장해 앱을 다시 실행한 뒤에도 재사용한다.

## 확정한 제품 결정

- 조회 순서는 캐시, 로컬 Git 기록, GitHub 또는 GitHub Enterprise의
  PR 기록이다.
- 앱을 시작할 때 모든 과거 브랜치를 미리 조회하지 않는다.
- 현재 브랜치나 태그로 이름을 알 수 있으면 기존 Git 참조를 우선한다.
- 복구한 이름은 선택한 커밋 행에만 표시한다.
- `삭제됨`은 옅은 붉은색 배지로 표시한다.
- 조회 실패는 경고창으로 알리지 않으며 현재 화면을 유지한다.
- 성공한 결과만 영구 캐시에 저장한다.

## 범위

### 포함

- 그래프의 브랜치 선에서 마지막 커밋 SHA 찾기
- 저장소별 영구 캐시 읽기와 저장
- 머지 커밋 제목에서 브랜치 이름 찾기
- 로컬 `HEAD` reflog에서 브랜치 이름 찾기
- 기존 `gh` 연동을 이용한 GitHub와 GitHub Enterprise PR 조회
- 선택한 커밋 행의 조회 중 상태, `삭제됨` 배지와 브랜치 이름
- 선택이 바뀐 뒤 도착한 비동기 결과를 무시하는 처리

### 제외

- 앱 시작 시 전체 커밋이나 전체 PR 기록 미리 조회
- GitLab, Bitbucket 등 새 원격 서비스 연동
- 사용자가 캐시를 편집하거나 지우는 별도 설정 화면
- 찾지 못한 브랜치 이름을 사용자가 직접 입력하는 기능
- 복구한 이름을 실제 Git 브랜치로 다시 만드는 기능
- 캐시 만료 시각과 별도 정리 정책

## 기존 구조 활용

새 패키지나 범용 캐시 계층은 추가하지 않는다.

- `GraphRow.branch`는 한 브랜치 선이 이어지는 동안 유지되는 식별자로
  사용한다.
- `GitRepository`에 로컬 기록 조회만 추가한다.
- 기존 `RemoteRepository`와 `AvatarService`의 `gh api --hostname`
  실행 방식을 재사용한다.
- 영구 캐시는 기존 `AppSettings`와 `SettingsStore`의
  `settings.json`에 저장한다.
- 화면 상태와 조회 시작 시점은 기존 `TimelineScreen`에서 관리한다.

## 브랜치 선과 캐시 키

선택한 커밋의 `GraphRow.branch`와 같은 값을 가진 실제 커밋 행 가운데
시간상 가장 위에 있는 행을 해당 브랜치 선의 마지막 커밋으로 본다.
커밋되지 않은 작업 트리 행은 제외한다. 마지막 커밋의 SHA를
`tipSha`로 사용한다.

조회 전에 `tipSha`에 현재 로컬 브랜치, 원격 브랜치 또는 태그가
붙어 있는지 확인한다. 참조가 있으면 기존 이름을 표시하고 삭제된
브랜치 조회를 실행하지 않는다.

영구 캐시는 다음 모양으로 저장한다.

```text
repository root
  └─ tip SHA → branch name
```

저장소 루트를 첫 키로 사용해 서로 다른 저장소에서 같은 SHA나 브랜치
이름이 섞이지 않게 한다. 브랜치 선의 마지막 SHA를 사용하므로 같은
선에서 다른 커밋을 선택해도 같은 결과를 재사용할 수 있다.

이름을 찾지 못한 결과는 영구 저장하지 않는다. 같은 앱 실행 중에는
`repository root + tip SHA`를 조회 시도 목록에 넣어 같은 선을
반복해서 선택해도 원격 요청을 다시 보내지 않는다. 앱을 다시
실행하면 실패한 조회를 다시 시도할 수 있다.

현재 Git 참조와 캐시가 모두 있으면 현재 Git 참조를 사용한다. 따라서
같은 SHA를 가리키는 브랜치가 나중에 다시 생겨도 `삭제됨` 표시가
남지 않는다.

## 조회 흐름

이름 없는 브랜치 선의 커밋을 선택하면 다음 순서로 조회한다.

1. `AppSettings`의 저장소별 캐시를 확인한다.
2. 현재 읽어 둔 머지 커밋과 로컬 `HEAD` reflog를 확인한다.
3. 이름을 찾지 못했고 지원하는 `origin`이 있으면 PR 기록을 조회한다.
4. 이름을 찾으면 캐시에 저장하고 현재 선택이 그대로일 때만 화면에
   반영한다.

조회는 타임라인 로딩과 커밋 선택을 막지 않는다.

### 머지 커밋 제목

선택한 선의 `tipSha`가 첫 번째 부모가 아닌 부모로 연결된 머지
커밋을 찾는다. 다음처럼 Git과 GitHub가 만드는 형식만 해석한다.

```text
Merge branch 'feature/name'
Merge remote-tracking branch 'origin/feature/name'
Merge pull request #123 from owner/feature/name
```

일반 커밋 메시지에 우연히 들어간 브랜치 이름은 사용하지 않는다.
원격 추적 브랜치 형식에서는 원격 이름을 제외한 실제 브랜치 이름을
저장한다.

### 로컬 reflog

`HEAD` reflog를 최신 항목부터 읽으며 다음 형식을 확인한다.

```text
checkout: moving from <branch> to <target>
```

체크아웃 직전 SHA가 `tipSha`와 같을 때 `<branch>`를 복구한 이름으로
사용한다. `HEAD`, SHA처럼 브랜치 이름이 아닌 값은 제외한다. reflog가
만료됐거나 저장소 설정 때문에 남아 있지 않으면 다음 단계로 넘어간다.

### GitHub와 GitHub Enterprise PR 기록

기존 `origin` 해석 결과에서 호스트, 소유자와 저장소 이름을 얻는다.
기존 `gh api --hostname` 실행 경로로 `tipSha`와 연결된 PR을 조회한다.

- 병합된 PR만 후보로 사용한다.
- PR의 `head.sha`가 `tipSha`와 같은 후보를 우선한다.
- 같은 우선순위의 후보가 여러 개면 `merged_at`이 가장 최근인 PR을
  사용한다.
- 선택한 PR의 `head.ref`를 브랜치 이름으로 저장한다.

`gh`가 없거나 로그인되지 않은 경우, 지원하지 않는 원격 주소, 요청
실패와 호출 제한은 이름을 찾지 못한 경우로 처리한다. 새 인증 화면이나
오류 창은 열지 않는다.

## 화면 표시

복구 대상 커밋을 선택하면 해당 행의 `BRANCH / TAG` 칸에
`브랜치 이름 찾는 중…`을 표시한다. 로컬 기록이나 PR에서 이름을 찾으면
다음과 같이 바꾼다.

```text
[삭제됨]  feature/name
```

- `삭제됨`은 현재 테마의 오류 색상을 낮은 불투명도로 섞은 옅은
  붉은색 배경과 읽기 쉬운 전경색을 사용한다.
- 브랜치 이름은 기존 참조 라벨의 글꼴과 여백을 따른다.
- 복구한 이름은 선택한 행에만 표시한다. 다른 행에 같은 이름을
  반복하지 않는다.
- 같은 브랜치 선의 다른 커밋을 선택하면 캐시된 이름이 선택한 행으로
  바로 이동한다.
- 실제 Git 참조가 있는 행에는 기존 라벨만 표시한다.

이름을 찾지 못하면 조회 중 문구를 지우고 기존 빈 칸으로 돌아간다.
타임라인, 미리보기와 키보드 이동에는 영향을 주지 않는다.

## 비동기 상태와 오류 처리

조회마다 저장소 루트, `tipSha`와 선택한 커밋 SHA를 함께 보관한다.
조회가 끝났을 때 저장소나 선택이 달라졌으면 결과를 현재 화면에
표시하지 않는다. 성공한 이름은 안전하게 캐시에 저장하므로 나중에
같은 브랜치 선을 선택하면 사용할 수 있다.

원격 요청이 실패해도 현재 커밋 선택과 타임라인 데이터는 바꾸지
않는다. 사용자 작업을 막는 로딩 화면, 재시도 버튼이나 경고창은
추가하지 않는다.

## 테스트

최소한 다음 동작을 자동 테스트로 남긴다.

- 같은 브랜치 선에서 항상 같은 `tipSha`를 선택한다.
- 현재 Git 참조가 있으면 복구 조회를 시작하지 않는다.
- 캐시, 머지 제목, reflog, PR 순서로 조회하며 이름을 찾으면 멈춘다.
- 지원하는 머지 제목만 해석하고 임의의 커밋 메시지는 무시한다.
- reflog의 체크아웃 직전 SHA가 일치할 때만 이름을 사용한다.
- PR 후보는 정확한 `head.sha`와 최근 `merged_at` 순서로 고른다.
- 저장소별 캐시를 `settings.json`에 저장하고 다시 읽는다.
- 조회 중 문구와 옅은 붉은색 `삭제됨` 배지, 브랜치 이름을 선택한
  행에 표시한다.
- 조회 중 선택이나 저장소가 바뀌면 늦게 도착한 결과를 표시하지
  않는다.
- 로컬 기록과 원격 조회가 모두 실패해도 기존 타임라인을 유지한다.

테스트에서 실제 네트워크나 GitHub 계정은 사용하지 않는다. 명령 결과와
PR 응답을 주입해 조회 순서와 화면 상태만 검증한다.

## 완료 기준

- 이름 없는 과거 브랜치 선의 커밋을 선택하면 필요한 순간에만 이름을
  찾는다.
- 이름을 찾은 행에 옅은 붉은색 `삭제됨` 배지와 브랜치 이름이 보인다.
- 같은 브랜치 선을 다시 선택하거나 앱을 다시 실행해도 저장한 이름을
  재사용한다.
- 현재 Git 참조가 생기면 복구한 이름보다 현재 이름을 우선한다.
- reflog와 PR 조회가 실패해도 타임라인 사용을 방해하지 않는다.
