# Branch Diff의 Merge·Rebase 미리보기 설계

## 최종 디자인 기준

구현 화면은 사용자가 승인한 다음 HTML을 기준으로 삼는다.

- 저장된 기준 페이지: `docs/superpowers/specs/assets/merge-rebase-preview/final-reference.html`
- 현재 실행 주소: `http://127.0.0.1:64815/merge-rebase-apply-confirmation-v33.html`
- 기준 파일 SHA-256: `7fe5304a05a69a079edfdd950185f4b6ac3387c95cd8f63c8ab891f1a30d3bc2`

기준 페이지에는 Merge 성공·Rebase 성공·Merge 충돌·Rebase 충돌과
실제 적용, 진행 상태, 완료, 원복 흐름이 모두 들어 있다. 구현 후
1280×720, 100% 배율에서 기준 페이지와 앱을 같은 상태로 맞춰 캡처한다.
문구, 색, 간격, 버튼 위치, 그래프 레일과 노드 위치, 강조 배경,
Unified/Side-by-side 전환을 나란히 비교한다. 눈에 보이는 차이가 하나라도
남으면 완료로 처리하지 않고 다시 수정한 뒤 같은 비교를 반복한다.

그래프 선은 다음 범위만 예외로 둔다.

- Merge·Rebase 미리보기 때문에 새로 추가되는 가상 레일, 가상 병합
  연결선, 원본과 재작성 커밋의 대응선은 기준 페이지와 엄격히 맞춘다.
- 그 밖의 기존 타임라인 레일은 기준 페이지와 픽셀 단위로 맞추지 않는다.
  기존 `GraphRow`와 `CommitGraphPainter`가 그리던 선, 곡률, 연결 규칙을
  그대로 유지했는지로 판단한다.
- 기존 레일의 위치나 곡률이 기준 페이지와 달라도 기존 앱과 같고 커밋
  관계가 정확하면 허용한다. 미리보기 기능 때문에 기존 레일의 선이나
  연결 규칙이 바뀐 경우에는 허용하지 않는다.

## 목표

Branch Diff 화면에서 두 브랜치의 차이만 보여주는 데서 그치지 않고, Merge 또는 Rebase를 실행했을 때 만들어질 커밋 구조와 파일 결과를 실제 저장소를 변경하지 않은 채 확인할 수 있게 한다.

이 기능은 다음 원칙을 따른다.

- 실제 브랜치, 인덱스, 작업 트리는 변경하지 않는다.
- 현재 Branch Diff의 브랜치 선택, 타임라인, 파일 미리보기 흐름을 그대로 확장한다.
- Merge와 Rebase의 실제 Git 동작 차이를 타임라인에 정확히 반영한다.
- 성공과 충돌 모두 같은 파일 목록 및 diff 탐색 방식을 제공한다.
- 미리보기 결과를 사용자가 확인한 뒤 실제 로컬 브랜치에 적용하거나
  폐기할 수 있게 한다.
- 실제 적용 뒤에는 두 브랜치를 적용 직전 SHA로 정확히 되돌릴 수 있게
  한다.

## 범위

이번 구현에 포함한다.

- Branch Diff 선택기 오른쪽의 `Merge 미리보기`, `Rebase 미리보기` 전환 버튼
- 마지막으로 선택한 미리보기 방식 저장
- 타임라인 상단의 전용 결과 요약 영역
- Merge 성공 및 충돌 타임라인
- Rebase 성공 및 충돌 타임라인
- 성공 결과의 가상 최종 파일 트리와 diff
- 충돌 파일과 충돌 지점의 diff
- Unified 및 Side-by-side 전환
- Rebase 충돌 커밋 간 이동과 포커스 애니메이션
- 충돌 화면 진입과 동시에 자동으로 준비되는 앱 전용 임시 공간
- 충돌 해결과 테스트가 끝난 뒤의 최종 두 브랜치 diff
- 최종 결과의 `Drop` 또는 실제 적용 선택
- Merge 및 Rebase 실제 적용 전 확인
- 커밋별 Rebase 진행 포커스 애니메이션
- 실제 적용 결과와 적용 직전 SHA 원복

원격 push는 포함하지 않는다. 충돌 해결과 테스트는 임시 공간에서만
진행하며 실제 브랜치 ref는 마지막 확인 전까지 갱신하지 않는다.

## 기존 구현 재사용

새 프레임워크나 diff 렌더러는 추가하지 않는다.

- `GitRepository.compareBranches()`의 merge base, 공통/고유 커밋, 파일 비교 결과를 재사용한다.
- `GitRepository.simulateRebase()`의 격리된 임시 worktree 방식을 확장한다.
- 기존 `FullDiff`의 Unified 및 Side-by-side 모델과 표시 위젯을 미리보기에도 사용한다.
- Cherry-pick 충돌 화면의 충돌 파일 선택, 내장/외부 편집기 선택, 계속/중단 패턴을 재사용한다.
- 현재 `GraphRow`와 `CommitGraphPainter`의 레인 계산 및 선 그리기를 확장한다.

## 화면 구성

### 미리보기 방식 선택

상단의 Branch Diff 대상 선택기 오른쪽에 두 버튼을 둔다.

- `Merge 미리보기`
- `Rebase 미리보기`

최초 기본값은 Merge다. 사용자가 선택한 값은 `AppSettings`에 저장하고 다음 실행에도 복원한다. 저장 값은 `merge` 또는 `rebase` 두 값만 허용하며, 알 수 없는 값은 Merge로 되돌린다.

### 결과 요약

기존 하단 상태 표시줄의 Branch Diff 결과를 타임라인 헤더 바로 아래 전용 영역으로 옮긴다. 이 영역에는 공통 조상, 양쪽 고유 커밋 수, 충돌 여부, 현재 미리보기 상태를 표시한다.

성공 상태의 제목은 다음과 같다.

- `Merge 미리보기`와 녹색 원형 체크 아이콘
- `Rebase 미리보기`와 녹색 원형 체크 아이콘

상태 선택용 보조 버튼은 `Merge 성공`, `Rebase 성공`으로 표기하고 성공일 때 녹색 체크 아이콘을 함께 표시한다. 충돌 상태는 `Merge 충돌`, `Rebase 충돌`로 명확히 구분한다.

## Merge 미리보기

### 성공

- 기준 브랜치와 비교 브랜치의 기존 레일은 실선으로 유지한다.
- 두 브랜치 끝에서 가상 Merge 커밋으로 이어지는 부분만 1px 점선으로 표시한다.
- 가상 Merge 커밋은 `VM` 노드로 표시한다.
- 가상 Merge 커밋을 선택하면 미리보기 영역에 최종 파일 목록과 diff를 표시한다.
- 파일 결과는 기준 브랜치 tip과 가상 merge tree를 비교해 계산한다.
- 우측 상태 카드에 `fix/docs를 main에 Merge 실제 적용`처럼 두 브랜치
  이름과 방향을 함께 표시한 버튼을 둔다.
- 버튼을 누르면 기준/대상 브랜치, 시작 SHA, 변경되는 브랜치, 원격
  push가 없다는 사실, 완료 뒤 원복할 수 있다는 사실을 확인창에
  표시한다.
- 확인 뒤 Merge 커밋을 만들고 타임라인의 가상 노드를 실제 `main ·
  HEAD` 노드로 전환한다.
- 완료 화면에는 적용 전/후 SHA와 `Merge 이전 시점으로 되돌리기`
  버튼을 표시한다.

### 충돌

- 기준 브랜치와 비교 브랜치의 기존 레일은 실선으로 유지한다.
- 두 브랜치와 가상 충돌 Merge 노드의 연결선은 1px 점선으로 표시한다.
- 가상 노드와 충돌 상태는 붉은색으로 표시한다.
- 미리보기에는 충돌 파일 목록과 선택한 파일의 충돌 diff를 표시한다.
- 선택지는 브랜치 이름과 대상 커밋 제목을 함께 사용한다. 커밋 SHA만 단독으로 표시하지 않는다.

## Rebase 미리보기

### 성공

- 기준 브랜치와 기존 비교 브랜치 레일은 실선으로 유지한다.
- 기준 브랜치 HEAD 위의 같은 레일에 재작성된 가상 커밋을 원래
  순서대로 배치한다. 독립 브랜치처럼 보이는 별도 가상 레일은 만들지
  않는다.
- 가상 커밋끼리는 1px 보라색 점선으로 연결한다.
- 가상 Rebase 결과가 기준 브랜치 HEAD에 이어지는 구간도 1px 점선으로 표시한다.
- 기존 커밋과 대응하는 가상 커밋은 1px 실선으로 연결한다.
- 대응선은 커밋 아바타를 통과하거나 서로 교차하지 않도록 레인별 직교 경로를 사용한다.
- 꺾이는 모서리는 둥글게 처리하고, 가상 커밋 쪽 끝에는 화살표를 표시한다.
- 대응하는 두 커밋 아바타의 테두리는 연결선과 같은 색을 사용한다.

대응선에는 기존 설정 및 타임라인 팔레트와 겹치지 않는 다섯 가지 어두운 색을 순환 적용한다.
커밋이 다섯 개를 넘으면 같은 순서로 색을 반복한다. 색은 커밋의 의미를 나타내지 않고 원본과 재작성 커밋의 대응만 돕는다.

우측 상태 카드에는 `main 위로 fix/docs Rebase 실제 적용`처럼 기준
브랜치와 대상 브랜치를 모두 표시한 버튼을 둔다. 확인창에는 두 브랜치
시작 SHA, 실제로 갱신되는 대상 브랜치, 원격 push가 없다는 사실을
표시한다. 작업 뒤 언제든 시작 SHA로 돌아갈 수 있으므로 걱정하지 않아도
된다는 안내도 함께 표시한다.

사용자가 확인하면 oldest-first 순서로 커밋을 적용한다. 현재 적용 중인
가상 커밋 행에는 보라색 포커스 배경을 표시하고 다음 커밋으로 넘어갈 때
포커스를 180~240ms ease-out으로 이동한다. 진행이 끝나면 가상 레일을
실선으로 바꾸고 `fix/docs · HEAD`, 새 SHA, 적용 완료 상태를 표시한다.
완료 화면에는 적용 전/후 SHA와 `Rebase 이전 시점으로 되돌리기` 버튼을
표시한다.

### 충돌

- 기준 브랜치와 비교 브랜치의 실제 커밋은 기존 위치에 그대로 둔다.
- 기준 브랜치 HEAD 위에는 Rebase가 완료되면 이어질 가상 위치만 작은 빈 원과 1px 점선으로 표시한다.
- 최초 충돌 커밋부터 시작하며, 현재 충돌이 발생한 실제 비교 브랜치 커밋 행을 붉은색 반전 배경으로 강조한다.
- 타임라인 상단 요약에는 `Rebase 충돌`, 진행 순서, 적용 완료 수, 대기 수를 표시한다.
- 미리보기에는 현재 Rebase 상태, 현재 커밋, 충돌 파일, 선택한 파일의 diff와 해결 선택지를 표시한다.
- `해결 후 계속`을 누르면 임시 worktree에서 다음 단계로 진행한다. 다음 충돌이 있으면 해당 실제 커밋 행으로 포커스를 옮기고, 충돌이 없으면 성공 상태로 전환한다.

충돌 상태를 여는 순간 앱 전용 임시 공간을 자동으로 준비한다. 별도의
`임시 작업 공간 시작` 버튼은 두지 않는다. 안내 문구는 다음 문장을
그대로 사용한다.

> 충돌 해결 과정은 임시 공간에서만 진행합니다. 기준 브랜치 main과
> 대상 브랜치 fix/docs를 직접 변경하지 않습니다.

충돌 해결은 diff에 붙어 있는 브랜치 선택, 직접 편집, 편집기로 열기,
계속 기능만 사용한다. 마지막 충돌 해결을 마치면 최종 두
브랜치 diff를 표시하고 사용자가 `Drop` 또는 실제 적용을 선택하게 한다.

포커스 이동은 180~240ms의 ease-out 스크롤과 행 강조 전환으로 표현한다. 사용자가 운영체제에서 동작 줄이기를 선택한 경우 애니메이션 없이 즉시 이동한다.

## Diff 미리보기

성공과 충돌 화면 모두 동일한 diff 도구막대를 사용한다.

- `Unified`
- `Side-by-side`

선택한 레이아웃은 Merge/Rebase 상태와 파일을 오가더라도 유지한다. 기존 Full Diff 설정을 덮어쓰지 않고 Branch Diff 미리보기 세션 안에서만 유지한다.

성공 시에는 가상 결과 tree와 기준 브랜치 tip을 비교한다. 충돌 시에는 현재 단계의 기준 내용과 적용하려는 커밋 내용을 비교하며, 해결 결과가 존재하면 결과 pane도 함께 반영한다.

## Git 데이터 수집

### Merge

현재 `git merge-tree --write-tree` 호출의 성공 결과에서 생성된 tree SHA를 보존한다. 이 tree를 이용해 다음 값을 만든다.

- 기준 브랜치 tip 대비 변경 파일 목록
- 파일별 patch와 blob 내용
- 가상 Merge 노드의 부모 SHA

충돌이면 기존 name-only 결과와 stage별 blob을 읽어 충돌 파일 모델을 만든다. 모든 명령은 읽기 전용이며 실제 인덱스를 사용하지 않는다.

### Rebase

현재와 같은 detached 임시 worktree를 사용하되, 미리보기 동안만 살아 있는 하나의 세션으로 관리한다.

세션은 다음 값을 가진다.

- 시작 시점의 기준/비교 브랜치 tip
- oldest-first 원본 커밋 목록
- 적용이 끝난 원본 SHA와 새 SHA 대응
- 현재 적용 중인 원본 커밋
- 충돌 파일과 진행 상태
- 성공 시 최종 가상 tip

미리보기 방식 변경, 비교 브랜치 변경, 저장소 변경, 화면 종료 시 임시 worktree를 정리한다. 새 요청이 시작되면 이전 요청의 결과는 serial 값과 시작 tip을 모두 확인한 뒤에만 화면에 반영한다.

## 실제 적용과 원복

실제 적용 직전에 기준/대상 브랜치 tip이 미리보기 시작 SHA와 같은지
다시 확인한다. 하나라도 달라졌으면 적용하지 않고 미리보기를 다시
계산하라는 안내를 표시한다. 원격 ref와 원격 저장소는 갱신하지 않는다.

### Merge 적용

미리보기에서 만든 tree와 두 부모 SHA로 Merge 커밋을 만든다. 기준
브랜치가 현재 체크아웃된 브랜치라면 인덱스와 작업 트리가 깨끗할 때만
적용하고 새 Merge 커밋에 맞춰 작업 트리도 함께 갱신한다. 기준 브랜치가
체크아웃되어 있지 않으면 예상한 이전 SHA를 조건으로 로컬 ref만
원자적으로 갱신한다. 비교 브랜치는 갱신하지 않는다.

### Rebase 적용

임시 worktree에서 검증을 마친 새 tip을 대상 브랜치에 적용한다. 대상
브랜치가 현재 체크아웃된 브랜치라면 인덱스와 작업 트리가 깨끗할 때만
새 tip에 맞춰 함께 갱신한다. 체크아웃되어 있지 않으면 예상한 이전
SHA를 조건으로 로컬 ref만 원자적으로 갱신한다. 기준 브랜치는 갱신하지
않는다.

### 원복

적용 결과에는 다음 값을 보관한다.

- 기준 브랜치 이름, 적용 전 SHA, 적용 직후 SHA
- 대상 브랜치 이름, 적용 전 SHA, 적용 직후 SHA
- 적용 방식: Merge 또는 Rebase

원복 직전에 두 브랜치 tip이 적용 직후 SHA와 같은지 확인한다. 사용자가
그 뒤에 커밋을 추가하거나 ref를 옮겼다면 원복을 중단하고 이유를
표시한다. 조건이 맞으면 현재 체크아웃된 브랜치는 깨끗한 상태에서
작업 트리와 함께 되돌리고, 나머지 브랜치는 적용 직후 SHA를 조건으로
ref를 갱신한다. 성공 뒤 두 브랜치가 저장한 적용 전 SHA와 정확히
일치하는지 다시 확인한다.

## 상태 모델

기존 비교 결과를 대체하지 않고, 화면에 필요한 최소 미리보기 상태만 추가한다.

- `BranchPreviewMode`: merge, rebase
- `BranchPreviewStatus`: loading, clean, conflict, failed
- `MergePreviewResult`: virtual tree, virtual parents, files, conflicts
- `RebasePreviewResult`: original/rewritten commit mapping, virtual tip, progress, conflicts
- `BranchApplyResult`: mode, base/compare branch, before/after SHA
- `BranchApplyStatus`: confirming, applying, applied, reverting, reverted, failed

타임라인용 가상 행과 연결 정보는 Git 결과에서 파생한다. Git 계층은 좌표나 색을 알지 못하고, 화면 계층은 Git 명령을 직접 실행하지 않는다.

## 오류와 오래된 결과 처리

- 선택한 브랜치가 사라지거나 tip이 바뀌면 현재 결과를 폐기하고 다시 계산한다.
- 임시 worktree 생성 또는 정리에 실패하면 오류를 요약 영역에 표시하고 일반 Branch Diff는 계속 사용할 수 있게 한다.
- 이미 Merge, Rebase, Cherry-pick이 진행 중인 저장소에서는 충돌 해결 조작을 비활성화하고 이유를 표시한다.
- 화면 종료 시 정리가 실패한 임시 경로는 다음 시작 때 한 번 더 정리한다.
- 비교 요청이 연속으로 발생하면 마지막 요청만 화면에 반영한다.
- 실제 적용 또는 원복 직전에 ref가 달라졌으면 어떤 브랜치가 바뀌었는지
  표시하고 아무 ref도 갱신하지 않는다.
- 현재 체크아웃된 브랜치를 적용하거나 원복할 때 작업 트리 또는
  인덱스가 더러우면 중단하고 사용자가 먼저 정리하게 한다.
- ref 갱신 도중 실패하면 성공한 단계와 실패한 단계를 구분해 표시하고
  저장한 SHA를 이용한 복구 동작만 제공한다.

## 접근성과 표시 규칙

- 성공/충돌 여부를 색만으로 전달하지 않고 아이콘과 문구를 함께 쓴다.
- 모든 미리보기 버튼과 파일 항목은 키보드로 이동하고 실행할 수 있어야 한다.
- 포커스된 충돌 행은 스크롤 영역 안에 유지한다.
- 실제 Rebase 진행 포커스도 현재 커밋 행이 스크롤 영역 안에 있도록
  유지한다.
- 점선, 실선, 화살표는 고배율에서도 구분되도록 논리 픽셀 기준으로 그린다.
- Branch Diff가 아닌 일반 타임라인의 그래프 표시는 변경하지 않는다.
- 실제 적용과 원복 확인창은 취소를 기본 포커스로 두고, 버튼 문구에
  두 브랜치 이름과 동작을 함께 표시한다.

## 검증

최소 다음 시나리오를 자동 검증한다.

1. 저장된 미리보기 방식의 기본값, 직렬화, 잘못된 값 복구
2. Merge 성공의 가상 tree와 파일 diff
3. Merge 충돌 파일과 1px 점선 가상 연결
4. Rebase 성공의 원본/새 SHA 대응 및 최종 tree
5. 다섯 가지 대응선 색 순환과 양쪽 아바타 테두리
6. 대응선이 아바타를 통과하거나 서로 교차하지 않는 직교 레이아웃
7. 최초 Rebase 충돌 커밋 포커스와 계속 진행 후 다음 충돌 이동
8. 성공과 충돌에서 Unified/Side-by-side 전환 유지
9. 브랜치 변경 중 도착한 오래된 비동기 결과 무시
10. 화면 종료 및 모드 변경 후 임시 worktree 정리
11. Merge 실제 적용 전 tip 재검증과 두 부모 Merge 커밋 생성
12. Rebase 실제 적용 전 tip 재검증과 oldest-first 진행 상태
13. 체크아웃된 브랜치의 더러운 작업 트리 적용 거부
14. Merge/Rebase 적용 뒤 시작 SHA로 두 브랜치 원복
15. 적용 뒤 ref가 달라진 경우 원복 중단
16. 1440×900 기준 페이지와 네 상태 및 적용·원복 화면 비교. 미리보기로
    추가된 선은 엄격히 비교하고 기존 레일은 기존 앱의 선, 곡률, 연결
    규칙이 유지되는지 확인

시각 검증에서는 다음 자료를
`docs/superpowers/verification/merge-rebase-preview/`에 저장한다.

- 기준 HTML을 캡처한 `reference/`
- 구현 앱을 캡처한 `actual/`
- 각 상태의 차이와 재작업 결과를 기록한 `review.md`

`review.md`에 남아 있는 차이가 0개일 때만 시각 검증을 통과한다.

위 검증은 기존 Git 저장소 fixture와 위젯 테스트를 확장한다. 별도 패키지는 추가하지 않는다.
