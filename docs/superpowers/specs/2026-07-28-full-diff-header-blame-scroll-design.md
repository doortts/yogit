# Full Diff 헤더 글자 및 블레임 커밋 메시지 스크롤 설계

## 목적

Full Diff 상단의 파일 정보를 더 쉽게 읽을 수 있도록 글자를 키우고 의미가 분명하지 않은 파일 아이콘을 없앤다. 블레임 커밋 정보 카드에서는 긴 커밋 메시지를 카드 크기를 과도하게 늘리지 않고 끝까지 읽을 수 있게 한다.

## 범위

### Full Diff 헤더

- 파일 경로 글자 크기를 11px에서 13px로 변경한다.
- 변경 요약과 인코딩 배지의 글자 크기를 9px에서 11px로 변경한다.
- 파일 경로 왼쪽의 `<>` 코드 아이콘을 삭제한다.
- 아이콘이 차지하던 공백도 함께 없애 파일 경로를 왼쪽으로 당긴다.
- 기존 높이, 배지 모양, 색상, 요소 순서는 유지한다.

### 블레임 커밋 정보 카드

- 커밋 메시지 영역은 최대 8줄 높이를 유지한다.
- 메시지가 8줄을 넘으면 말줄임표로 자르지 않고 메시지 영역 안에서 스크롤할 수 있게 한다.
- 작성자, 커밋 해시, 커밋 시간은 메시지 스크롤과 관계없이 카드 하단에 고정한다.
- 마우스 휠, 트랙패드, 스크롤바 드래그로 메시지를 움직일 수 있게 한다.
- 실제로 넘치는 내용이 있을 때만 스크롤바가 나타난다.
- 카드 안에서 스크롤해도 선택한 블레임 라인과 블레임 목록의 키보드 포커스는 바뀌지 않는다.
- 파일 히스토리의 커밋 정보 카드는 현재 동작을 유지한다.

## 구현 구조

`GlobalFileBar`에서 파일 경로와 배지의 글자 크기를 조정하고 코드 아이콘을 제거한다.

`FullDiffCommitInfoCard`에는 메시지 스크롤을 선택적으로 켤 수 있는 옵션을 추가한다. 블레임 화면에서만 이 옵션을 켜고 파일 히스토리에서는 기본값을 사용한다. 스크롤을 켠 메시지 영역은 8줄 높이로 제한한 `SingleChildScrollView`와 전용 `ScrollController`를 사용한다. 메타 정보는 스크롤 영역 밖에 둔다.

블레임 화면의 커밋 카드에 걸려 있는 포인터 차단 범위를 조정해 카드 내부의 스크롤 입력만 받을 수 있게 한다. 카드 밖의 블레임 목록 동작은 그대로 유지한다.

## 상태와 수명

- 커밋 카드가 선택한 커밋으로 바뀌면 메시지 스크롤 위치를 맨 위로 되돌린다.
- 카드가 사라질 때 전용 `ScrollController`를 해제한다.
- 메시지를 불러오는 기존 비동기 처리와 앱 실행 중 커밋 메시지 캐시는 변경하지 않는다.

## 오류 처리

- 커밋 메시지를 불러오지 못하면 현재와 같이 요약 문구를 표시한다.
- 메시지가 비어 있거나 8줄 이하이면 일반 텍스트처럼 보이며 스크롤 표시를 만들지 않는다.
- 좁은 화면에서도 카드의 기존 최대 폭과 경계 안에서만 스크롤 영역을 만든다.

## 검증

- 헤더에서 코드 아이콘이 사라지고 파일 경로, 변경 요약, 인코딩 글자 크기가 각각 13px, 11px, 11px인지 위젯 테스트로 확인한다.
- 아이콘을 없앤 뒤 파일 경로가 뒤 요소와 겹치지 않는지 레이아웃 테스트로 확인한다.
- 8줄 이하 메시지에는 스크롤바가 나타나지 않는지 확인한다.
- 8줄을 넘는 메시지는 카드 높이를 유지하면서 마지막 줄까지 스크롤할 수 있는지 확인한다.
- 메시지를 스크롤한 뒤 다른 블레임 라인을 선택하면 새 카드가 맨 위에서 시작하는지 확인한다.
- 카드 스크롤 중 블레임 라인 선택과 포커스가 유지되는지 확인한다.
- 관련 Full Diff 헤더, 커밋 카드, 블레임 화면 테스트를 실행한다.
